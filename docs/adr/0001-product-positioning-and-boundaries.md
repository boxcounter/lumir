# ADR 0001: 定位与边界

- 状态: proposed
- 日期: 2026-09-04
- 角色: Alex Lee（评审/裁决），AI agent（起草）

## Context

市场格局（2026-09 核实）：

- 代码侧：Zed 已将 agent 可见协作做成编辑器一等能力，其 ACP（Agent Client Protocol）成为开放事实标准（JetBrains、Google、GitHub 及 25+ agent 接入）。"显示 agent 编辑状态、选中内容发起对话"本身不构成差异化。
- 知识侧：Obsidian 无一方 agent、核心只渲染 Markdown（非 md 文件靠设置项或社区插件绕行）；Notion / Tana 已 agent-native，但绑定云端与私有数据结构。
- 空位：**本地纯文件 × 全文件类型一等公民 × agent 可见协作 × 极致快**的交集无人占据。

动机：作者日常依赖 Obsidian 但持续碰到其边界（只显示 md、agent 靠插件拼装、性能一般）。项目同时是一场公开发布的方法论实验（AI-only 开发）。用户群体小可接受——自用愉悦是第一要务。

## Decision

1. **定位**：把 agent 当作可见协作者的文本工作台。利基人群是"用 agent 做知识创作、拥有大量知识文件的人"，不是写代码的人，也不是随手写 Markdown 的人。
2. **产品本体是统一的 agent 协作契约**：agent 对文件的读写、待裁决的变更、对话与选区的锚定关系，都是一等 UI 对象，拥有统一的权限/审批/回滚。侧边栏聊天窗只是 feature，不是形态目标。
3. **非目标（v0）**：IDE 能力（LSP、调试器、补全——代码文件的期望是着色可读、agent 可改）；团队实时协同；移动端；插件市场。
4. **键盘优先 = chorded + 非 modal**。拒绝 Vim 式 mode：中文输入下 mode 切换与输入法切换构成双重状态机，是结构性痛点。
5. **极致快与极致美是一票否决级追求**。"极致快"由 ADR 0002 的性能合同量化，不由形容词定义。
6. **开放但带隔离**：开源（时点见 ADR 0004），外部贡献经"进程外 extension + CI 性能门禁"双保险，不拖慢核心。

## Consequences

### 正面

- 差异化是交集定位而非单点功能，难以被单点抄袭；两侧最近的邻居（Zed、Obsidian）各自缺少交集中的两个角。
- 非目标清单直接保护 13 周时间盒（见 ADR 0004）。
- 自用 daily driver 定位使观测问题免费解决：作者即用户。

### 代价与风险

- 放弃 IDE 用户、团队协同、移动端三类场景，天花板自觉压低。
- "agent 协作契约"没有现成参照物，需自行定义交互与权限模型，承担试错成本。
- 交集定位依赖 ACP 生态持续繁荣（见 revisit）。

## Revisit 条件

- ADR 0004 的 M3 出口标准达成失败（13 周后作者仍无意愿用 Lumir 替代 Obsidian）→ 定位整体重估。
- ACP 生态崩塌或被私有协议取代 → 重评"协作契约是产品本体"的实现路径。
