# ADR 0007: AI 定位重启——以使用探针替代定位预判

- 状态: accepted
- 日期: 2026-10-02
- 角色: Alex Lee（评审/裁决），AI agent（起草）

## Context

- ADR 0006 将 AI/Agent 定位 deferred，其 Revisit 条件为「friction log 中『需要把上下文搬运到外部 Agent』类摩擦累积到主观不可忍受，或 Alex 主动裁决」。2026-10-02 Alex 主动裁决触发 revisit，摩擦具体化为：阅读教材 / 理解代码时，需手动复制「不理解的片段 + 文件路径」，切到外部 agent（如 Kimi Code）、找到项目、开新会话——上下文搬运本身是主要成本，且外部 agent 无法知道「当前打开哪个 TAB、视口停在哪个片段、选中了什么」。
- ADR 0006 §5 约定的 dogfood friction log 机制从未实例化（全仓检索无其踪迹）。本次重启走的是 revisit 条款的「Alex 主动裁决」分支；记录机制随本探针补齐（见 Decision 5）。
- ADR 0006 删除了 Thread 特性与 agent 接入空壳（`acp_client.rs` / `mcp_server.rs` / `cli.rs`），理由是「按未验证的架构预判堆 Agent 功能，成本高于先用起来再决定」。本 ADR 延续同一方法论：探针的价值由使用实证，不由架构预判。
- 2026-10-02 二轮裁决对探针边界的三处修正（本 ADR 已吸收）：探针须能**写本地文档**（不是只读问答）；须具备**基础 tool use**（工具循环、读 vault、可配置搜索、本地 Skill + CLI）；对话面板**视觉一次到位**，不做与现有 UI 不兼容的草稿态。

## Decision

1. **AI 定位状态从 deferred 转为「探索中」，但本 ADR 不做任何定位判断。**
   - 不定目标形态、不定完整产品功能集、不定 Harness 的最终重量级。
   - **Alex 裁决（2026-10-02）显式记录**：除本条第 2 款授权的探针能力清单外，一切 AI 相关想法——后台异步任务（自动体检、定时提醒）、插件框架与知识库等——均为头脑风暴级别的思考碎片，不进入任何关键文档、不构成承诺、不作为后续决策的输入。AI 定位具体怎样，由 Alex 在实际使用中体验和思考后另行裁决。
2. **授权一个使用探针：基础 Harness 能力 + 选中片段探讨。**
   - 对话形态：编辑器中选中片段可唤起对话；注入上下文至少包含当前 TAB 的文件路径与选区内容（视口片段等扩展项在 OpenSpec change 的设计阶段定）。
   - **工具循环**：Harness 具备基础 tool use 能力，工具集至少包括——读取 vault 文件内容（消除手动复制粘贴）、vault 内搜索、**写本地文档**（修改既有文档或新建文档，由 Alex 在对话中要求触发）。
   - **可配置的外部能力**：工具集配置驱动（符合 ADR 0002 §5 配置即数据），首批支持 Tavily 搜索增强与本地 Skill + CLI 调用。
   - **写入约束**：修改既有文档必须是局部 patch，不得重排或规范化未触及的内容——这是 ADR 0003 铁律「永不改写源文件格式」在 agent 写入侧的延伸。写操作的交互形态（直接写入 / 预览后采纳）在 OpenSpec change 的设计阶段定。
   - 能力边界以上述清单为限；清单外的能力扩张仍需 Alex 显式裁决。
3. **架构：可演进是显式质量属性。**
   - 三层解耦：编辑器上下文组装 / 对话运行时（会话管理、工具循环、流式输出）/ 对话 UI。各层之间以明确接口交互。
   - **对话运行时是抽象边界**：工具以可注册方式扩展；运行时的实现可替换——初版采用自研工具循环还是嵌入成熟 agent runtime（如经 ACP 或 headless CLI），在 OpenSpec change 的设计阶段论证决定，但无论哪种实现，替换不得波及 UI 层与上下文组装层。
   - 可演进目标：未来引入 subagent、后台任务等能力时，应能在运行时层加入而不推倒 UI 与编辑器集成。本款是对架构的约束，不是对这些能力的承诺。
   - 网络调用与流式渲染不得进入编辑器热路径；性能合同（ADR 0002 §6）与既有全部约束不变。
4. **视觉：对话面板一次到位。**
   - 遵循现有 UI token 体系与排版基线（openspec ui-design-system），与编辑器视觉语言兼容。
   - 不做「先草稿、后重做」——ADR 0006 推倒视觉方向的教训是半成品滞留的成本高于一次做好；探针期接受因此增加的设计与实现成本。
5. **补齐 ADR 0006 §5 的记录机制，改为双向。**
   - 探针会话本地留存（问了什么、答了什么、调用了什么工具、写了哪些文件）；
   - Alex 手记维持原 0006 口径：哪里卡住、哪里仍回到外部 agent。
   - 两者共同作为未来定位裁决的输入。
6. **与既有决策的关系。**
   - ADR 0001 §3 非目标（IDE 能力、团队实时协同、移动端、插件市场）不变；§1/§2 维持 deferred 状态。
   - ADR 0003 铁律不变，并由 Decision 2 的写入约束延伸到 agent 写入侧。
   - ADR 0004 M2（agent 集成）维持 deferred：本探针不等于恢复 M2，只是 AI 方向上的一个使用探针。
   - ADR 0005 与 PRODUCT-CONCEPT.md 仍是未来定位决策的输入而非必须恢复的前提。
   - ADR 0006 的 Revisit 条款由本 ADR 消费；0006 其余内容（当前阶段定位 = Emacs keybinding PKM、视觉基线等）继续有效。

## Consequences

### 正面

- 以已确认摩擦为起点的使用探针替代定位预判，决策可逆、可追溯。
- 能力清单（工具循环、写文档、可配置搜索、Skill/CLI）直接消除「手动搬运 vault 内容」的全部摩擦，而非只消除一半。
- 运行时抽象边界保护未来演进：subagent 等能力或运行时实现的替换，不推倒 UI 与编辑器集成。
- 视觉一次到位避免半成品滞留——与 ADR 0006 删除半成品 Agent 骨架的教训一致。
- 「头脑风暴碎片不入文档」的显式记录，防止愿景碎片沉淀为既成承诺，保护未来定位裁决的自由度。
- 双向记录机制补上 0006 留下的证据缺口，下一次定位裁决将有实证输入。

### 代价与风险

- 探针体量显著大于「纯问答」形态：工具循环、写能力、视觉一次到位三者叠加，是 2026 年以来单个最大功能投入。自觉接受；对冲 = 能力边界以 Decision 2 清单为限，扩张需显式裁决。
- 写能力引入误写风险：Harness 可能写出不符合意图的内容。对冲 = Decision 2 的局部 patch 约束 + 交互形态在 design 阶段正面论证（直接写入 vs 预览采纳）。
- 内容出域范围扩大：除选区与路径外，工具循环会把更多 vault 内容发送给 LLM API，Tavily 查询出域至第三方。自用阶段接受，未来对外发布需重估隐私口径。
- 探针有滑向「事实定位」的风险：用久了可能未经裁决就被默认接受。对冲 = 定位判断必须显式做出，不允许默认发生。
- 「探索中」状态若长期无裁决，与 0006 的「deferred 滑向遗忘」同构。由双向记录机制与 Revisit 条件对冲。

## Revisit 条件

- Alex 基于探针使用体验主动裁决 AI 定位 → 以新 ADR 做出定位判断（输入：ADR 0005、PRODUCT-CONCEPT.md、探针会话记录与手记）。
- 探针在实践中被弃用（不再为其打开对话面板）→ 撤回探针，AI 定位回到 deferred。
- 探针能力清单需要扩张（如后台任务、subagent 从架构约束转为实际需求）→ Alex 显式裁决后修订本 ADR，不允许在 OpenSpec change 中静默扩张。
