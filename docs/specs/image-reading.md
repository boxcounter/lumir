# Foundation Image Reading 质量合同

- 状态：生效中的质量合同（M182 建立；新增条款 = 图片显示宽度的时序无关性）
- 范围：md 文档内图片引用的**显示宽度**与它依赖的量；不重定义 [attachment-display](../../openspec/specs/attachment-display/spec.md) 已定的语法覆盖、路径解析、可见回退与 SVG 安全条款
- 上位合同：[Foundation Markdown 质量合同](foundation-markdown.md)（§2 F0/F1 与异步资源 settle、§3 P1.5 image）、[attachment-display spec](../../openspec/specs/attachment-display/spec.md)（「图片引用的可见回退不变量」）
- 依据：用户实测报告（2026-09-18：首次打开文件时图约为正文栏宽的一半，切走再切回后与正文同宽）；M182 的真机取证与反向验证证据留档 `test-results/m182/` 与 `test-results/acceptance/`

## 1. 两个输入维度：固有尺寸是否确定

图片替换区的显示宽度只可能由两个量决定：图片**固有尺寸**（引擎从字节解出的宽高）与替换区的**包含块宽度**（阅读栏宽）。引擎对这两个量的用法按固有尺寸是否确定分两族，本合同的宽度条款按这两族写：

| 族 | 输入形态 | 引擎给出的固有尺寸 | 本合同的宽度规则 |
|---|---|---|---|
| 固有尺寸确定 | 位图；带 `width`/`height` 的矢量图 | 字节里的真实宽高 | 宽度 = min(固有宽, 栏宽) |
| 固有尺寸不确定 | 只给百分比宽（如 `width="100%"`）或只声明 `viewBox` 的矢量图（mermaid / D2 / Excalidraw 导出器的默认形态） | 无固有像素尺寸，只有比例；`naturalWidth/Height` 返回的是**默认对象尺寸**（300×150 按比例缩放），不是显示宽度 | 宽度 = 栏宽，高度按固有比例缩放 |

第二族里 `naturalWidth` 不是可用信号：实测 `width="100%"` + `viewBox="0 0 240 80"` 的 svg，`naturalWidth×Height = 300×100`（默认对象尺寸），把它当显示宽度写死会得到与栏宽无关的固定像素宽度（M178 的尺寸兜底曾如此，M182 收窄了它的适用范围，见 §3）。

## 2. 条款：图片显示宽度的时序无关性（M182）

对任意被 live preview 识别为图片引用的源码片段——标准 Markdown `![alt](target)`、标准 Markdown 的外部 `http(s)` 目标、Obsidian 方言 `![[target]]` 三种形态——图片替换区的显示宽度 SHALL 只由 §1 的两个量决定：

- 固有尺寸确定的引用：显示宽度 = min(固有宽, 栏宽)；
- 固有尺寸不确定的引用：显示宽度 = 栏宽（高度按固有比例），MUST NOT 回落成与栏宽无关的固定像素宽度；
- 引擎给不出可见像素的形态：按 attachment-display 的「图片引用的可见回退不变量」走可见占位（本条款不改变该处置）。

显示宽度 MUST NOT 依赖以下任一量：字节加载的快慢、图片缓存是否命中、打开次序（首开 / 切走再切回 / 重新装载）、以及**加载中状态块的在否与其文本宽度**。同一引用在同一文档首次打开与重开（切走再切回）SHALL 收敛到同一显示宽度，MUST NOT 出现「首开一个宽度、重开另一个宽度」。

判据 SHALL 落在替换区自身的布局盒（`getBoundingClientRect` 的宽高）上；MUST NOT 用 `naturalWidth` 一类内在尺寸信号推断显示宽度（§1 第二族的反例）。替换区的可见内容高度 MUST 保持 > 0（不出现零高度空白）。

条款引用输入分布（引用形态 × 固有尺寸是否确定 × 栏宽），不引用具体案例。

## 3. 机制：包含块宽度必须与在场内容无关

宽度条款的机制落点是替换区包装盒（`.cm-lp-image`）的宽度。`<img>` 的 `max-width: 100%` 与「固有尺寸不确定时按包含块填充」两条都相对包装盒解析，因此包装盒若是 `width: auto`（shrink-to-fit），它的宽度就由**当场在场的内容**决定：

- 加载中状态块的文本宽度先参与布局时（首开、字节未到），包装盒被钉在该文本宽度上；图片到达后填充这个宽度并被终态判据视为「已画出」，宽度就停在状态块宽度（实测约为栏宽的一半）。
- 缓存命中时终态处置在首次布局前同步跑完，包装盒按图片自己算，收敛到栏宽。

两个终态由「布局时状态块在不在场」决定，正是 §2 禁止的时序依赖。给包装盒一个与在场内容无关的确定宽度（栏宽，`width: 100%`）后，两条路径的包含块相同，终态必然一致；图片本身仍按固有宽度 + `max-width: 100%` 渲染，窄图不拉伸。

**已知行为边界（待裁决项）**：包装盒取块级宽度后，与正文混排在同一行的图片引用会独占一行（引用前的正文与引用后的正文各自成行）。真实 vault 抽样（只读统计，M182）：256 条独占行引用 / 16 条同行含他字符，后者多为被链接包裹的 `[![…](…)](…)` 与样本文件里的 JSON 字符串，未见正文混排行内图。该边界已登记 [docs/backlog.md](../backlog.md)。

## 4. 证据与门禁

- **不变量级属性测试**：[tests/visual/scenes/m182-image-first-open-width.spec.ts](../../tests/visual/scenes/m182-image-first-open-width.spec.ts)——fixture 扫「固有宽度分布（超栏宽定尺寸 / 窄定尺寸 / 百分比固有宽度 / 仅 viewBox / 固有尺寸为零 / 解码失败 / 读取失败 / 行内）× 首开与切走切回两态」，断言 §2 的条款本身。
- **反向验证**：判别断言是「固有尺寸不确定的引用按栏宽渲染」这一条（不是「两态相等」——修复前 chromium 下两态本就相等，都停在 300×100）。移除机制落点（`src/preview/theme.ts` 的 `width: "100%"`）后该断言实测变红（读得 300，栏宽 828.8），红输出留档。
- **真机层**：[scripts/acceptance/scenarios/23-image-first-open-width.md](../../scripts/acceptance/scenarios/23-image-first-open-width.md) 用 AX 几何读数（`AXImage … @x,y W×H`）断言首开与切回两态的宽度一致且等于栏宽。
- **不变量的边界**：本合同只判「显示宽度由 §1 两个量决定」；图片的**观感**（大小是否合适、留白）仍归裁决者，不由门禁判。
