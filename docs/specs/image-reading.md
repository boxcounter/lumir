# Foundation Image Reading 质量合同

- 状态：生效中的质量合同（M182 建立；新增条款 = 图片显示宽度的时序无关性；M187 增补 = 替换区尺寸的会话内一致性）
- 范围：md 文档内图片引用的**显示宽度 / 高度**与它们依赖的量；不重定义 [attachment-display](../../openspec/specs/attachment-display/spec.md) 已定的语法覆盖、路径解析、可见回退与 SVG 安全条款
- 上位合同：[Foundation Markdown 质量合同](foundation-markdown.md)（§2 F0/F1 与异步资源 settle、§3 P1.5 image）、[attachment-display spec](../../openspec/specs/attachment-display/spec.md)（「图片引用的可见回退不变量」）
- 依据：用户实测报告（2026-09-18：首次打开文件时图约为正文栏宽的一半，切走再切回后与正文同宽；2026-09-21：倒序慢滚经过 svg 图时正文跳一下再弹回，滚不到图的完整内容）；M182 与 M187 的真机取证与反向验证证据留档 `test-results/m182/`、`test-results/m187/` 与 `test-results/acceptance/`

## 1. 两个输入维度：固有尺寸是否确定

图片替换区的显示宽度只可能由两个量决定：图片**固有尺寸**（引擎从字节解出的宽高）与替换区的**包含块宽度**（阅读栏宽）。引擎对这两个量的用法按固有尺寸是否确定分两族，本合同的宽度条款按这两族写：

| 族 | 输入形态 | 引擎给出的固有尺寸 | 本合同的宽度规则 |
|---|---|---|---|
| 固有尺寸确定 | 位图；带 `width`/`height` 的矢量图 | 字节里的真实宽高 | 宽度 = min(固有宽, 栏宽) |
| 固有尺寸不确定 | 只给百分比宽（如 `width="100%"`）或只声明 `viewBox` 的矢量图（mermaid / D2 / Excalidraw 导出器的默认形态） | 无固有像素尺寸，只有比例；`naturalWidth/Height` 返回的是**默认对象尺寸**（300×150 按比例缩放），不是显示宽度 | 宽度 = 栏宽，高度按固有比例缩放 |

第二族里 `naturalWidth` 不是可用信号：实测 `width="100%"` + `viewBox="0 0 240 80"` 的 svg，`naturalWidth×Height = 300×100`（默认对象尺寸），把它当显示宽度写死会得到与栏宽无关的固定像素宽度（M178 的尺寸兜底曾如此，M182 收窄了它的适用范围，见 §3）。

## 2. 条款：图片显示宽度的时序无关性（M182）

对任意被 live preview 识别为图片引用的源码片段——标准 Markdown `![alt](target)`、标准 Markdown 的外部 `http(s)` 目标、Obsidian 方言 `![[target]]` 三种形态——图片替换区的显示宽度 SHALL 只由 §1 的两个量决定：

- 固有尺寸确定的引用：显示宽度 = min(固有宽, 栏宽)；
- 固有尺寸不确定的引用：显示宽度 = 栏宽（高度按固有比例），MUST NOT 回落成与栏宽无关的固定像素宽度；
- 引擎给不出可见像素的形态：按 attachment-display 的「图片引用的可见回退不变量」走可见占位（本条款不改变该处置）。

显示宽度 MUST NOT 依赖以下任一量：字节加载的快慢、图片缓存是否命中、打开次序（首开 / 切走再切回 / 重新装载）、以及**加载中状态块的在否与其文本宽度**。同一引用在同一文档首次打开与重开（切走再切回）SHALL 收敛到同一显示宽度，MUST NOT 出现「首开一个宽度、重开另一个宽度」。

判据 SHALL 落在替换区自身的布局盒（`getBoundingClientRect` 的宽高）上；MUST NOT 用 `naturalWidth` 一类内在尺寸信号推断显示宽度（§1 第二族的反例）。替换区的可见内容高度 MUST 保持 > 0（不出现零高度空白）。

条款引用输入分布（引用形态 × 固有尺寸是否确定 × 栏宽），不引用具体案例。

## 3. 机制：包含块宽度必须与在场内容无关

宽度条款的机制落点是替换区包装盒（`.cm-lp-image`）的宽度。`<img>` 的 `max-width: 100%` 与「固有尺寸不确定时按包含块填充」两条都相对包装盒解析，因此包装盒若是 `width: auto`（shrink-to-fit），它的宽度就由**当场在场的内容**决定：

- 加载中状态块的文本宽度先参与布局时（首开、字节未到），包装盒被钉在该文本宽度上；图片到达后填充这个宽度并被终态判据视为「已画出」，宽度就停在状态块宽度（实测约为栏宽的一半）。
- 缓存命中时终态处置在首次布局前同步跑完，包装盒按图片自己算，收敛到栏宽。

两个终态由「布局时状态块在不在场」决定，正是 §2 禁止的时序依赖。给包装盒一个与在场内容无关的确定宽度（栏宽，`width: 100%`）后，两条路径的包含块相同，终态必然一致；图片本身仍按固有宽度 + `max-width: 100%` 渲染，窄图不拉伸。

**已知行为边界（待裁决项）**：包装盒取块级宽度后，与正文混排在同一行的图片引用会独占一行（引用前的正文与引用后的正文各自成行）。真实 vault 抽样（只读统计，M182）：256 条独占行引用 / 16 条同行含他字符，后者多为被链接包裹的 `[![…](…)](…)` 与样本文件里的 JSON 字符串，未见正文混排行内图。该边界已登记 [docs/backlog.md](../backlog.md)。

## 4. 证据与门禁

- **不变量级属性测试**：[tests/visual/scenes/m182-image-first-open-width.spec.ts](../../tests/visual/scenes/m182-image-first-open-width.spec.ts)——fixture 扫「固有宽度分布（超栏宽定尺寸 / 窄定尺寸 / 百分比固有宽度 / 仅 viewBox / 固有尺寸为零 / 解码失败 / 读取失败 / 行内）× 首开与切走切回两态」，断言 §2 的条款本身。
- **反向验证**：判别断言是「固有尺寸不确定的引用按栏宽渲染」这一条（不是「两态相等」——修复前 chromium 下两态本就相等，都停在 300×100）。移除机制落点（`src/preview/theme.ts` 的 `width: "100%"`）后该断言实测变红（读得 300，栏宽 828.8），红输出留档。
- **真机层**：[scripts/acceptance/scenarios/23-image-first-open-width.md](../../scripts/acceptance/scenarios/23-image-first-open-width.md) 用 AX 几何读数（`AXImage … @x,y W×H`）断言首开与切回两态的宽度一致且等于栏宽。
- **不变量的边界**：本合同只判「显示宽度由 §1 两个量决定」；图片的**观感**（大小是否合适、留白）仍归裁决者，不由门禁判。

## 5. 条款：替换区尺寸的会话内一致性（M187）

§2 判的是**宽度**不依赖时序。本条款判**高度**：同一引用的替换区，在会话内第二次进入渲染视口时的高度 MUST NOT 依赖「字节是否已在手」。

用户现场（2026-09-21）：倒序（自下往上）慢滚经过含 svg 图片的文档，当图片底边出现在正文区顶部时，正文会「向下跳一下再弹回」，滚不到图片的完整内容；鼠标快速滚动不出现。

**机制**（根因，M187 探针实测）：live preview 的装饰层只为渲染视口内的行建 widget（[`livePreview.ts`](../../src/preview/livePreview.ts) 的视口增量），行滚出渲染视口后 widget 被销毁、装饰消失。再次滚回来时 widget 从零重建——重建瞬间 DOM 里只有一行「加载中…」文本（≈28px），而 CM 的高度图里这个行块仍留着上一次测得的整张图片高度（485px）。CM 的滚动锚定（`@codemirror/view` 的 `EditorView.measure`：`newAnchorHeight − scrollAnchorHeight > 1` 时把差值加到 `scrollDOM.scrollTop`）如实把这个高度差翻译成一次滚动位移：**加载中状态把行块压缩 457px → 正文被推开 → 字节到达行块长回来 → 又被推回**，两次位移相差几十毫秒，用户看到的就是「跳一下再弹回」。当图片底边正好压在正文区顶部（滚动锚点落在该行块内）时，锚点自身的 top 不变、CM 的校正恒为 0，两次位移里的一次完全落到正文坐标上——正文整体跳走再跳回，正是用户描述的形态。正向滚动不触发：那时高度变化发生在锚点**下方**，锚点 top 不变，校正为 0。

**条款**：对任意被 live preview 识别为图片引用的源码片段（§1 的三种形态 × 两族固有尺寸），**本会话内已渲染过一次**的引用，其替换区在 widget 重建时 SHALL 在字节到达前就占住与终态一致的尺寸：

- 同一栏宽下，重建时（加载中状态）的替换区高度与终态高度 SHALL 一致（判据：替换区所在行块的布局高度，实测差 MUST ≤ 1px）；
- 该引用的字节异步到达 MUST NOT 改变正文任何一行在文档坐标中的位置（等价说法：MUST NOT 引起 `scrollDOM.scrollTop` 的非用户输入变化）；
- 预留 MUST 用与图片自身相同的尺寸规则表达（宽度 = min(固有宽, 栏宽)、高度按固有比例），MUST NOT 写死与栏宽无关的像素高度；窄于栏宽的引用与贴满栏宽的引用**同一个函数**推出各自的预留，不按扩展名 / 格式分支。

会话内**首次**确定某引用固有尺寸的那一次不受本条款约束：字节未到时尺寸无从得知，行块按真实高度增长是图片占位的必然，属 §2 判据之外。条款引用输入分布（引用形态 × 固有尺寸是否确定 × 栏宽 × 是否首见），不引用具体案例。

**机制落点**（[`src/preview/attachments.ts`](../../src/preview/attachments.ts)）：把每次成功渲染测得的替换区几何（图片布局盒 + 当时的栏宽）按引用键记在会话内；widget 重建时用一个空的块级占位元素把行高撑到终态尺寸——占位元素带 `aspect-ratio`（高度随栏宽自动等于终态高度），窄图另加 `max-width` 钉住宽度档位、贴满栏宽的引用不加（见 §1 两族）。加载中状态同时移出正常流（`position: absolute`）：留在流里会让 inline-block 的基线落在文本基线上，加载态与终态的行高差几像素（实测 8px），一样会被锚定校正翻译成位移。占位元素挂在包装盒**内**而不是包装盒上：包装盒的布局盒是 §2 宽度不变量的判据面（首开 / 重开两态逐项一致），预留样式加到包装盒上会让窄图的两态宽度不同（首开按栏宽、重开按自身宽度）。

## 6. 证据与门禁（M187 增补）

- **不变量级单测**：[tests/unit/image-widget.test.ts](../../tests/unit/image-widget.test.ts)——`imageReserve` 的推导在「固有宽度（窄 / 等于栏宽 / 超栏宽）× 栏宽（窄窗 / 默认 / 宽窗）」分布上断言「预留解出的盒子逐项等于上次渲染的盒子」，并单独钉住两条边界：贴满栏宽的引用（含只声明 `viewBox` 的矢量图）MUST NOT 被钉在旧宽度上（否则破 §1/§2）、窄图 MUST NOT 被拉伸；几何缓存按引用键存取、可失效、超限淘汰最旧。
- **真机层**：[scripts/acceptance/scenarios/26-svg-scroll-stability.md](../../scripts/acceptance/scenarios/26-svg-scroll-stability.md)——合成含大尺寸 viewBox-only svg 的文档，倒序滚动，断言倒序往返后大图被完整渲染、没有卡住的加载状态、宽度仍是栏宽一档。**边界（场景 notes 已如实声明）**：这条只守用户可见**终态**——套件没有滚轮动作、读不到 `scrollTop`、断言采样间隔（一次 MCP 往返）远长于本缺陷的窗口，因此它修复前后都是绿的，判别性验证不在这一层。
- **反向验证（REVIEW.md 第 1 条）**：判别断言必须有区分度——先造一个必须让它 FAIL 的输入再提交。M187 的判别判据 =「非用户输入的 `scrollTop` 变化」（每次输入后 ~40ms 与 ~200ms 各采一次，差 > 8px 记一次），驱动为真 app + 桩后端 + 逐帧采样，实测：
  - 修复前（master `7267b26`）：倒序慢滚（-60 × 30）1 次 / 最坏 **465px**；倒序快滚（-600 × 30）1 次 / 最坏 465px；**正向慢滚 0 次**（与用户「正向不触发」一致）。
  - 修复后：五种驱动（正向慢滚 / 倒序慢滚 / 倒序快滚 / 翻屏键 / 细步倒序）全部 0 次，最坏 **0px**（判据阈值放到 2px 也没有任何一步越界）。
  - 窄图（定尺寸 `240×80`）单独跑重建路径：0 次；同时读到 `.cm-line` 宽 764.8（栏宽，`columnOf` 的落点成立）、包装置换区宽 = 栏宽、`img` 仍是 240×80（窄图未被拉伸、M182 的两态判据面未变）。
  - 探针脚本是临时的（不入 git：它属于 chromium 视觉通道，本 mission scope 未含该目录），实测输出与脚本副本留档 `test-results/m187/`。
- **已知边界**：
  - **首次渲染**（会话内还没见过该引用）：字节到达时行块按真实高度增长，属条款明确排除的一次；若此时图片底边正压在正文区顶部（锚点落在该行块内），正文会随这一次真实增长下移一次——这是图片占位的必然，不是缺陷。
  - **几何缓存按引用键（附件路径 / 外部 URL）记**：同一路径的字节在会话内被换掉（外部改文件、切到同名路径内容不同的另一个 vault）后，重建时会先按旧几何预留、字节到达后再按真实尺寸修正，那一次修正会带来一次位移。失效点在成功渲染时覆盖、读取失败 / 终态不可见时删除。
