## 适用范围

harness 面板的混排输入区：`contenteditable` 容器（`.lumir-hp-composer`），顶层块只有三类
原子卡片（`.lumir-hp-qcard`：引用卡片 / 消息摘录卡片 / 图片卡片，change
harness-composer-image-paste 新增第三类）与问题段落（`.lumir-hp-qpara`）。本文档约束
**键盘驱动的换行**（Enter 发送 / ⇧Enter 换行）与**断行后的视口位置**。输入分布（条款引用
分布，不引用具体案例）：

- **光标落点**：段落内（段中 / 段首 / 段末）· 空段落 · 卡片前缘（含无前段落）· **相邻两张卡之间**
  （两者之间没有段落——卡片与卡片之间、卡片与段落之间的前缘是同一个模型值，此处显式写成独立
  一档，避免读成「卡片前缘只指卡片与段落之间」，见 HC3）；
- **段落文本**：空 / 单字 / 多字 / 已含内部换行（粘贴或快照恢复带进来的 `\n`）· **以换行结尾**
  （原生编辑路径可达：WebKit 删空一行后残留的 `<br>` 经 `paraTextOf` 记为 `\n`、`normalize`
  不剥除——属性测试的生成器枚举这一档，见 §证伪方式）；
- **内容体量**：单行（不滚）· 超出 `max-height`（可滚，`overflow-y: auto`）。

## 不变量

### HC1 — 一次 ⇧Enter 恰好多一行可见行，且光标落在可见行上

对**任意**块序列与**任意**光标位置，一次 ⇧Enter MUST：

1. 让 composer 的**可见行数恰好 +1**；
2. 断行结束后，光标落在**可见行**上——光标的行号 MUST 小于其所在段落的**渲染行数**。

第 2 条不是实现细节，是第 1 条的可判据形态：CSS 里**尾随换行不产生行盒**
（`white-space: pre-wrap` 下 `"ab\n"` 与 `"ab"` 同高，实测见下节），所以「段末追加 `\n`」这种
最自然的写法会让光标落在一个**没有渲染出来的行**上——用户看到的是「按了没反应」，再按一次
才把上一次的尾随换行挤成内部换行。这正是本条款要禁的形态。

第 2 条的判据是**充要**形态、不能省成「段落文本不以 `\n` 结尾」：段落文本可以以 `\n` 结尾
（见 §适用范围 的第二条），此时「段落尾随 `\n`」与「光标落在尾随换行之后」是两件事——
`"\na\n"` 里 offset 1（第二行行首）的光标是**可见**的，`"a\n"` 里 offset 2（尾随换行之后）
的光标才是不可见的那个。按行号 < 渲染行数判，两例各归其位。

落法的形状不做承诺（段内插 `\n`、拆出新段落块、别的表示都可以），只约束上面两条可观测结果。

### HC1 第 3 条 — 段末断行的**落点**：新行落在当前行之后（M462）

光标在**段落末尾**时——含末段末缘的**归一等价表示**「末尾之后」`{block: 块数, offset: 0}`
（`normalizeComposerCaret` 的折叠结果；行级命令 ⌃E / ⌃F 落在这里并把该值写回 DOM 的块级容器
边界）——一次 ⇧Enter MUST 把新空段落块落在**该段之后**：

1. 该段落的文本 MUST NOT 变化——MUST NOT 出现「新行插到当前行**之前**」的形态（缺陷形态：
   `\n` 落到该段文本的第 0 位，该行文字被挤到下一行、光标停在文字行行首）；
2. 该段之后的既有块顺序 MUST NOT 变化；末块是卡片时新空段落块追加在**末尾**（MUST NOT 插到
   卡片之前——那是「卡片前缘」这一档的落法，「末尾之后」与它是两个不同的模型位）；
3. 光标落新空段落块段首（= 新行的可见位置）。

**判据形态（可证伪）**：末段末缘的两种表示 MUST 给**同一个**结果——
`insertSoftBreakAtCaret(blocks, {block: 块数, offset: 0})` 与
`insertSoftBreakAtCaret(blocks, {block: 末块下标, offset: 末块文本长度})` 的块序列逐字节相同、
光标同属一个归一等价类。

**为什么必须单独立这条**：上面两条（可见行 +1 / 光标在可见行上）对本缺陷形态**恒真**——`\n`
插在段内同样 +1 行、光标同样落在可见行上，缺陷因此从它们下面整体溜过；有区分度的判据只有落点。
缺陷现场（Alex 2026-10-12）与真机探针读数见 §实测依据的 M462 节。

### HC2 — 断行 / 光标移动后，光标行 MUST 在 composer 视口内

composer 视口（`.lumir-hp-composer` 的 `overflow-y: auto` 区）MUST 把**光标所在行**纳入可见区，
用户 MUST NOT 需要手动滚动才能看到刚断出来的那一行。内容不足以滚动时不适用。

判据形态（可证伪表述）：断行后，光标行的渲染区域与视口可视区有非空交集。

机制按**结果**约束、不按实现约束：composer 的光标是程序化 `Range` 落下的（`renderComposer`
重渲后 `setDomCaret`），引擎在选区变化时的 reveal 行为是**引擎特性**——WKWebView 会 reveal
（实测，2026-10-10），Blink 不会。实现侧因此显式给一条**引擎无关的保证**
（`caretScrollTop` + 写 `scrollTop`，光标已在视口内时不动）：它保证条款在任何引擎 / 任何
重渲路径上成立，而不是依赖引擎的默认行为。

边界光标位（HC3）中**写作块级容器边界**的那一档（今天只剩「末尾之后」）其 `Range` 会量出
**零高**，此处回落**后一张卡片**的块矩形——「后一张卡片在视口内」是「边界可见」的可用代理。
M457 起有文本宿主的边界位不再走这一档（落点是文本节点 / 卡片内文本位，几何真实）。

### HC3 — 边界光标位：相邻卡片之间可停光标，内容输入在该处物化段落

composer 的模型层 SHALL 把「相邻两个原子块之间的位置」当作一等公民的光标位，其表示 SHALL 为
`{block: 后一块的下标, offset: 0}`（等价于「后一块的前缘」）。**相邻两张卡片之间没有段落是
合法状态**，归一化 MUST NOT 为此凭空插入段落（HC1 的「对任意块序列」承诺含这些形态）。对
**任意**块序列与上述任一光标位：

1. **往返对称**：该位置从 DOM 读回 SHALL 得到 `{block: N, offset: 0}`——`Range(composer, N)`
   与「选区锚在某张卡片元素内部或卡片元素本身」两种 DOM 形态归一到同一个模型值；把该位置写回
   DOM SHALL 落在**有文本宿主的相邻位**上（第 2 条，M457 修订）；该光标位 SHALL 跨整面重渲
   （`renderComposer` + 写回光标）与撤销 / 重做恢复保持一致；
2. **写回落点 MUST 有 caret 几何**（M457 新增）：边界位是**无文本宿主**的位置——卡片是
   `contenteditable=false` 的原子块、块级容器边界又落在两个块级盒之间，`Range(composer, N)`
   在引擎里**量不出 caret 几何**（`getBoundingClientRect()` 全 0，WebKit 与 Blink 实测同结果，见
   §实测依据）——画在哪由引擎自行决定（真机现场：⌃B 之后光标落进卡片正文里，Alex 2026-10-12）。
   写回因此落**有文本宿主**的相邻位：
   - 前一块是段落 → 该段落的**末缘**（段落非空时与边界位同属 `normalizeComposerCaret` 的归一
     等价类 ⇒ 导航 / 行级命令 / 退格 / 前删 / ⇧Enter 的口径逐字节不变；空段落自占一行、不参与
     归一，落点 = 该空段落的行位）；
   - 两侧都没有文本宿主（两卡相邻 / composer 以卡片开头）→ **后一张卡片的首个文本位**（DOM
     读回按「锚在卡片内」归一为同一个边界位）。
   唯一的例外是「末尾之后」（`block = 块数`）：它**没有后一块**，写回落**最后一个块**的边界
   （M473）——末块是非空段落时落该段的**文本末缘**（`{kind: "text", index: 块数-1, offset: len}`，
   与「末尾之后」同属 `normalizeComposerCaret` 的归一等价类 ⇒ 模型值与读回口径不变）；末块是
   **空段落 / 卡片**时仍写块级容器末尾边界（空段落只有一个停靠点，落到它会与「空段落前缘」
   这一档的写回位重合；卡片没有文本末缘宿主）——**已知边界**，登记在 §已知边界与 docs/backlog.md；
3. **导航不是编辑**：仅把光标移动到该位置 MUST NOT 改变块序列、MUST NOT 产生撤销步；
4. **内容输入物化段落**：内容型输入到达该位置时 SHALL 在该处物化一个问题段落块并把内容落进它
   ——键入字符落在新段落里；粘贴 / 拖入的纯文本同样落在新段落里；⇧Enter 在该处落一个新空段落
   （与 HC1 的「卡片前缘」档同一条落法，仍满足「恰好多一行可见行」）；插入卡片 SHALL 把卡片落在
   该边界上并保证其后仍有承接光标的问题段落。物化 MUST NOT 吞掉被该边界分隔的卡片、MUST NOT
   把内容折进相邻的其它段落块；
5. **一个撤销步**：物化与该次输入 SHALL 合成**一个**撤销步——一次撤销后回到「两张卡片相邻、
   两者之间无段落、光标在边界位」的前态（新段落与其中的文字一并消失、两张卡片不丢）。

**键入的挂点 MUST 落在会派发的事件上**（M457）：引擎在边界位**不派 `beforeinput` / `input`**
（卡片内是 `contenteditable=false` 的不可编辑区、容器边界又不参与编辑，WebKit 实测：`keydown`
到达 composer，`beforeinput` / `input` 都不派、字也不落）——物化若只挂在 `beforeinput` 上，
「两张相邻卡片之间」这一档永远不可达（M450 的模型层语义与单测都对，挂点挂到了不派发的事件上，
Alex 2026-10-12 的「两卡之间不能输入」即此）。内容型键入（折叠选区 + 非修饰键 + 可打印单字符 +
非组合期 + 卡片前缘）因此由 composer 的 `keydown` 这一拍走模型（`boundaryTypingCaret` 是判据的
唯一居所）；`beforeinput` 那一档保留给引擎会把边界位解析成相邻可编辑位的形态（如「段落 + 卡片」
之间的边界，WebKit 在该处会派 `beforeinput`）。

**已知边界（HC3）**：IME 组合在「两卡相邻」这一档起不来——组合需要一个可编辑的行内宿主，而
该位置在 DOM 里没有（卡片是原子块）。可行路径：先 ⇧Enter（走模型物化一个空段落，光标随之进入
可编辑位）再组合；登记在 docs/backlog.md，真机判据在注入通道修复后补。

**卡片前缘输入纯文本 MUST NOT 删除该卡片**（`insertPlainTextAtCaret` 的既存缺陷：旧实现把
`blocks[at]` 整个跳过、卡片被删）。退格 / 前删在该位置的语义沿用既有卡片语义（退格删**前**一张、
前删删**后**一张），不在本条另立新语义。

### HC4 — Emacs 文本导航族：停靠点一步必有位移，导航不是编辑、不重渲

composer 内的 Emacs 文本导航族（⌃F / ⌃B、⌃A / ⌃E、⌃N / ⌃P、⌃D / ⌃H、⌥D / ⌥⌫、⌃K / ⌃Y、⌃T、
扩选六键 ⌃⇧F/B/N/P/A/E 与按词扩选 ⌥F / ⌥B）SHALL 经**统一键位表**（作用域 `text` = 编辑器内容区
或 composer 输入区，change composer-emacs-nav）分发并按模型层语义执行；MUST NOT 由引擎的原生
caret 路径决定行为。族外的键位（⌃G、⌥G、翻屏族 ⌃V / ⌥V / ⌃L、`Tab` / `⇧Tab`、撤销族）MUST NOT
被本 capability 改变。

1. **停靠点与同形位归一**：停靠点序列 = 段落各**码点边界**偏移（代理对整体一步；低位代理不构成
   独立停靠点）· 卡片前缘 `(i, 0)`（后缘 = 下一块前缘）· 末尾之后的 `(块数, 0)`。段落**非空**末缘
   `(i, len)` 只在**与之写回同一个 DOM 位**时才归一到紧邻后块的前缘——判据是落点形态
   （`domCaretTarget`）的同一性，不是「相邻」本身：后块是**原子卡片**时卡片前缘的写回位就是本段
   末缘（`{kind: "text", index: i, offset: len}`）⇒ 同一位、归一；后块是**段落**（含 M456 起常驻的
   末尾空段落）时两个块各占自己的行盒（`.lumir-hp-qpara` 是块级盒），后块前缘的写回位在**下一行**
   `{kind: "text", index: i + 1, offset: 0}` ⇒ **不是同一位，MUST NOT 归一**（本段末缘是序列上的
   独立停靠点）。**末段**末缘归一到「末尾之后」（M462 已声明这一档即末段末缘的等价表示；M473 起
   它的写回是**末块边界**——末块是非空段落时即该段文本末缘，见 HC3 第 2 条）。归一 SHALL 只有一处实现
   （`normalizeComposerCaret`，移动 / 扩选命令共用）；**空段落**只有 `offset 0` 一个停靠点、不参与
   归一（它自占一行；把它折进「末尾之后」会把归一变成非传递关系——见下条与 §实测依据 M465 节）。
   归一等价类后有两条不变量，缺一不可：**① 一步必有位移**——序列上任意相邻两个停靠点的**写回 DOM
   位**（`domCaretTarget` 的输出）必不相同（MUST NOT「原地空走」）。唯一豁免：**卡片前缘** `(i, 0)`
   与它前一块（**空**段落）的前缘写回同一位（卡片档的写回 = 前段末缘，而空段落只有一个位）——两个
   模型位的**编辑语义不同**（卡片前缘的内容型键入物化新段落、空段落前缘插进该段，HC3 第 3 条），
   都得保留，故这一对在导航上表现为「一次不动的步」（已知边界，见本文件 §实测依据 M465 节）；
   **② 序列不丢点**——每个**非末块**
   段落的每个码点边界 `k ∈ [0, len]` 都 MUST 在序列里有自己的停靠点（等价形态：写回位集合覆盖
   `{kind: "text", index: i, offset: k}` 全部取值），MUST NOT 因归一折叠把一个真实停靠点整档抹掉
   （M465 的缺陷形态）。⌃F / ⌃B SHALL 在停靠点序列上移动**一步**，遇原子卡片 SHALL 整块一步跨过；
   ⌃A / ⌃E 落当前逻辑行行首 / 行尾（`\n` 为界）；⌃N / ⌃P SHALL 优先在**渲染行**之间移动（软折行
   产生的每一屏行是一行，同 x 位；M457 起，Alex 2026-10-12 裁决「与编辑器正文对齐」），**段内没有
   相邻渲染行时**才沿用既有的逻辑行 / 跨相邻段落块行为（超集）；卡片不产生停靠行。
   **行级命令的基准光标 SHALL 取光标所在段落的原始位**（M457，与 M455 的 ⌃N/⌃P 同一条）：段落
   **末缘**（`offset = 文本长度`——键入之后的常态光标位）在**卡片档 / 末段档**归一后会折到下一块
   前缘（末段折到「末尾之后」），那两个落点位**没有行语义** ⇒ 一行都算不出来 ⇒ 表现为「⌃A 按了
   没反应」（M465 起「后块是段落」档不再折叠，这一档的成因随之消失；卡片档 / 末段档照旧）；
   且原始位还带着**真实列位**——⌃N / ⌃P 同列位步进要的正是它。原始位上算行、归一只服务停靠点
   序列（`lineBasisCaret` 一处实现，⌃A / ⌃E / ⌃N / ⌃P 共用）。**词步 ⌥F / ⌥B 的基准位走同一条**
   （M473）：旧实现第一步过归一，卡片档 / 末段档被折成无文本宿主的落点 ⇒ 早退 ⇒ 两个方向都
   「不动」（同一现场下 ⌥B 在段落档回词首、在卡片档不动的既有不对称）；取原始位后三档同形
   ——段末 ⌥F 无动作、⌥B 回本段词首，不跨段（M465 的语义裁决不变）。
2. **导航不是编辑**：仅移动光标 MUST NOT 改变块序列、MUST NOT 产生撤销步、MUST NOT 触发
   `renderComposer` 那类整面重渲（只允许写选区与滚动位）；移动后光标行 SHALL 在 composer 视口内
   （HC2）。失败形态（无动作、块边界、无法落位）SHALL 表现为「无动作」，MUST NOT 留下半截状态。
3. **扩选**：anchor 不动、head 走与移动族**同一份**移动纯函数；⌥F / ⌥B 是**按词扩选**（与键位表内
   既有语义一致），MUST NOT 被实现为词移动。
4. **删除族与 kill-yank**：⌃D / ⌃H SHALL 与 Delete / Backspace 走**同一份**模型语义（卡片前缘 /
   段末遇卡片时对整块作用；有选区时删除选区），MUST NOT 存在第二份删除判定；⌃D / Delete 删除
   一张**卡片**后的光标落点 SHALL 与「卡片 × 钮」的块移除（`removeBlockAt`）**同口径**——贴被删
   块的**前一个段落末缘**（前一块不是段落时落后继块前缘；M473 起两处共用同一份实现，旧实现在
   前删那一路写「被删块的原下标」⇒ 光标从上一行行尾跳到下一行行首）；
   ⌥D / ⌥⌫ SHALL 按词
   kill 到词尾 / 词首并并入 kill 槽，词边界口径与编辑器侧共用同一份实现；⌥⌫ / ⌥Delete SHALL 由
   本能力接管（MUST NOT 被输入区既有的就地退格 / 前删路径吞掉）。词级 kill 与 ⌃K MUST NOT 跨块
   ——到达段落边界即停（段边界处无动作），MUST NOT 隐式合并段落、MUST NOT 隐式删除卡片。⌃K kill
   到当前逻辑行行尾（已在行尾则杀该行界、段内合并两行）。kill 槽 SHALL 是**跨面共用**的单一真源
   （编辑器与 composer 同一槽、同一份连续 kill 相接判定）；kill 的内容 MUST NOT 含卡片。⌃Y 把
   kill 槽内容插入光标处（有选区先删选区），多行经段落拆分入口落成多个段落块，光标在卡片边界位
   时先物化一个段落。

> **消费口径**：本族命令经统一键位表分发，**命中即消费**——分发器命中绑定即吞默认行为，「该处无动作」
> （块首 ⌃B / 段首 ⌥⌫ / 有选区的 ⌃T 等）表现为**无操作**，MUST NOT 放行原生路径（段首的 ⌥⌫ 若放行，
> WKWebView 的原生 `deleteWordBackward` 会跨块合并 / 删卡，与上一条「不跨块」冲突）。族内命令的键位
> ——含 `⌥⌫`（`Alt-Backspace`）与 `⌥Delete`（`Alt-Delete`，与 ⌥D 同命令）——全部在表内；composer 侧
> 的就地退格 / 前删路径只处理**不带任何修饰键**的那一拍。

> 归一口径的一处**实现注记**（与 change 的 design §4.1「读回处也调它」不同）：`caretFromDom` 的
> 编辑读回**不**调 `normalizeComposerCaret`——编辑动词（退格 / 前删 / 键入分派 / 粘贴）依赖
> 「段落末缘 `(i, len)`」与「后块前缘 `(i+1, 0)`」是两个不同的模型值（归一后段落末缘的退格会
> 变成跨块合并、段末键入会插到下一段段首）。等价类服务的是**导航**（移动 / 扩选命令）。

### HC5 — IME 组合期结构冻结：组合窗内 normalize 不得改写 DOM、组合期整面重渲不得运行

IME **组合窗** = `compositionstart` 之后到 `compositionend + IME_CONFIRM_WINDOW_MS` 之前
（确认窗与 M361 的确认拍拦截门同源：WKWebView 先派 compositionend 再派确认拍 Enter，组合的
DOM 落定落在 compositionend 之后的那一段时序里）。对**任意**块序列与**任意**组合落点：

1. **结构归一冻结**：组合窗内 `normalize` MUST NOT 摘除 / 重建任何 composer 子节点、MUST NOT
   改写 DOM 选区。理由：组合期引擎自造的瞬时节点（组合文本宿主变化、空块维持的 `<br>` 等）
   不是 quirk ④ 意义上的脏数据，是 **IME 会话的活锚点**——normalize 的折叠规则（qpara 含元素
   子节点即折进前段）对它们照常成立，摘除即销毁锚点：组合文本被折进前一段、空段落消失，
   随后的落字跟着错位的选区走。缺陷现场（Alex 2026-10-16）：第一行有文字 → ⇧Enter 新起
   第二行 → 第二行起中文组合 → 选中候选后**组合文本跳回第一行、第二行消失**。
2. **整面重渲冻结**：组合期（compositionstart → compositionend）内 `withModel` / `undo` /
   `redo` 的整面重渲（`replaceChildren`）MUST NOT 运行——与 HC3 已知边界「compositionstart
   的物化不走整面重渲」同一条理由（销毁组合锚点、打断 IME 会话），本条款把那一刻的纪律推广到
   整个组合期。冻结范围的不对称是刻意的：normalize 覆盖**全窗**（含确认窗——落定可能落在
   compositionend 之后），整面重渲只覆盖**组合期**——确认窗内组合已结束、DOM 已落定，且键路
   入口（非 Enter 键）在 M361 状态机里本就自清窗口。
3. **补账**：compositionend 后、确认窗过期时 MUST 补跑一次归一，把组合窗内被闸门跳过的裸节点
   折回 `.qpara`——冻结是**延期执行**不是豁免数据层不变量；窗内新起的组合由它自己的
   compositionend 续期（再排一次补账）。
4. **可观测判据（可证伪）**：第一行有文字 → ⇧Enter 新起空行 → 第二行起 IME 组合 → 组合期的
   任何 DOM 变化（含 MutationObserver 触发）之后：第二行段落 MUST 在场、组合文本 MUST NOT
   折进第一行、DOM 选区 MUST NOT 被程序化改写；候选确认（compositionend）后第二行文本 =
   候选文本，光标留在第二行。

**已知边界（HC5）**：发送钮在组合期点击 = 提交并清空当前组合文本（与原生输入框的 commit-and-clear
同行为）；normalize 在组合窗内对发送路径同样冻结，发送读到的就是 DOM 里的组合现状。
组合窗内的键盘入口已被 M361 门覆盖（确认拍吞掉、其余键自清窗口），withModel 组合期闸门防的是
鼠标路径（组合期右键粘贴 / 拖入）等不经键盘的入口。

### M462 现场（2026-10-12）：段末断行的落点（⇧Enter 插到当前行之前）

缺陷现场（Alex）：「光标放在**最后一行的行末**，按 ⇧Enter 不是新起一行，而是在当前这一行
**前面**加了一个换行，光标留在文字行行首」。

探针口径：真实 app（worktree 的 `vite dev`）+ Playwright **WebKit**（真机同族引擎、真机同款
UA）+ Tauri 桩 + 草稿恢复预置合成块序列（三段），逐键注入后读 DOM 选区锚 + 块序列。

| 光标放置法 | DOM 选区（起点，修前=修后） | 修前 ⇧Enter 之后 | 修后 ⇧Enter 之后 |
|---|---|---|---|
| 文本节点末缘（`#text@len`，鼠标点在字后 / 逐键键入的常态位） | `#text(<qpara>)@13` rect 829,715 | 新空段落块追加在末尾（**本来就对**） | 不变 |

| **⌃A → ⌃E**（行级命令把光标放到末行行末 = 用户路径） | `#composer@3`（写回的就是容器边界） | 同上（**用户现场**） | 同上 |
| ⌃E（光标已在末行行末的**原始位**上） | `#text@len`（`navigate` 判「无位移」⇒ 不写回、不折叠） | 不变（本来就对） | 不变 |

- **用户路径是行级命令**：`{block: 块数, offset: 0}` 只在**归一后的写回**里产生（导航把等价值

  自行决定）——这是 HC3 已知边界那一档，本 change 不改它；本条只保证**这一档上的 ⇧Enter 落法**。

**反向验证（区分度）**：把 `insertSoftBreakAtCaret` 里的「末尾之后」这一档去掉（回到钳制
形态）后，模型层 **6 条红**（两种等价表示同结果 / 末段文本逐字节不变 / 末块是卡片时追加在末尾 /
空块序列 / 「末尾之后」与末段段首是两件事 / 第 3 条的落点属性），WebKit 探针两档读数回到
「末段文本被插进 `\n`」，验收场景 117 的两条新断言（像素层行位 + AX 分层签名）同时变红。
探针脚本与逐档读数落 `.local/probes/m462-probe/`（git 外）。

同一个值（`normalizeComposerCaret` 的折叠），行级命令在内部段末写回后段前缘。M465 按「折叠只在

## 实测依据（M465 现场，2026-10-12）：段落后紧邻段落的段末停靠点被归一折叠吃掉

缺陷现场（Alex 原话）：「当我把光标放在末行行首，按 Ctrl+B，光标移动到上一行的倒数第二个字符
后面，而不是行末。」截图现场 = 三行 composer（两行文本 + 末尾空行，M456 起 ⇧Enter 在段末落下的
常驻空段落），光标在末尾空行行首。

**根因**（模型层，零 DOM 即可复现）：`composerCaretStops` 对每个候选停靠点先过
`normalizeComposerCaret`，而该折叠不加条件地把**任何**段落非空末缘 `(i, len)` 折成后块前缘
`(i+1, 0)`。折叠本身只对**卡片**档成立（`domCaretTarget` 把卡片前缘写回前一段落末缘——同一位），
对**后块是段落**这一档不成立：两个段落各占自己的行盒，末缘在上一行行尾、后段前缘在下一行行首。
折叠后 `(i, len)` 与后块前缘同值、被 `push` 的去重合并吃掉 ⇒ 序列里 `(i+1, 0)` 的前一项退化成
`(i, len-1)`，⌃B 于是落在**倒数第二个字符之后**（Alex 的读数逐字对应）。同一折叠还让 ⌃F 从段末
跨两步（跳过 `(i+1, 0)` 落到后段第 1 个字符后）、让 ⌃P 的「列位超出取目标行行尾」写到**后一行行首**
（`.local` 之外的既有单测 `clamp` 档替缺陷形态背了书，M465 一并改准）。

**修法**：折叠条件收紧为「后块**无文本宿主前缘**」——`blocks[i + 1]` 是原子卡片（卡片前缘的写回位
就是本段末缘）或不存在（末段末缘 → 「末尾之后」，M462 口径）时才折；后块是段落时保留 `(i, len)`
原样。空段落前缘 MUST NOT 折进「末尾之后」：那会让归一成为**非传递**关系（`(i, len)` 与
`(i+1, 0)` 同值、`(i+1, 0)` 又与 `(n, 0)` 同值），等价类随即把 `(i, len)` 一并吃掉——正是本缺陷。

**判据与证据**：模型层四条——① 复现用例（三块现场 ⌃B 落 `(1, len)`）；② **覆盖不丢点**属性
（小块序列全枚举：每个非末块段落的每个码点边界都有自己的写回位）；③ **相邻即互为一步**属性
（全枚举的正反向对称）；④ **词步的段-段边界**（段末 ⌥F 无动作、段末 ⌥B 回本段词首、段首 ⌥B 无动作、
卡片档既有口径——两方向都钉）。**区分度如实**：把折叠改回缺陷形态后 **① ② ④ 判红**（① 实测落
`{block: 1, offset: 9}` = `len-1`；② 首个反例 `[para("abc"), para("")]` 的码点边界 `0:3` 没有写回位；
④ 实测回到「跨段」落点），
**③ 仍绿**——旧序列虽然丢了 `(i, len)` 这一点、内部却自洽，故 ③ 守的是另一种失效（正反向不对称 /
折叠只落在一侧），对本缺陷**无区分度**，不计入本条的覆盖声明（REVIEW.md「断言等价于子串 / 覆盖声明超出真实验证」条）。真机层：
验收场景 154（末段空行行首 ⌃B + 键入探针串，判据是探针接在**上一行行末**而不是倒数第二个字符之后），
修前 **FAIL**（AX 读数 `hnl-brk-cxqzkd`，与 Alex 现场逐字对应）/ 修后 **PASS**（`hnl-brk-cdxqzk`）。
证据（git 外）：`.local/acceptance/<日期>/154-…/`（修后绿）+ `.local/missions/m465-reverse-validation/`
（缺陷形态的两轮读数与原始输出）。

**已知边界（如实登记）**：
- **末尾空段落前缘 `(i, 0)` 与「末尾之后」`(n, 0)` 谁是哪一位**：两者都是 0×0 几何的无 caret 位置
  （M456 的 `:empty::after` 零宽字符撑出行盒、但 `Range` 量不到位），本 mission 的通道（KimiCU 的
  AX / 截图 / 键入注入，无 JS 求值）判不了它们的**绘制**位置是否同一。M465 **不**折叠这一对：折叠
  会连带吃掉 `(i, len)`（见上），代价远大于收益；两档的写回位不同（`{text, i, 0}` vs
  `{boundary, n}`），一步往返因此至少不改变模型值。**M473 起「末尾之后」的写回分末块形态**：末块是
  **非空段落** ⇒ 该段文本末缘（`{text, n-1, len}`，可见性修好）；末块是**空段落** ⇒ 仍写容器边界
  ——落到空段落前缘会与 `(i, 0)` 这一档的写回位重合（停靠点序列的「一步必有位移」判红，见下），
  故这一子档的可见性**未修**。
- **卡片前缘 `(i, 0)` 与它前一块（空段落）的前缘写回同一位**：卡片档的写回是「前段末缘」，空段落
  只有这一个位 ⇒ 这一对在停靠点序列里表现为「一次不动的步」。M465 **不**折：两个模型位的编辑语义
  不同（卡片前缘的内容型键入物化新段落、空段落前缘插进该段），折掉任一个都会改掉可达行为
  （`tests/unit/composer-nav.test.ts` 的「相邻即互为一步」属性对这一对显式豁免，豁免条件写成
  「其中一项是卡片前缘」）。两对都登记在 `docs/backlog.md`。
- **以尾随 `\n` 结尾的段落文本**（`"ab\n"`）：末缘 `(i, len)` 落在**没有行盒**的那一行上（HC1 的
  渲染口径：尾随换行不产生行盒），它的写回位与 `(i, len-1)` 是同一位。composer 的编辑入口保证
  「光标所在段落恒不以 `\n` 结尾」（`insertSoftBreakAtCaret` 的函数头），草稿恢复的存量数据仍可能
  命中；M465 不动这一档，登记在此。
- **删除族那处既有不一致（M465 暴露、M473 已修）**：`⌃D` / `Delete` 在卡片前缘的整体移除
  （`deleteForwardAtCaret`）当时有自己的光标口径（留在被删块原下标 = 后一块前缘），与同位置经
  写回位按同一键（光标不动）落点不同——M465 之前被无条件折叠遮住，收紧后暴露并登记
  `docs/backlog.md`（M465 finding）。M473 把卡片档改成直接复用 `removeBlockAt`：两条路径的光标
  同值，判据回到一条断言（旧例外分支已删，见 §实测依据 M473 节）。编辑动词的**读回**路径
  （`caretFromDom` 不归一）仍未动。
- **扩选包装**（⌃⇧F / ⌃⇧B / ⌃⇧N / ⌃⇧P / ⌃⇧A / ⌃⇧E 与 ⌥F / ⌥B 的 head）走的是**同一份**移动纯函数

  不导出的闭包，模型层没有单独判据，真机面由场景 146（anchor 不动）覆盖——本 mission 未新增扩选层
  判据，如实登记在此而不是算进覆盖。
- **词步（⌥F / ⌥B）在段-段边界的**行为变更（M465 显式登记，不由上面那条「同效」盖过）**：

  后段，于是**段-段边界不再跨段**——段末 ⌥F = **无动作**（旧：折进后段、一步跳到后段词尾，末段时
  表现为「末尾之后」）、段末 ⌥B = **回本段词首**（旧：折到后段前缘 = **反向按键却向前跳**）、
  段首 ⌥B = 停在本段段首（两版一致）。**语义裁决（tower 2026-10-12，M465 r1 评审 P2-1）：采用

   单测覆盖），故无可观测面变化。

   判据：`tests/unit/harness-composer.test.ts` 的边界位写回用例（「末尾之后」不再是 `continue`

## 实测依据（M527 现场，2026-10-16）：IME 组合期 normalize 折段——候选落字跳回第一行

缺陷现场（Alex 原话）：「harness composer 里，当我输入一行文字，然后 Enter 新起一行后，我使用
中文输入法并选中一个候选后，输入的内容会回到第一行，原本第二行就消失了」。

**根因**（代码路径推理；真机探针暂停——装版实例在场 + IME 本就无法自动化，诊断以代码路径 +
DOM 替身单测复现为准）：composerObserver（只有 `normalizing` 重入闸）被组合期的 childList
变化触发 → normalize 跑在组合中途。事件序列：

1. 第一行 `第一行` + ⇧Enter：`softBreakStep` → withModel → renderComposer 两块
   `[qpara("第一行"), qpara("")]`，光标写进空 qpara2（`{block:1, offset:0}`）。
2. `compositionstart`：非卡片前缘 ⇒ 无 DOM 写（undoHistory 压前态）。WKWebView 往 qpara2 插
   组合文本；组合期的块内含元素子节点（空块维持的 `<br>` / 组合包装——qpara 从
   `childElementCount 0` 变成 >0）。
3. 该 childList 变化到达 observer → normalize：qpara2 因含元素子节点被判脏 → 摘除、
   `paraTextOf` 读出的组合文本**折进前驱 qpara1** → 结尾 `setDomCaret` 按组合前的选区写回。
4. 组合锚点节点被销毁、选区被程序化改写 → IME 会话错乱；选中候选后落字跟着错位选区走进
   第一行，qpara2 已不在 = Alex 截图（m4）的两行并一行。

次要嫌疑 withModel 整面重渲排除为**防线缺口而非本案真凶**：组合期内键盘入口（keydown /
beforeinput）均已有 M361 组合期早退，withModel 无现实触发路径；修复时按 HC5 第 2 条一并补上
组合期闸门（防鼠标路径）。

**修法**（HC5）：normalize 组合窗闸门（composing ‖ 确认窗内早退）+ withModel / undo / redo
组合期闸门 + compositionend 排期确认窗过期后的补账归一。折叠规则本身不动——缺陷在**时机**
不在规则。

**判据与证据**：DOM 替身单测（tests/unit/harness-ime-enter.test.ts「HC5」小节）断言两块结构、
组合文本落段、选区不改写、补账归一四件事；反向验证 = 闸门改回直通后该小节 MUST 全红。真机
候选确认路径归场景 156 手动复验（合成键进不了 TSM，m461 定案）。

## 与实现的关系

- HC1 的落法由 `src/harness-panel.ts` 的纯模型层 `insertSoftBreakAtCaret` 决定（段末 / 卡片前缘
  落新空段落块，段中插 `\n`），DOM 只是这个模型的渲染面——**不得**为同一次按键再挂第二套
  键盘处理路径。M462 起该函数先判「末尾之后」（`caret.block >= 块数`）为「末块之后」：新空段落块
  追加在末尾；**不得**把它钳到末块后按 `offset 0` 当末段段首处理（那正是本缺陷的形态）。
  键位挂点在 composer 的 `keydown`（Enter / ⇧Enter 那一档），MUST NOT 再加第二处。
- HC2 的判据是纯函数 `caretScrollTop`（`src/harness-panel.ts`），DOM 侧（`setDomCaret` 的
  收尾）只负责量读数、写 `scrollTop`；光标已在视口内时纯函数返回原值，不抖动视口。
- HC3 的读回 / 写回规则是 `src/harness-panel.ts` 的四个纯函数：`boundaryCaretAt`（DOM 边界
  → 模型位）、`domCaretTarget`（模型位 → DOM 落点形态）、`isCardFrontCaret`（是不是边界位）、
  `boundaryTypingCaret`（边界位上的内容型键入判据）。
  `caretFromDom` / `setDomCaret` / `domPointOf` 只是这些规则在真 DOM 上的执行面，读 / 写必须互为
  逆运算（写落的阶梯见 `domCaretTarget`：前段落末缘 → 后一张卡片的首个文本位 → 末块边界——M473
  起「末尾之后」在末块是非空段落时落该段文本末缘，只剩末块是空段落 / 卡片这一子档仍写块级容器
  边界）。
  内容型输入的物化收口在三处：composer `keydown` 的可打印单字符（`boundaryTypingCaret` 命中才
  consume——边界位上**唯一会派发**的事件）、`beforeinput` 的 `insertText`（引擎把边界位解析成
  相邻可编辑位的形态）、`compositionstart`（IME 组合的首次落字）；粘贴 / 拖入 / ⇧Enter /
  插卡片各自的入口**不改落法**——它们的「卡片前缘」分支早已实现。

  后块**无文本宿主前缘**——卡片 / 末段之后——时折叠段落末缘，M465 起收紧；后块是段落时末缘不是
  同一位、MUST NOT 折叠）、

- 已知边界：卡片上按 ⇧Enter 时「新行」落在卡片那一行的上方（光标所在处），不改变卡片与
  文本块的相对次序——卡片是原子块，本条不承诺它内部出现换行。
- 已知边界（HC3，M457；M473 修订第一条）：
  - **「末尾之后」**（`block = 块数`）：M473 起末块是**非空段落**时写回该段文本末缘（有 caret

  （先压前态再插块），代价是这一步的实现偏离「结构性修改一律整面重渲」的常规路径，写在这里备案。
