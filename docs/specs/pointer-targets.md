# 次级图标动作的指针命中区合同

> 状态：canonical（2026-11-27 Alex 采纳治理沉淀方向）。
> 适用范围：新增或修改的次级图标动作。首个 consumer 是 Harness；本合同不要求回改全仓既有按钮。
> 主按钮、正文内联链接与 coarse pointer / 触屏密度不在这里重新定档；触屏改造另议。

## 1. 尺寸依据与 Lumir 定档

[W3C WCAG 2.2 Understanding SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
给出的最低目标是 24×24 CSS px，或满足 spacing 等例外；该条覆盖鼠标、触控板、触控笔与触摸等指针输入，
并非只服务触屏。同文档把 44×44 CSS px 列为 Enhanced 档，不是桌面次级动作的强制尺寸。

Lumir 在此基础上作更明确的产品选择：

- 新增或修改的次级图标动作，实际指针命中区 SHALL 默认达到 **28×28 CSS px**。
- 空间受限时可收缩，但宽、高 MUST 各自不低于 **24 CSS px**；不得以 W3C 的 spacing exception 代替这个下限。
- 28 是 Lumir 的桌面默认设计目标，MUST NOT 写成 W3C 标准。44 不是本合同的桌面目标。
- 上述尺寸按 CSS px 判定，不随主题、字号缩放或设备像素比降低下限。

## 2. 三层尺寸分离

实现 MUST 分别定义并验收下列三层，MUST NOT 用其中一个尺寸代替另外两个：

| 层 | 含义 | 约束 |
|---|---|---|
| 图标视觉尺寸 | 用户看到的 glyph / SVG / 可见文字 | 保持表面所需的轻量层级；具体值由该表面的设计合同规定 |
| 可见按钮底板 | hover / focus / active 等状态下可见的背景、边框与圆角 | 可保持紧凑；不得为了放大命中区而同步放大成触屏式按钮 |
| 实际指针命中区 | 接受指针动作的真实区域 | 默认 28×28、最低 24×24；必须是真实可命中的几何，不是仅写在 CSS 里的意图 |

命中区 SHALL 由实际按钮盒或等效的透明扩展承载。图标与装饰层 SHOULD 不拦截事件语义；不得以 JS 坐标猜测、
扩大父表面点击范围或把邻近文字变成动作入口来伪造命中区。

## 3. 几何与布局不变量

- **无布局跳动**：hover / focus / 显现 / 消退 MUST NOT 改变文档文本、消息行高或周边布局几何。
  命中盒应在静止态已稳定，不得等 hover 才换盒、移位或撑开内容。
- **相邻不重叠**：不同动作的命中区在任何相关状态下 MUST NOT 有正面积交集；可见文字变长、success、
  disabled、焦点与语言切换也属于相关状态。需要让位时只移动动作层，不推挤文档内容。
- **不裁切、不可达**：命中区 MUST NOT 被祖先 `overflow` / clip 裁掉，也不得越过容器形成看得见或声明存在、
  实际却无法点击的区域。在元素完整进入视口的稳态下，中心与边缘都必须能命中。
- **不遮正文**：透明扩展 MUST NOT 截获正文、摘录、出处或其他既有内容区域的指针操作。若扩展与文字区相交，
  应先消耗既有留白或预留真实动作槽位，不得以遮住正文换取命中率。
- **可见内容完整且居中**：可见底板与装饰层 MUST 位于 glyph / 状态文案之后，不得遮盖其实际渲染墨迹；
  glyph / 文案及其 SVG 视盒 MUST 完整落在可见底板内。实际墨迹包围盒中心相对可见底板中心的水平、垂直偏移
  MUST 各自不超过 1 CSS px；该容差只吸收像素栅格化，不允许用 SVG 外框尺寸或 CSS 居中声明替代像素验证。
- **嵌套事件优先级**：动作嵌套在另一个可点击表面内时，整个动作命中区 MUST 只触发动作自身；中心与透明边缘
  都不得触发父表面。父表面自身的大面积 MUST NOT 被计作子动作的命中区；动作区之外的父表面行为保持不变。

## 4. 显现、状态与可访问名

- hover 显现的动作 MUST 同时有 `focus-visible` 显现路径；两条路径使用同一个稳定命中盒，不得产生布局跳动。
- hover / focus / disabled / success 等状态 SHALL 保持同一套三层尺寸模型。状态反馈不得令相邻命中区重叠。
- 既有键盘模型 MUST NOT 被无意改变：不得顺手新增或删除 Tab 停靠点，不得把原属文本编辑器的按键改交给卡片。
  若某表面明确禁止卡片或动作进入 Tab 序，继续遵守该表面合同。
- icon-only 动作 MUST 有 accessible name。可见文字与 accessible name 的对应关系沿用该表面的既有规则；
  替换 glyph、改内联 SVG 或扩展命中区不得改掉既有读屏名。
- 复制反馈、错误反馈与禁用语义属于既有产品行为；尺寸改造 MUST NOT 伪造成功或把 disabled 变成可执行。

## 5. 机器验收

新增或修改的次级动作 MUST 同时有声明层与真实行为层判据：

1. 用 `getBoundingClientRect()` 或等效方法读取真实几何，核对默认 / 最低尺寸、相邻不重叠、文本区不相交与容器边界。
2. 用 `document.elementFromPoint()` 或等效命中测试检查中心、四边与近角采样点；结果必须是目标按钮或其装饰后代。
   只断言 `min-width` / `height` / `padding` 等 CSS 声明不算通过。
3. 至少对关键动作执行真实指针点击，核对动作恰好发生一次；嵌套动作还须核对父表面没有收到跳转 / 打开等副作用。
4. 对 hover / focus / disabled / success 与相关语言档分别检查状态几何；对完整可见的容器边缘位置检查裁切。
5. 每条新增或修改的断言 MUST 按
   [OpenSpec 流程「新断言的反向必红」](../process/openspec-workflow.md) 单独构造必红输入，实测 FAIL；
   恢复后实测 PASS。红 / 绿两次读数均须留存，整批只造一个反例不算逐条完成。

## 6. 视觉裁决与状态分列

视觉候选与工程通过是不同事实。实施前 / 实施中 SHALL 用同一合成 fixture 做现状与候选的同屏或并排对比；
正式视觉基线更新前 MUST 另经 Alex 过目，不得由实施任务自行 `--update`。

节点 2 记录、mission / 批次报告与复盘报告 MUST 至少分列下列状态，并分别附证据或「否 / 不适用 + 原因」；
不得以一个「PASS」概括，也不得互相替代：

| 状态 | 含义 |
|---|---|
| 视觉候选 | 现状 / 候选对比已产出，Alex 的审美与基线裁决状态可追踪；机器 PASS 不等于视觉候选已批准 |
| implemented | 实现已提交，附 commit / merge hash |
| machine PASS | 自动化门禁、单测、结构与本地像素层分别按要求通过，附命令、原文结果与证据 |
| native PASS | 要求的真实 WKWebView 验收场景通过，附场景与 `status.txt` 指针 |
| released | 已进入发布产物，附版本与 release index；不打包则明确写「否」及原因 |
| archived | 已提交归档且 `--archived` 审计 PASS，附归档提交与读数 |

五态的既有口径以 [OpenSpec 流程「状态分列」](../process/openspec-workflow.md) 为准；本节的「视觉候选」是新增的视觉
裁决轨，不替代其中任何一态。
