# 浮层可见性合同（overlay visibility）

> 状态：新增（M397，2026-10-09）。本文档是**浮层类弹出物可见性**的质量合同：可被测试证伪的
> 不变量条款。渲染/交互缺陷修复的「合同先行」规则见
> [../process/rendering-defect-contract-first.md](../process/rendering-defect-contract-first.md)——
> 定位到本文件某一条、配不变量级属性测试，两者与修复同 PR。
> 浮层的**外观**（阴影 / 描边 / 圆角 / elevation 配方）不在本文件，见
> [design-tokens-v1.md](design-tokens-v1.md) §浮层 elevation 与遮罩。**宽度与可读宽度**（三档、
> em 上限、换边 / 平移、截断方向）也不在本文件，见 `openspec/specs/ui-design-system` 的
> 「浮层宽度分档与可读宽度注册表」条（change `overlay-width-contract-oct24` 的 delta）。
> 本文件只管**可见性**。

## 适用范围

「浮层类弹出物」指任何**打开后覆盖在既有内容之上、关闭即消失**的瞬时界面元素：popover、
下拉菜单、选择器浮层、tooltip / hover 泡、modal 面板、toast。按几何形态枚举的输入分布是
（条款引用分布，不引用具体案例）：

- **锚定方式**：锚在某个触发元素（钮 / 图标 / 读数格）旁的浮层 vs 全局居中/边缘的覆盖层；
- **锚点落点**：触发元素贴视口左缘 / 右缘 / 上缘 / 下缘 / 中部；
- **祖先容器**：触发元素到根之间的任意祖先是否带 `overflow: hidden` / `auto` / `scroll` /
  `clip`，以及是否带 `transform` / `filter` / `backdrop-filter` / `will-change` /
  `contain`（这几个属性会改变 `position: fixed` 的包含块）；
- **内容体量**：空态 / 单行 / 长清单（可滚动）。

## 不变量

### O1 — 打开即完整可见（不得被祖先裁切）

**任意**浮层类弹出物，在其**打开态**下，其可见区域 MUST 等于其完整包围盒。等价的可证伪表述：
打开态的浮层，其包围盒内的像素 MUST 呈现浮层自身的绘制内容（如背景 / 描边 / 文字字形），
而不是其下方被覆盖元素的绘制内容；且浮层内容 MUST NOT 在包围盒之外被截断或整体缺失。

「打开」的语义以元素的可见性状态为准（本仓即 `[hidden]` 撤销 / 组件自报 open）；浮层自身
`hidden` 时本条款不适用。

### O2 — 打开即落在视口内

打开态的浮层，其包围盒 MUST 完整落在**视口矩形**内（不越出窗口四边）。当锚点贴边使「按自然
偏移摆放」会越界时，由**定位逻辑夹住**（移动浮层或压其可滚动区高度），MUST NOT 用「越出后靠
祖先裁掉」当作合规——裁掉正是 O1 要禁的形态。

### O3 — 定位包含块不得落在会被裁的祖先里

浮层的定位方式（`absolute` 的包含块 / `fixed` / 挂载点）MUST 保证 O1 对**整条祖先链**成立，
而不是只对当前的某一个祖先成立：只要从浮层到根之间存在任何满足「会裁切其后代」的祖先
（带上述 `overflow` 之一、且是浮层的定位包含块链上的一环），O1 即处于随时可被触发的状态。

### O4 — 锚定到发起它的区域（不跨 pane）

**由某个区域的动作触发的 toast，其定位包含块 MUST 是发起它的那个区域**（编辑器 pane 或
harness 面板）的挂载元素，MUST NOT 是跨 pane 的容器（如整个编辑器列）或视口。等价的可证伪
表述：在分栏（双 pane）态下，由某个 pane 的动作触发的 toast，其几何包围盒 MUST 落在该 pane
的矩形内，MUST NOT 落在另一个 pane（或 harness 面板）的矩形内。

「发起它的区域」的解析 MUST 收敛在一处（本仓即 `src/main.ts` 的 toast 归属解析）：文档动作的
提示归**活跃 doc pane**，harness 面板动作的提示归 **harness pane**，调用方不各判一次
（单一来源，REVIEW.md 「同一语义两处真源」条）。反例形态（M420 现场，Alex 2026-10-10）：toast 挂在
跨 pane 的编辑器列上，单 pane 时看不出问题，分栏后编辑器列的右下角就是右 pane ——左 pane 里
保存（`Saved!`）的提示落到右 pane（可能是 harness）上，「提示属于谁」与「它画在哪」错位。

本条与 O1–O3 **正交**：O1–O3 管「打开即完整可见」，本条管「看得见的是不是这里」。承载手段
不限（`absolute` 挂 pane 挂载元素 / 现算坐标挂视口都可），只约束可观测结果；但它与 O3 有共同
的结构前提 —— 该包含块在整条祖先链上不得有裁切者。

### O5 — 空内容浮层不得先开后收（无「可见但无内容」的中间态）

对「内容为空即不显示」的浮层（上文的**内容体量 = 空态**这一维），从「用户表达展开意图」到
「浮层可见」之间 MUST NOT 出现**可见但无内容**的中间态：可见性 MUST 以「内容已确认为非空」
为前提，取数过程（同步 / 异步 / 失败）MUST NOT 让空内容短暂可见。空内容路径（清单确认为空
或取数失败）MUST NOT 造成一次「可见 ↔ 不可见」的往返，且 MUST 给用户可感知反馈（toast /
钮态一类），MUST NOT 静默。

等价的可证伪表述：以**内容体量（空 / 单行 / 长清单）× 取数时延（立即 resolve / pending /
reject）**为输入分布，断言浮层元素在**任一观察点**（同步任务内 / 微任务 / 取数 resolve 后）都
不以空内容可见；内容非空时 `hidden` 恰翻转一次 true→false 并保持，空内容时 `hidden` 恒 true。
同一浮层的 **`aria-expanded` MUST 反映实际可见态**（`aria-expanded="true"` ⟺ 浮层可见），
MUST NOT 按「展开意图」提前翻——可见态在 `hidden` 与 `aria-expanded` 两处各写一遍即同一语义
两处真源（REVIEW.md 「同一语义两处真源」条），改动只落到一处就会脱节。

反例形态（M442 现场，2026-10-10）：会话浮层 `setSessPop(true)` 先 `hidden = false` + 定位、
**后**异步拉清单；清单为空时在取数 resolve 后收起。`.lumir-hp-sesspop` 是带 padding / border /
box-shadow 的盒，于是先画出一个空盒、一个 IPC 往返后收回——用户看到「闪现一个小浮层、瞬间
消失」。期间 `aria-expanded` 已按展开意图翻 true，而浮层实际从未「打开」到可测量。

本条与 O1–O4 **正交**：O1–O4 管**打开态**（可见即完整 / 落在视口内 / 包含块不被裁 / 归属发起
区域），本条管**可见性的进入条件与开-闭跃迁**——M442 的缺陷正落在两者之间的缝里（浮层从未
「打开」到可测量，O1–O4 因此都够不着）。

### O6 — 关闭只由用户意图触发（自身重建不得改变可见态）

**任意**浮层类弹出物，其**自身发起**的内容 / 行 DOM 重建（列表刷新、确认态进出、数据重拉、
逐项删除后的重排）MUST NOT 改变浮层的开闭状态，MUST NOT 把焦点送出浮层。等价的可证伪表述：
以**重建触发**（数据重拉 / 确认态进出 / 空结果切换 / 异步刷新）× **持焦节点**（浮层内任一可
聚焦件：筛选输入框、行钮、确认钮）× **引擎的焦点修复行为**（持焦节点被移除 / 被禁用时的
`focusout`）为输入分布，断言重建之后浮层仍可见（`hidden` 保持 false）、`document.activeElement`
仍在浮层内，且浮层内的就地键与输入照常生效。

根因形态（M668 现场，来自 M667 真机批）：vault 列表移除确认后，重拉列表用
`list.replaceChildren(...)` 换掉整份行 DOM；浏览器在**持焦节点被移除 / 被禁用**时把焦点送回
body 并派发 `focusout`（relatedTarget 为 null），浮层的「焦点离开即收起」把这条派发读成用户
意图——浮层整个收起，撤销提示成为唯一入口。两个引擎实测的分叉（探针
`.local/probes/m668/focus-semantics.mjs`）：chromium 在「持焦节点被移除」与「持焦钮被禁用」
两条上都派发该事件；Playwright WebKit 两条都不派发，但焦点会**静默**退回 body（浮层还开着、
键入却不再落进筛选框）。因此**按引擎分支不是解**：正确做法是让重建根本不碰持焦节点——重建前
把焦点收到不会被重建的元素上，重建窗口内不把 `focusout` 当关闭信号，重建后再核一次焦点还在
不在浮层内。

本条与 O5 同属「开-闭跃迁」，区别在触发源：O5 管**进入**可见态的条件（内容为空不得先开后收），
本条管**保持**可见态——关闭只由用户意图（点浮层外 / Tab 出去 / Esc / 窗口失活）触发，浮层自己的
实现细节不是关闭信号。

## 证伪方式（属性测试口径）

对「锚定方式 × 锚点落点 × 祖先容器 × 内容体量」的输入分布逐个取样，打开浮层后：

1. **几何**：取浮层的几何包围盒，断言它完整落在视口矩形内（O2）、且非退化（宽高为正，
   不小于其内容的最小尺寸）。
2. **绘制**：在**包围盒区域内**采样像素，断言区域内确有浮层自身的绘制内容（文字字形 /
   壳底色 / 描边）——这是区分「真的画出来了」与「几何上存在、实际被祖先裁掉」的唯一判据，
   因为多数 AX 实现（含本仓真机用的 WKWebView）对**被裁内容照样暴露节点与未裁的包围盒**，
   纯几何断言在这一类缺陷上无区分度。
3. **反向验证**：把被测的可见性成因（祖先裁切 / 定位包含块 / 夹取逻辑）临时改回缺陷形态，
   断言 MUST 变红；不变红即说明该断言对该缺陷无区分度，不算覆盖。
4. **归属（O4）**：分栏态下触发某 pane 的 toast，断言其几何包围盒落在**发起 pane** 的矩形内、
   且**不落在另一个 pane** 的矩形内。真机层用窗口截图的相对取色承担（在「发起 pane 的右下角」
   与「另一 pane 的对应位置」各采一点，与同一块空白底色比）——`geom` 只对**视口**判越界，
   判不了「在哪个 pane 里」，两者不可互替。
5. **空态跃迁（O5）**：以**内容体量（空 / 单行 / 长清单）× 取数时延（立即 resolve / pending /
   reject）**为输入分布，断言浮层在同步任务内 / 微任务 / 取数 resolve 后**任一观察点**都不以
   空内容可见，非空时 `hidden` 恰翻转一次 true→false；空内容路径另行断言有用户可感知反馈
   （不得静默）与 `aria-expanded` 与可见态一致。**可判读数落在决策层**：真机层无「逐帧」采样
   通道，浮层的开-闭往返（一帧级）不可直接观测——因此判据下沉到纯粹函数（揭示决策 + 可见态
   派生），真机层只判后果面（不出现浮层盒 + 出现反馈）。
6. **自身重建（O6）**：以**重建触发 × 持焦节点 × 引擎焦点修复**取样，重建后断言浮层
   `hidden` 仍为 false、`document.activeElement` 仍在浮层内，且输入 / 就地键照常生效。
   **反向验证**：把「重建前把焦点收进浮层、重建窗口内忽略 `focusout`、重建后核一次」这套收口
   去掉，断言 MUST 变红——chromium 会以「浮层被收起」变红，Playwright WebKit 会以「焦点静默退回
   body」变红（两条都实测过）。判据落点：`tests/unit/vault-switcher.test.ts` 的假 DOM 属性
   用例（模型按上面两条引擎行为建模）+ `tests/visual/scenes/m668-vault-remove-focus.spec.ts`
   的真实引擎场景（chromium 与 webkit-realua 两个 project）。

## 与实现的关系

- 本条款对实现**不给具体定位手段**（`fixed` / 挂 app-shell / 去祖先 overflow 都可能是合规解），
  只约束可观测结果与「包含块不得落在会被裁的祖先里」这条结构性前提。
- 判据的落点：真机行为层由 `scripts/acceptance` 的 `geom` 断言承担（几何 + 绘制两段，
  见其 [README](../../scripts/acceptance/README.md) §断言）；chromium 视觉层的
  `toBeVisible` 类断言**不算覆盖** O1（它不查祖先裁切），需要时另加包围盒包含断言。
- O6 同为**结果约束**：不规定用什么手段把焦点留在浮层内（重建前收焦、重建窗口内忽略
  `focusout`、重建后接回，任一套或组合），只约束「重建后浮层仍可见、焦点仍在浮层内」这个可
  观测终态；判据落在单测的假 DOM 属性用例与真实引擎场景（见「证伪方式」第 6 条）。
