# 浮层可见性合同（overlay visibility）

> 状态：新增（M397，2026-10-09）。本文档是**浮层类弹出物可见性**的质量合同：可被测试证伪的
> 不变量条款。渲染/交互缺陷修复的「合同先行」规则见
> [../process/rendering-defect-contract-first.md](../process/rendering-defect-contract-first.md)——
> 定位到本文件某一条、配不变量级属性测试，两者与修复同 PR。
> 浮层的**外观**（阴影 / 描边 / 圆角 / elevation 配方）不在本文件，见
> [design-tokens-v1.md](design-tokens-v1.md) §浮层 elevation 与遮罩。本文件只管**可见性**。

## 适用范围

「浮层类弹出物」指任何**打开后覆盖在既有内容之上、关闭即消失**的瞬时界面元素：popover、
下拉菜单、选择器浮层、tooltip / hover 泡、modal 面板、toast。按几何形态枚举的输入分布是
（条款引用分布，不引用具体案例）：

- **锚定方式**：锚在某个触发元素（钮 / 图标 / 读数格）旁的浮层 vs 全局居中/边缘的覆盖层；
- **锚点落点**：触发元素贴视口左缘 / 右缘 / 上缘 / 下缘 / 中部；
- **祖先容器**：触发元素到根之间的任意祖先是否带 `overflow: hidden` / `auto` / `scroll` /
  `clip`，以及是否带 `transform` / `filter` / `backdrop-filter` / `will-change` /
  `contain`（这几个属性会改变 `position: fixed` 的包含块）；
- **内容体量**：空态 / 单行 / 长清单（可滚动）。

## 不变量

### O1 — 打开即完整可见（不得被祖先裁切）

**任意**浮层类弹出物，在其**打开态**下，其可见区域 MUST 等于其完整包围盒。等价的可证伪表述：
打开态的浮层，其包围盒内的像素 MUST 呈现浮层自身的绘制内容（如背景 / 描边 / 文字字形），
而不是其下方被覆盖元素的绘制内容；且浮层内容 MUST NOT 在包围盒之外被截断或整体缺失。

「打开」的语义以元素的可见性状态为准（本仓即 `[hidden]` 撤销 / 组件自报 open）；浮层自身
`hidden` 时本条款不适用。

### O2 — 打开即落在视口内

打开态的浮层，其包围盒 MUST 完整落在**视口矩形**内（不越出窗口四边）。当锚点贴边使「按自然
偏移摆放」会越界时，由**定位逻辑夹住**（移动浮层或压其可滚动区高度），MUST NOT 用「越出后靠
祖先裁掉」当作合规——裁掉正是 O1 要禁的形态。

### O3 — 定位包含块不得落在会被裁的祖先里

浮层的定位方式（`absolute` 的包含块 / `fixed` / 挂载点）MUST 保证 O1 对**整条祖先链**成立，
而不是只对当前的某一个祖先成立：只要从浮层到根之间存在任何满足「会裁切其后代」的祖先
（带上述 `overflow` 之一、且是浮层的定位包含块链上的一环），O1 即处于随时可被触发的状态。

### O4 — 锚定到发起它的区域（不跨 pane）

**由某个区域的动作触发的 toast，其定位包含块 MUST 是发起它的那个区域**（编辑器 pane 或
harness 面板）的挂载元素，MUST NOT 是跨 pane 的容器（如整个编辑器列）或视口。等价的可证伪
表述：在分栏（双 pane）态下，由某个 pane 的动作触发的 toast，其几何包围盒 MUST 落在该 pane
的矩形内，MUST NOT 落在另一个 pane（或 harness 面板）的矩形内。

「发起它的区域」的解析 MUST 收敛在一处（本仓即 `src/main.ts` 的 toast 归属解析）：文档动作的
提示归**活跃 doc pane**，harness 面板动作的提示归 **harness pane**，调用方不各判一次
（单一来源，REVIEW.md 第 8 条）。反例形态（M420 现场，Alex 2026-10-10）：toast 挂在
跨 pane 的编辑器列上，单 pane 时看不出问题，分栏后编辑器列的右下角就是右 pane ——左 pane 里
保存（`Saved!`）的提示落到右 pane（可能是 harness）上，「提示属于谁」与「它画在哪」错位。

本条与 O1–O3 **正交**：O1–O3 管「打开即完整可见」，本条管「看得见的是不是这里」。承载手段
不限（`absolute` 挂 pane 挂载元素 / 现算坐标挂视口都可），只约束可观测结果；但它与 O3 有共同
的结构前提 —— 该包含块在整条祖先链上不得有裁切者。

## 证伪方式（属性测试口径）

对「锚定方式 × 锚点落点 × 祖先容器 × 内容体量」的输入分布逐个取样，打开浮层后：

1. **几何**：取浮层的几何包围盒，断言它完整落在视口矩形内（O2）、且非退化（宽高为正，
   不小于其内容的最小尺寸）。
2. **绘制**：在**包围盒区域内**采样像素，断言区域内确有浮层自身的绘制内容（文字字形 /
   壳底色 / 描边）——这是区分「真的画出来了」与「几何上存在、实际被祖先裁掉」的唯一判据，
   因为多数 AX 实现（含本仓真机用的 WKWebView）对**被裁内容照样暴露节点与未裁的包围盒**，
   纯几何断言在这一类缺陷上无区分度。
3. **反向验证**：把被测的可见性成因（祖先裁切 / 定位包含块 / 夹取逻辑）临时改回缺陷形态，
   断言 MUST 变红；不变红即说明该断言对该缺陷无区分度，不算覆盖。
4. **归属（O4）**：分栏态下触发某 pane 的 toast，断言其几何包围盒落在**发起 pane** 的矩形内、
   且**不落在另一个 pane** 的矩形内。真机层用窗口截图的相对取色承担（在「发起 pane 的右下角」
   与「另一 pane 的对应位置」各采一点，与同一块空白底色比）——`geom` 只对**视口**判越界，
   判不了「在哪个 pane 里」，两者不可互替。

## 与实现的关系

- 本条款对实现**不给具体定位手段**（`fixed` / 挂 app-shell / 去祖先 overflow 都可能是合规解），
  只约束可观测结果与「包含块不得落在会被裁的祖先里」这条结构性前提。
- 判据的落点：真机行为层由 `scripts/acceptance` 的 `geom` 断言承担（几何 + 绘制两段，
  见其 [README](../../scripts/acceptance/README.md) §断言）；chromium 视觉层的
  `toBeVisible` 类断言**不算覆盖** O1（它不查祖先裁切），需要时另加包围盒包含断言。
