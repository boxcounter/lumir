# 渲染/交互缺陷的合同先行规则

渲染/交互类缺陷修复（live preview 装饰、CSS 布局、光标/选区/键盘/滚动行为）禁止只做案例级补丁。本规则源于 M98–M110 的表格宽度补丁史：四个 mission 各修一处（拉满主栏 → 贴合内容 → 固定像素封顶），缺陷仍以新形态再现（M119 的欠宽折行与超宽裁切）——根因是缺少可证伪的不变量合同，每个补丁只针对报告中的那一个案例。

## 规则

一个渲染/交互缺陷修复合入前必须完成三步，缺一不可：

1. **定位合同条款**：指出缺陷违反了哪一份质量合同（docs/specs/）的哪一条；该条款必须是可被测试证伪的不变量表述。
2. **合同缺条款时先补条款**：把缺失的行为写成不变量——「任意满足条件 X 的输入，行为 Y 恒成立」——并更新对应 spec 文档。条款引用输入分布（列数、内容长度、栏宽），不引用具体案例（「这张表」「那个文件」）。
3. **配不变量级的属性测试**：fixture 由生成器扫相关输入维度（如 列数 × 内容长度 分布），断言不变量本身。复现用户报告的单一案例的回归测试可以保留，但不得单独存在——它只证明那个案例被修好，不证明同类缺陷被根除。

## 反例与正例

- 反例：为「宽表溢出」加一条固定 `max-width` 上限——欠宽折行缺陷（栏宽未用尽时强行折行）必然以新形态再现。
- 正例：表格宽度统一合同（[docs/specs/table-reading.md](../specs/table-reading.md) §3 的 M119 条款）+ 属性测试（tests/visual/scenes/m119-table-width.spec.ts 的 fixture 矩阵断言：折行/总宽/横滚/零裁切不变量在列数 × 内容长度分布上恒成立）。

## 适用范围

- 适用：live preview 装饰层、CSS 布局、编辑器交互（光标、选区、键盘、滚动）的缺陷修复与新行为。
- 不适用：行为不变的纯重构、Rust 后端逻辑（走现有合同/测试约定）、文案与主题 token 微调。

## 评审节点

- Alex 介入点：新增或修订的合同条款（不变量表述）本身，与既有 spec 变更同口径评审；实现与属性测试由 review 门禁覆盖。
- 通过标准：条款是不变量表述且被属性测试钉死；无对应条款的渲染/交互缺陷修复不得合入。
