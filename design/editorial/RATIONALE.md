# 编辑部 Editorial — 设计说明（RATIONALE）

> 本文件供裁决用：不看代码，凭本文 + 浏览器走查 `design/editorial/index.html` 判断。
> 走查台 URL 参数直达任意状态组合，例：`?nav=a&theme=eink&state=review&lang=zh&measure=480&annotate=on`（`nav=a|b|c` 切换左栏结构变体，`lens=threads` 直达 b 变体的 Threads 视角）。

## 一、命题

**排印即界面。** 界面没有"壳"：窗口即一个版面，报头一线、目录一栏，其余全部退入页边。Lumir 的协作对象（编辑点、委派、回看、冲突）不做成面板与弹层的堆叠，而是排印系统里的注记——活在页边、与正文同视野、resolve 即消失。

签名时刻：**一页你愿意打印装裱的中文排版 + 页边注记系统**。前者证明排印工程，后者证明 agent 协作可以长在排印秩序里而不是长在 chrome 里。

锋利度自检：这不是"又一个衬线主题"。正文是黑体（硬约束），衬线只出现在展示面；命题的力度全部来自排印参数、空间秩序与注记生命周期，不来自字体皮肤。

## 二、参照谱系

- **Tufte**：sidenote 优于 footnote——注记在视野余光内，不打断阅读；本设计把编辑点、解释、diff、裁决全部做成页边注记，按锚点纵向对齐。
- **报刊版面传统（大标宋 + 黑体正文）**：标题宋、正文黑是杂志而非书的惯例，宋黑对比天然承担层级；校对红 = 编辑手里的红铅笔，是唯一强调色。
- **瑞士国际主义排印**：层级只靠留白与字重，网格产生秩序；目录与报头零装饰，只有字距与 hairline。
- **iA Writer / CLReq**：行宽、行高、缩进的量化默认值来源；行宽开放为滑块（iA 64/72/80 的"少而精可调"哲学的连续版）。
- **calmtech（Amber Case）**：状态沟通分级谱——锚点 = Status Light（余光级），页边注记 = tone，冲突 = popup（只给不可静默处理的事）。

## 三、关键决策与数值依据

### 排印层（签名页）

### 展示面字体论证（标题 = Songti SC）

正文黑体已定死，标题是自由变量。选宋体的理由：

1. **报刊传统**：中文报纸、杂志的标准版面就是"标题宋（大标宋）+ 正文黑"。本方向叫"编辑部"，标题宋体是这套隐喻的本体，不是装饰。
2. **层级经济学**：宋/黑的字体类别对比让标题在 1.12–1.78em 的小字号差下依然清晰，不需要靠字号堆砌层级——符合瑞士网格"层级靠留白与字重（此处扩展为字体类别）"的纪律。
3. **零成本**：Songti SC 是系统字体，不触碰"不依赖外部字体文件"红线；英文走 `ui-serif/Georgia`，同栈切换。
4. **反证**：若标题也用黑体加粗，整个方向退化为"排版较好的工具软件"，命题锋利度丢失；若正文宋体（v1/v2 的路），则违反硬约束且低分屏发虚。

### 协作层（对象 → 排印原语）

| 时刻 | 空间策略 | 形态 |
|---|---|---|
| 创建 | 浮层（瞬态、贴选区、说完即走） | 引用 + 自然语言意图输入，回车即成 |
| 在场 | 正文内安静锚点（calmtech light 级） | 虚线下划线 + 朱红圈码 ①②③ |
| 积累 | 页边注记（Tufte sidenote） | 编号 + 你的问题，与锚点纵向对齐 |
| 委派 | 居中卡片（用户主动发起） | 授权范围全文写出（ADR 0005 §5：授权边界由委派声明决定） |
| 工作中 | 注记原地升级 | 进度细条动画；eink 为静态斜纹条 |
| 回看 | 注记逐点展开，解释优先 | 焦点点完整展开（你的问题 → 解释 → 词级内联 diff → 影响与代价 → 跳到正文；动词仅 **接受 / 拒绝**），其余折叠为单行卡，点击可提前展开；裁决后焦点自动递进到下一点 |
| 归档 | 消失 | 注记淡出、锚点消解；文尾跋文「本次修订 2 处 · 编辑点已归档 · 正文即事实」 |
| 冲突 | popup（唯一弹窗态） | 版本变化即暂停、不静默覆盖；重新处理 / 查看差异 / 保留外部修改 |

词级内联 diff：中文按短语粒度（CJK 无空格分词），删除 = 灰字划线，插入 = 朱红下划线——编辑红笔的传统语义，避免 Cursor 式满幅红绿。预设点覆盖两类结局：ep1（核验）只解释不改正文（ADR 0005「Agent 可明确表达不确定性并选择不修改」），ep2/ep3（压缩/改调）产生修改。

回看逐点展开的取舍：折叠层（单行卡）始终贴锚点纵向对齐，保持页边的空间索引；展开卡是瞬态——展开瞬间（≈450px）会把其后折叠行推离锚点（ep2 最大位移 271px），裁决后版位立即回落对齐。备选是把解释 clamp 到 3–4 行压小展开卡，但会牺牲「解释优先」的完整阅读，未采用；若观感仍嫌挤，这是第一个可调旋钮。

### 导航重构（M51：目录 × Threads 同栏）

Alex 硬输入：「左栏是极致美的目录结构和 Threads，默认显示目录结构」。此前「Thread 索引取代文件树」的做法被否决——它对 ADR 0005 的忠诚是以撒谎为代价的：文件在磁盘上有真实的目录归属（事实空间），只按 Thread 角色呈现等于宣称目录不存在。新左栏让两个空间同栏共存、各自说真话：**文件属于 workspace（目录树），角色属于 Thread（引用列表）**。同一文件可被多 Thread 引用——demo 数据里「把卡顿变成正文.md」在 Thread A 是主文档、在 Thread B 是来源，两处呈现互不矛盾（ADR 0005 §2：Thread 不拥有文件，角色只属于当前 Thread）。

#### 目录树工艺（Alex 树的裁决逐条落实）

- **层级 = 缩进节奏 + 字重 + 明度**：缩进 13px/级、caret 占固定 15px 槽位保证行间对齐；目录 600 / 文件 400 字重；文件名明度按深度向栏底色 96/91/86/81% 调和（`color-mix`，亮暗主题同构）。禁止字号倒挂——目录与文件统一 13px。
- **行高 27px** 给足呼吸；**选中态克制**：¶ + 2px 朱红左边线 + 600 字重，无填充色块（¶ 沿用校对页边符语义）。
- hover 淡底（eink 改下划线）、focus-visible 描边；长名省略号截断 + `title` 全路径；深层嵌套（demo 至 4 级）缩进节奏不塌；目录可折叠（caret 旋转，eink 无动画）。
- **eink 禁灰阶**：明度通道失效，层级只靠缩进 + 字重承担；选中走双线框，与注记系统「待裁决 / 选中」的图案语义一致。

#### 三个结构变体（`?nav=a|b|c`，默认 a）

| 变体 | 结构 | 优点 | 代价 |
|---|---|---|---|
| **a 分区式（默认）** | 目录为主区在上，Threads 为栏内独立分区在下 | 两空间同屏共存、无需模式切换；目录优先满足「默认目录」；Thread 卡完整承载 §7 信息量 | 栏纵向空间紧张时 Threads 区需滚动 |
| **b 视角式** | 栏顶 lens tab：目录 ｜ Threads（快捷键 1/2），默认目录 | 单视角专注，每个视角可用全栏高度 | 两空间互不可见，切换有记忆成本；「当前文件在哪个 Thread」要切一次才知道 |
| **c 叠加式** | 目录为基座；当前 Thread 节记浮于栏顶，其关联文件在目录中带角色标记（主文档/参考/草稿/来源），多 Thread 引用给 ×n 计数 | 事实空间唯一、引用关系原地可见，最诚实；一栏装下全部 | 角色标记挤占文件名宽度、加剧长名截断；非当前 Thread 的关联不可见 |

三个变体中 Threads 均承载 §7 的信息量：标题、状态（进行中 / 暂停 / 完成；冲突态当前 Thread 显示暂停）、开放编辑点数、待回看数。当前 Thread 的计数由运行态编辑点实时推导（走查台切状态可见变化）。**当前 Thread（朱红计数 / 卡片 / 节记）与当前文件（¶ + 边线）在两个空间各自可辨、互相印证。**

#### 推荐：a 分区式为默认

1. 硬输入是「目录结构和 Threads」的并列共存——b 把 Threads 藏进切换，c 把 Threads 压成标记，只有 a 让两者同时是一等公民。
2. a 的撒谎成本最低：目录说事实、Thread 卡说意图，互不僭越。
3. c 的叠加思想（目录行内引用标记）可作为 a 的后续增强合入；b 的 lens 可作为窄屏降级形态。

此为设计建议，最终取舍留 Alex 裁决——走查台「导航」维度可现场切换对比（URL 参数 `?nav=` 直达）。

### 右栏 = Context Surface

默认不存在（无栏、无框、无占位）。第一个编辑点出现时注记列才随状态出现；全部归档后整列消失。版位稳定策略：正文在 `#spread` 内恒定居中（`width:min(var(--measure),100%); margin:0 auto`），注记列以绝对定位叠加在正文右侧（不挤占文档流），clean 态与 points 态正文左缘位移为 0——注记来去不推动版面。

### eink 主题

纯黑 #000 / 纯白 #fff，禁灰阶（`--dim` 也是纯黑，弱化一律走斜体）；无阴影、无透明、无动画（全局 `!important` 封杀）；状态区分走图案：斜纹 = 进行中，双线框 = 待回看 / 当前选中；主按钮黑底反白。控制台附「灰度检查」开关（grayscale 滤镜），验证纯黑白在灰度下零信息损失。

## 四、取舍清单（有意为之的放弃）

1. **放弃编辑态/预览态分离**。demo 只呈现预览态精排（悬挂、autospace）；编辑态应保持网格对齐保光标可预测，这是实现期决策，demo 不演示。
2. **行宽滑块允许超过 CLReq 上限**（1200px ≈ 75 字）。控制台读数实时显示「约 N 字/行」，把判断留给用户；大屏双栏阅读场景存在，不做硬夹断。
3. **注记拥挤时顺延而非重叠**。锚点过密时注记向下顺排，牺牲严格对齐保可读（Tufte 手工版面会做同样的事）。
4. **首字下沉只用在一处**（文章起首）。每节都下沉就成了杂志内页而非编辑工作台，克制是签名的一部分。
5. **demo 创建跨段落选区拒绝服务**（toast 说明）。真实实现需要跨段锚点，demo 用单段落 extractContents 保真实可交互。
6. **live 创建的编辑点无预设解释/diff**，回看时以演示注记明示「未接入真实 Agent」——不伪造协作状态（呼应 ADR 0005 外部 Agent 不伪造批次的底线）。
7. **委派条固定在注记列顶端**而非跟随最后一枚注记——动作 affordance 必须永远可见，位置稳定比"贴着内容"重要。
8. **暗色主题不做纯黑**：#1a1917 暖黑 + 正文亮度压一档，避免 OLED 式刺眼对比（iA：深灰优于纯黑白）。
9. **窄视口（≤1100px）页边栏降级为文后附注**而非 display:none——编辑点信息不可因视口丢失，Tufte 的脚注传统在这里兜底：注记列转静态文档流、落在正文末尾，委派条随之。
10. **朱红同时承担装饰与信号（待 Alex 裁决）**。当前朱红 = 校对红，一身二任：装饰位（kicker、首字下沉、h2 序号）与信号位（锚点圈码、插入 diff、主按钮）。张力在于装饰稀释信号纯度；备选「朱红只留 actionable，装饰位改墨色」会让版面更纪律但丢失报刊传统里红题/红起首的修辞。不改设计，留作裁决点。
11. **冲突弹层「保留外部修改」落回干净正文态**而非归档跋文——外部修改不是本次修订的产物，正文保持外部版本、编辑点清空，无「本次修订 N 处」的虚报。
