## 关键设计决策（第二轮）

1. **骨架修正：标签在标题栏里面，与真实产品同构。** 第一版把标签条画成标题栏下、每个 pane 上缘的独立一栏——Alex 指出实际产品的标签在标题栏里（M149 起就是如此：`.titlebar` = traffic 空位 + `.tabstrip` + 动作钮 + 产品标识；双 pane 时 pane B 的标签段由装配层现建、插在 pane A 标签段之后，同一条标题栏内，见 `src/shell.ts` / `src/main.ts:286`）。本轮全部屏改为该结构：pane 内不再有标签行，标签段样式直接镜像 `src/style.css` 的 `.tabstrip` / `.tab`。
2. **去蓝色强调色（Alex 裁决）。** accent 族改中性灰阶；第一版的「活跃 pane 标签条上缘 2px accent 线」随之取消（它本来就是待裁决的新增元素，去蓝后没有合适载体，不另造中性形态硬留）。wikilink 失去颜色信道后补下划线作第二信道。pending（用量警示）/ ok（完成勾、已复制）语义色保留——Alex 只否了蓝色强调色，语义色不动。
3. **harness 默认宽度：harness:pane#1 = 1:2（Alex 裁决），取代第一版的 400px 建议值。** flex grow 2:1 实现，1280 视口下 harness ≈346px；分隔条拖动态（屏 3）不受影响。被推翻的 400px 建议值如实记录：第一版决策 3 废止。
4. **多 pin 流程（Alex 需求）：pin 多条引用、各配各的问题、一次发出。** pin 卡片在 composer 上方排队，每张卡片 = 图钉 + 文档名 + 标题锚点 + 摘录 + **该引用自带的问题**（左边线次级行）；hint 行报数「2 条引用随下一条消息一次发出」。发送后沉淀为一条用户消息：多个附件条与各问题交替排列，agent 分问作答（屏 5）。这回答了「一次 pin 多个」的队列形态与发送语义——一次发送 = 一条消息携带全部 pin。
5. **agent 进度：不定态 + 阶段指示，无百分比（tower 已答 Alex：token 数与工具轮数运行时才定，总量事先不可知，百分比进度条技术上是假的）。** 第一版的 58% 细进度条废止；改为「阶段名（思考中 → 调用工具 → 生成中）+ 已进行秒数 + 不定态滑动条」（屏 4 摆拍「调用工具中」）。
6. **上下文用量：常驻警示句移除（Alex 裁决：一直显示很抢注意力）。** 高用量态 = 黄色高亮百分比（既有）+ 尾部小 info 钮；点击/悬停才展开说明气泡（原那句「继续对话将触发压缩，细节可能丢失」+ 就地「新建会话」出口，泄压动作不丢）。屏 6 摆拍气泡展开态。第一版的头部下警示条（`.h-warn`）整条废止。
7. **思考程度菜单：三个裸档位（Alex 裁决：无需解释每档含义）。** 低/中/高 + 当前打勾；第一版的每档释义、档标签（最快/默认/慢·用量高）、底部脚注全部移除。
8. **处理中的发送钮 = 进行中态，点击停止（Alex 建议）。** 工作中（屏 4）发送钮换停止 glyph + 脉冲环，title/读屏名改「停止当前回合」；其余屏保持发送箭头。
9. **原型控制面板（Alex 纪律：手改 URL 不方便，要创世者控制面板）。** 右下角常驻 pill（显示当前屏与主题），点击展开画面网格（10 屏）+ 主题行（3 档），点击即切；`?screen/?theme` 深链照旧；截图脚本用 `?panel=0` 关闭面板保持画面干净。
10. **fixture 全合成（Alex 纪律）。** 第一版原型与截图含真实 vault 内容（同事姓名、真实项目目录名、真实文档），本轮全部替换为合成 vault（Fieldnotes / reading-workflow.md 等）并重截 30 张；纪律已沉淀进 AGENTS.md 硬规则与 REVIEW.md 第 17 条。

## 沿用的第一轮决策（未被动摇）

- 消息流 document 式平铺（无气泡、无头像）；用户消息描边卡片、agent 消息平铺。
- 工具调用完成即折叠为一行摘要，可展开回看。
- 模型选择放 composer 控制行（per-turn 决策离输入最近）。
- 新建会话两个入口一个语义（头部常驻 ＋新会话 + 会话名下拉底部）。
- 复制消息 hover 浮现、反馈就地将息。
- 思考过程折叠为默认、展开是次级阅读（左边线 + 次级灰）。
- pin 的编辑器侧形态（左边线 + tint 底 + 行尾小图钉，hover 浮现图钉钮）。

## 六条原则对照

- **内容即界面**：屏 1 正文占比与现行产品持平；harness 在场时正文仍是主 pane（2/3 宽）。
- **chrome 退后但不粗糙**：新增控件（pin 钮、复制钮、chip、浮层、info 钮、控制面板）全部有 hover/focus/过渡；常驻警示句移除后 chrome 更少。
- **质感来自工艺**：除 accent 族中性化外零新色值、零渐变；圆角/字号/间距走既有 token 阶梯。
- **色彩克制且语义化**：去蓝后彩色只剩 pending（用量警示）+ ok（完成勾、已复制）；eink 全转明度/线宽/字重。
- **agent 可开可关**：屏 1-3 零 agent 痕迹（只留标题栏一颗 toggle 钮）。
- **对话是输入不是档案**：工具过程完成即折叠；pin 是待发上下文不是消息装饰；agent 产出仍归提案队列（本原型不重设计，对话里只留一句指引）。

## 已知妥协点（诚实清单）

1. **红绿灯 / 窗口 chrome 是画在页面里的**（真实产品由系统绘制，且真实产品刻意不自绘），原型为自包含截图保留。
2. **屏 3 的拖拽态、屏 4 的工作态、屏 6 的说明气泡是静态摆拍**，没有真拖拽/真流式；分隔条 hit area（5px）与抓柄形态供评审，手感归实现期。
3. **会话列表条目、pin 内容、文档正文是合成 fixture**；「⌘⇧N」「⌘⇧A」键位是本原型建议，未经裁决。
4. **harness 1:2 默认比是 Alex 裁决值**；拖拽后的宽度回写路径（`config_set_ui_value`，ADR 0008 D2）不变。
5. **accent 族中性灰阶是本原型建议值**，与现行 `src/style.css` 的蓝色 token 有出入——实现期改 token 是全局视觉变更，需走对应 change 流程；dark 下 accent-fill 反转为浅底深字，发送钮观感变化最大， Alex 过目时重点看屏 4/8 深色。
6. **屏 6 说明气泡摆拍为展开态会遮一点 transcript 首条消息**——气泡是瞬态覆盖层，真机 hover/点击才出现，非常驻遮挡。
7. **dark / eink 全屏验证过不破版、对比达标，像素级细节没有逐一推敲**。
8. **提案队列不在本原型范围**；屏 6/8 对话里「请在提案队列裁决」只是文案占位，队列形态沿用现状。
9. **「活跃编辑器 pane」暂无可见对应物**（第一版的 2px accent 线随去蓝取消，未另造中性形态）——ADR 0008 D3 的 selected window 语义在实现期需要一个可见表达，留作开放问题。
