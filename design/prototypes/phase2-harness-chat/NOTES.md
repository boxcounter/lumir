文件：`index.html`（自包含，无外部资源）。切换方式：`?screen=1..10`、`?theme=light|dark|eink`。
目标视口 1280×900，十屏 × 三主题共 30 张截图（`shots/`，1280×900 @2x），逐一目检无破版。
依据：ADR 0008 Decision 8（Phase 2 范围）+ Alex 2026-10-05 追加裁决（上下文使用百分比 / 新建会话 / 复制消息 / 思考过程呈现 / 思考程度选择）。设计准绳 docs/specs/design-brief-v1.md。

## 关键设计决策

1. **骨架：标签随 pane，标题栏瘦身。** dock 列移除后，标签条从全局标题栏下沉到每个 pane 上缘（ADR 0008 D1「每个 pane 承载一组文档标签」的自然推论）；标题栏只剩 traffic 空位、拖拽区、harness toggle（✦ 钮，⌘⇧A）、产品标识。单 pane 默认态（屏 1）因此与现行产品的差别一眼可读：右栏 dock 没了，标签搬家了。
2. **活跃编辑器 pane 有可见对应物。** 「最近活跃的编辑器 pane」（ADR 0008 D3，Emacs selected window 语义）原本是纯逻辑概念——焦点在 harness 里时用户无从得知命令与上下文落在哪个 pane。原型给它一个低成本可见标记：活跃 pane 的标签条上缘 2px accent 线。这是本原型新增的唯一骨架层元素，供 Alex 裁决要不要。
3. **⌘⇧A 自动分栏的比例：编辑器弹性 + harness 400px 起。** 对话是 rail 不是对等文档，等宽 split 浪费正文宽度；harness 以 400px 起步（比现 dock 348px 宽，回应「默认过窄」反馈），分隔条可拖（宽度经 `config_set_ui_value` 回写，ADR 0008 D2 已裁决此路）。
4. **消息流：document 式平铺，不是气泡。** 沿用方向 A 与现行 harness 的无气泡路线（brief 原则 5「不是聊天气泡」）：署名行（你 / Agent + 相对时间）+ 平铺正文。用户消息保留现行描边卡片形态——发出的指令是「我说过什么」的实体，扫读时与 agent 叙述可区分；agent 消息完全平铺，markdown 直排。
5. **工具调用进度：内联在 agent 回合内，完成即折叠。** 工作中 = 紧凑步骤行（24px：灰勾 = 完成、脉冲点 = 当前、空心圈 = 待办）+ 底部「已进行 N 秒 + 细进度条」；该回合结束后整个块折叠成一行「▸ 4 个工具调用 · 全部完成」，可展开回看。依据 brief 原则 6：过程是 narration，不是档案——默认不占垂直空间。
6. **模型选择放 composer 控制行，不放 pane 头部。** 头部放会话身份（会话名 + 切换）；模型是 per-turn 决策，离输入最近——与思考程度 chip、发送钮组成「本回合怎么跑」控制行。这也避开了「harness 缺模型选择」反馈里最重的形态（全局设置），先给最轻的就地切换。
7. **上下文使用百分比：头部常态 mono 读数 + 阈值警示条。** 常态 = 头部右对齐 `ctx 62%`（mono tabular-nums，数字变化不抖动，沿用现行 `.lumir-hp-usage` 形态）；≥80% 读数转 pending 色 + 头部下方出警示条「继续对话将触发压缩」+ 就地「新建会话」出口——警示与泄压动作同屏，不让用户自己想办法。
8. **新建会话：两个入口，一个语义。** 头部常驻「＋ 新会话」文本钮（现行已有）；会话名本身是下拉，列出最近会话（当前打勾）+ 底部「新建会话 ⌘⇧N」。会话切换与新建收在同一块语义区（头部左侧 = 会话身份），不与 composer 控制行（本回合怎么跑）混淆。
9. **复制消息：hover 浮现，反馈就地将息。** hover 消息时 who 行右侧浮现复制图标钮（不遮蔽正文、不常驻占位）；点击后原位置变「✓ 已复制」短暂停留后消隐。不做消息级动作栏（多个图标排一排）——那是 IDE 密度，brief 反例。
10. **思考过程：折叠为默认，展开是次级阅读。** 折叠态 = 一行 meta「▸ 思考过程 · 12 秒」；展开态 = 左边线 + meta 字号次级灰正文，与正式回答的字级拉开一档。思考是「可审计的过程」不是「交付物」，视觉层级必须低于回答本体；耗时读数让「思考程度」选择可感知（屏 10 的因果闭环）。
11. **思考程度：三档 chip，说明写清代价。** composer 控制行「思考：中 ▾」→ 浮层三档（低 = 直答最快 / 中 = 默认平衡 / 高 = 深度推理慢且用量高），每档一句适用场景，底部一行「作用于下一条消息；高档显著增加上下文用量」——把档位与上下文百分比（决策 7）显式挂钩，用户能理解用量从哪里来。
12. **pin 上下文：编辑器段落 ↔ composer 卡片的双向可见。** 编辑器侧：段落 hover 浮现图钉钮，pinned 段落 = accent 左边线 + tint 底 + 行尾小图钉（eink 转纯黑左边线，tint 退场）；harness 侧：pin 块堆叠在 composer 上方（待发上下文），卡片 = 图钉 + 文档名（mono）+ 所属标题锚点 + 段落首行摘录 + 移除 ×，顶部一行 hint「钉自活跃编辑器 pane · 随下一条消息发送」——回答「钉的是哪个文档」（ADR 0008：由最近活跃编辑器 pane 回答）并把「何时生效」说清。发送后 pin 块沉淀为用户消息顶部的附件条（`.att-pin`），对话可回看当时钉了什么。

## 六条原则对照

- **内容即界面**：屏 1 正文占比与现行产品持平；harness 在场时正文仍是主 pane（弹性宽 vs 400px rail）。
- **chrome 退后但不粗糙**：新增控件（pin 钮、复制钮、chip、浮层）全部有 hover/focus/过渡；复制与 pin 钮默认不浮现，hover 才出现。
- **质感来自工艺**：零新色值、零渐变；所有圆角 / 字号 / 间距走既有 token 阶梯。
- **色彩克制且语义化**：彩色只有 accent（活跃 pane 线、pinned 段落、运行中脉冲、当前会话/档位打勾）+ pending（用量警示）+ ok（工具完成勾、已复制）；eink 全转明度/线宽/字重。
- **agent 可开可关**：屏 1-3 零 agent 痕迹（只留标题栏一颗 toggle 钮）。
- **对话是输入不是档案**：工具过程完成即折叠；pin 是待发上下文不是消息装饰；agent 产出仍归提案队列（本原型不重设计，对话里只留一句指引）。

## 已知妥协点（诚实清单）

1. **红绿灯 / 窗口 chrome 是画在页面里的**（同方向 A 妥协 1），真机交系统。
2. **屏 3 的拖拽态是静态摆拍**（accent 线 + 抓柄），没有真拖拽；分隔条 hit area（5px）与抓柄形态供评审，手感归实现期。
3. **会话列表 / 思考程度浮层的条目是虚构的**，命名沿用 vault 惯例；「⌘⇧N」键位是本原型建议，未经裁决。
4. **harness 400px 起步宽是本原型建议值**，不是裁决；等宽 split 作为对照已在屏 2 可见。
5. **dark / eink 全屏验证过不破版、对比达标，但像素级细节（如 dark 下 pinned 段落 tint 的和谐度）没有逐一推敲**（同方向 A 妥协 5）。
6. **提案队列不在本原型范围**（Phase 2 只重做 chat UX 与容器）；屏 6/8 对话里「请在提案队列裁决」只是文案占位，队列形态沿用现状。
7. **「活跃 pane」2px accent 线是新增视觉元素**，与现行产品的克制口径有张力——这是刻意提出的裁决点，不要默认它已被接受。
