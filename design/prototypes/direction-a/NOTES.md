# 方向 A「器物」原型 — 设计说明

文件：`index.html`（自包含，无外部资源）。切换方式：`?screen=1|2|3`、`?theme=light|dark|eink`。
目标视口 1280×900，三主题 × 三屏共 9 种组合均已在 Chromium 1280×900 下截图验证无破版、无滚动条穿帮。

## 关键设计决策

1. **调色板：暖灰 + 单一靛蓝。** chrome 区 `#f2f1ee`、内容区 `#fbfbfa`，刻意与旧 editorial 的米色纸底拉开距离——暖灰偏中性，不偏黄。全界面只有一个强调色（靛蓝 `#5563c1`），仅出现在 wikilink、主按钮、进行中状态、Agent 按钮激活态四处。diff 的绿/红是语义色，不算装饰色。
2. **正文排版承担质感。** 阅读列宽 660px，正文 16px / 1.75，标题 27px  Bold 无衬线（方向 A 取无衬线分叉）。有序列表用 tabular-nums 数字、悬挂缩进；嵌套列表降级为空心方点 + 次级灰。wikilink 不着色块、不加图标，只着色 + hover 底色——含蓄但与正文可区分。
3. **chrome 三件套：侧栏 / 标签 / 状态栏全部低调。** 文件树无文件图标，只有 disclosure 三角；选中态 = 中性灰底 + 字重 550，不用强调色。标签是 pill 式，激活标签与内容区同色相接。状态栏 11.5px 三级灰，只放路径与光标位置。
4. **Agent pane：裁决对象在上、对话在下。** 严格按 brief 原则 6：提案是一等对象，排队在 pane 上半；对话平铺行（无气泡、无头像），只做输入与 narration。pane 宽 376px，从右侧 220ms ease 滑入，屏 1 完全无痕迹（只留工具栏一个召唤按钮）。
5. **提案卡的信息层级：类型 chip → 文件名（mono）→ 一句摘要 → 证据（预览 / diff）→ 操作。** 证据区是卡片的核心：新建给内容预览（带「预览 2 / 28 行」的诚实标注），修改给行内 diff（带「+2 −1 · 其余 60 行不变」的安心信息）。每张卡可单独批准 / 驳回 / 修改意见，队列头部有「全部批准 / 全部驳回」批量操作。第三张卡用紧凑形态，演示队列的密度弹性。
6. **工作态（屏 2）不打扰正文。** 活动流用紧凑行（27px 行高）：完成 = 灰勾、当前 = 脉冲点、待办 = 空心圈，底部一行「已进行 12 秒 + 细进度条」。提案队列位置先放空态文案（「工作完成后，提案将出现在这里」），让用户预期提案的出现位置——屏 2 到屏 3 的 pane 结构不变，只是空态被卡片替换。

## 六条原则对照

- **内容即界面**：屏 1 约 80% 面积是正文排版；质感全在字距、行高、列表缩进纪律上，无插画无装饰。
- **chrome 退后但不粗糙**：出现的每个控件（搜索框、标签、树行、按钮）都有完整 hover / focus（focus 环 = 3px accent-soft）/ 过渡（100–150ms），无一裸奔。
- **质感来自工艺**：无渐变、无阴影卡片（卡片只有 1px 边 + `0 1px 2px` 极轻投影）、圆角统一 6–10px 阶梯。
- **色彩克制且语义化**：彩色只有靛蓝 accent + diff 绿/红 + 状态点；eink 主题零彩色，diff 用删除线 / 加粗替代色相，wikilink 改用下划线。
- **agent 可开可关**：屏 1 零 agent 痕迹；pane 结构取 Zed 的克制（分区、紧凑行），表面质感走 Things（圆角、留白、柔色）。
- **对话是输入不是档案**：agent 的产出全部沉淀为提案卡（可排队、可批量）；对话区只有指令与 narration，不承担任何待办。

## 主题策略

三主题共享同一套 token 与结构，只换变量值（印证 brief「对比度分档」假设）：light 暖灰柔和、dark 暖黑（`#1a1917` / `#201f1d`，accent 提亮为 `#93a0e6`）、eink 纯黑白灰（选中态反转为黑底白字，红绿灯描边，阴影清零）。

## 已知妥协点（诚实清单）

1. **红绿灯是画在页面里的。** 静态 HTML 没有真窗口 chrome，三颗圆点是为了截图时读得出「macOS app」；真机里应交给系统。
2. **屏 2 对话区底部仍有约 180px 空白。** 聊天表面的固有形态（输入框锚底），已用一条 agent 进展消息缓解，但没有为了填满而虚构更多对话。
3. **正文是「策展过的真实内容」。** 原文 63 行里 `# 碎片` 等结构瑕疵没有照单全收——为让首屏排版成立，选取了 AI Coding 段与研发部视角段，文字基本原样，但顺序与删节经过编辑。两个 pilot 的表述在提案卡摘要里有轻微改写。
4. **状态栏「第 1 行，第 1 列」「约 1,200 字」是估值**，非精确统计；提案卡里的 `2026-04 和忠旺.md`、`2026-02 和国杰.md` 两个文件名是按 vault 命名惯例虚构的（vault 里 1:1 笔记在 Archives，未逐一核对真实文件名）。
5. **dark / eink 只打磨了屏 1。** 屏 2、3 在这两个主题下验证过不破版、对比达标，但细节（如 dark 下 diff 底色的和谐度）没有逐像素推敲。
6. **动效只有 CSS 过渡（pane 滑入、脉冲点、hover），没有演示「提案从对话长出来」的动线**——panel 派的结构性答案，留给裁决后细化。
