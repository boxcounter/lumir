思路：不是学工具，而是改进工作方式

AI Coding 的基建、工作流规范

  1. 基建、流程、规范
    1. .claude: Context engineering
    2. PR：template-based auto generated, first-pass review, code review Skills；Author self-review, Reviewer
    3. 设计规范；Spec：业务逻辑、服务间或模块间的接口（如 gRPC 和 RESTful）
    4. 和 AI 的合作：讨论 / 头脑风暴、发现、拆解成 AI 擅长的大小
    5. Review (Plan + Code) > Coding
      1. 从自动补全、我来设计结构、我来决定用什么设计模式 → Review over Coding
      2. 重点是 Review：除了 Agent 的 Plan 和 Code 的质量，还需要探究为什么 Agent 没有达到我的预期——是缺少什么业务上下文吗？是缺少背景吗？
  2. 技能：Code Review、Agent（Hook）、Task decomposition、TDD?
  3. pilot：忠旺——重写 API；华南——Slax Reader
  4. 测试：AI driven 自动化测试（computer-use?）

从研发部的视角出发的 Tech Vision

  • 对各职能端的期望——从各端的年终总结中收集信息。
  • PR：AI 编写描述让 reviewer 快速了解概要；AI 做初审，降低 reviewer 的心智负担。
  • 对忠旺——2026-01 和忠旺：全局统筹和主动同步。蹚出一条 AI Coding 的道，比如后端的服务迁移（PHP → Golang）。
  • 后端组的基建 → 公司的基建（如 AI Agents）。也许可以鼓励华南来做。

维度 2：Mode（工作模态）

值定义判断标准
Deep Work单人、专注、认知负荷高需要持续注意力；产出理解、决策或设计
Communication实时同步互动有对方参与的双向实时交流
Ops单人、例行、认知负荷低有明确的步骤/流程；不需要深度思考

一个测试：做这件事时，如果被打断 2 分钟，需要多久才能恢复原状态？

录入流程

  1. Goal 可选优先——在推进月度承诺就先锚定 Goal，否则跳过直接往下
    1. Goal 留空时，该 Entry 不计入 Commitment Spent
  2. Mode 其次——模态判断最简单，身体感受直接告诉你
  • 历史数据不迁移——由 agent 按 差距盘点-既有埋点 的映射双源处理
  • 设计细节见 实施设计-v1
