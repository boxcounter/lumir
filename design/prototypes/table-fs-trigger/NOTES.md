## 三轴的取舍（每轴一段，组合意图 = 三段直积）

**位置**

- `inside` 右上角内侧叠放：压在表格可视区右上角。语义最准——「它作用在这张表上」不靠位置猜；
  绝对定位叠放，文档几何零变化。代价是叠在首行末格之上，宽表末列表头会被短暂遮挡
  （hover 才出现的时机下遮挡只发生在 hover 期间，移开即还）。
- `outside` 表格外右上：钉在表格右上、664 栏宽之外的沟槽。不碰表格一根线，最干净。
  代价：它依赖栏宽两侧留白**存在**——窗口收窄、或未来正文栏布局变化时沟槽消失就无处安放；
  且视觉上是一个「游离的 chrome」，与表格的归属关系要靠对齐暗示。
- `top` 上缘中央：骑在表格上缘正中。findability 最高（视线扫表格上沿必经）。
  代价：居中于容器而非表格内容，宽表横滚时它的位置与「表的右端」无关；
  三档里最重——像一枚钉在内容上的横幅，与「chrome 退后」张力最大。

**图标**

- `expand` 对角 expand 箭头：两条沿对角线向外的箭头，「放大/展开」语义。
  风险：带方向性，单条对角箭头是「外部打开（open in new）」的通行字形，两条外向箭头仍可能被读成
  「拖大窗口」或「去别处打开」——而实际行为是就地模态层，哪都不去。
- `corners` 四角框：四个角括号，macOS 与视频播放器的 fullscreen 通行字形，无方向性，
  「全屏查看」语义无歧义，与「打开的是一个模态层、不是新去处」一致。

**出现时机**

- `hover` hover 表格容器才出现：静止态零足迹——不出现、不占位、不进任何整页基线
  （对 REVIEW.md 第 3 条的基线纪律最友好：含表格的静止帧逐字节不变）。代价：可发现性全靠动作偶遇，
  纯键盘用户看不到它（但键盘路径本来由 `table.toggle-fullscreen` 命令承担，两入口分工正好）。
- `dim` 常驻淡态：rest 态 opacity 0.5 常驻，hover 升全值（board 里可真实体验）。
  可发现性最高。代价：每张表多一个常驻噪点，且**会出现在所有含表格的整页基线里**——
  这正是提案原文点名的裁决理由（「会出现在所有含表格的整页基线里」），选它意味着一批基线重拍。

## 推荐档：`inside-corners-hover`

- 位置取 `inside`：宽表触发钮必须钉在**横滚容器的可视区**而非内容（内容会滚走），
  `inside` 是唯一天然落在容器坐标系里的方案；`outside` 依赖会消失的沟槽，`top` 与内容无关且最重。
- 图标取 `corners`：全屏语义无歧义、无方向性；`expand` 的「外部打开」误读风险不值得冒。
- 时机取 `hover`：静止态零足迹与「chrome 退后 / 内容即界面」同一方向，且静止帧零基线变化；
  可发现性缺口由命令入口（键盘）兜住——双入口本就是 D3 裁决的形态（命令 + 工具钮）。

## 按钮形态纪律（三轴共用的底座，不因裁决而变）

- 零新 token：壳 = `--preview-bg`（bg 层级最亮档，「浮于内容之上」的色阶表达）+ 1px `--border`
  hairline；圆角 r6（小型控件档）；尺寸 26×24（`--layout-tb-btn` 侧栏变体先例）；图标色
  `--text-2` → 热态 `--text`；过渡 0.1s ease（`--dur-hover`）。
- **无阴影**：两档阴影分别专用 active tab（`--shadow-pop`）与浮层（`--shadow-raise`），
  内容区平铺 chrome 不投影（tokens v1 规则 7）；它再像浮层也是内容区的钮。
- eink：白底实心黑框（规则③⑤），热态黑底反白（规则④，同 `.tb-btn.on` 的 eink 处理）；
  `dim` 淡态在 eink 用 opacity 承载，不改黑白纪律。
- 读屏名：按钮 `aria-label="放大查看表格"`（原型占位措辞，实现期走 deck D120 裁决，
  tasks §3.5）；overlay 读屏名复用 `Markdown 表格 N` 既有生成处，不另起字面量。

## overlay 目标态（`?frame=overlay`，「点下去之后」）

M184 同款遮罩惯用语（`src/lightbox.ts` / `src/style.css` `.lumir-lightbox-overlay`）：
`--scrim` 全屏压暗底层文档 + 居中浮层壳（tokens v1.1 配方：`--preview-bg` + 1px `--border` +
`--shadow-raise`，圆角 r10 浮层壳档；eink = 白底 + 实心黑框 1.4px modal 强调档、阴影退场、
遮罩 .35 明度差保留）。表格快照**自然尺寸不缩放**，超出由壳内双向滚动承载（tasks 2.3）——
截图里宽表在壳内右缘被裁即此行为的呈现。零 chrome、零新文案（同 M184 裁决点 4 口径）。

## 实现期交接（不在本裁决范围，如实记录）

- 按钮必须定位在表格**滚动容器**的坐标系（容器可视区右上角），不是表格内容流里——
  内容横滚时按钮不动；原型是绝对定位静态呈现，实现期别抄成「跟着内容滚」。
- 降级表 / 非矩形表没有 grid DOM，按钮天然不存在（结构性事实，不加提示分支，proposal §Why）。
- 若裁决 `dim`：含表格的整页基线全部重拍，截图 Alex 过目后才 `--update`（AGENTS.md 视觉门禁卫生）。

## 妥协点（诚实清单）

- **hover 浮现的动态过程不可截图**：`hover` 时机的帧是「浮现完成态」，0.1s 淡入节奏无法在静态稿里
  评估；board 里 `dim` 行可真实 hover 体验升档手感，但浮现态的出现动画要留到实现后 dogfood。
- **遮挡只演示了一种情形**：`inside` 叠放对「首行末格」的遮挡用宽表呈现；极窄表（2–3 列）下按钮
  右缘会悬空在表外内容区上——原型未单独出帧，实现期按容器可视区定位自然覆盖。
- **overlay 的滚动条不可见**：macOS overlay scrollbar 静止时不渲染，壳内横滚能力只能从「右缘被裁」
  推断；真实滚动手感归 Alex dogfood（tasks 6.4：手感层不下沉）。
