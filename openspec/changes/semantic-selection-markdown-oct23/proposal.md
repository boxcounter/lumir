# Proposal: 选中渲染态文本时，把 Markdown 语法字符一并纳入选区

- Change ID: `semantic-selection-markdown-oct23`
- 日期: 2026-10-23
- 角色: Alex Lee（评审/裁决），AI agent（起草）

> 评审记录
> 节点 1（提案评审）：**待 Alex 裁决**（2026-10-23 起草）。裁决点 D1–D5 见「裁决点」节，
> 每项附倾向；不回即按倾向落地。
> 节点 2（归档评审）：实现完成后填写。

## Why

Alex 2026-10-23 的需求原话（逐字）：

> 「我希望选中 Markdown 标记文字时，能自动选中文字前面（和后面）的 Markdown 语法字符。
> 比如当我选中标题、但鼠标没有松开时，看到（截图：渲染态标题「Why the Order Is Fixed」
> 整体高亮）我的心理预期是我会选中整个标题，但当我松开鼠标后，发现标题前的井号没有选中。
> 同样，对于粗体，也有类似的问题。」

并追问：

> 「这个需求合理吗？如果不符合多数软件和用户的习惯请告诉我」

Alex 的高频场景是 Quote to chat：拖选标题 / 粗体后点「摘录到对话」，引文缺 `##` 与 `**`。

### 1. 先回答「是否符合多数软件的习惯」：调研结论

调研对象与读数（方法、信源可靠度与未验证项见 design §1）：

| 编辑器 | 选中渲染态文本时，语法字符在选区里吗 | 复制时语法字符如何处理 | 信源 |
|---|---|---|---|
| Obsidian（Live Preview） | **不在**。Live Preview 隐藏大部分语法，光标进入格式内容时才显示；跨隐藏标记的选区另有专门修补（0.13.8 修过「跨隐藏 Markdown 格式的选区」） | 编辑视图复制出去的是**源码文本**（用户抱怨粘贴到文字处理软件后满是 `#` / `*`）；阅读视图复制得到带格式的渲染文本 | [Obsidian Help — Views and editing mode](https://obsidian.md/help/edit-and-read)、[0.13.8 changelog](https://obsidian.md/changelog/2021-12-09-desktop-v0.13.8/)、[论坛现场](https://forum.obsidian.md/t/copy-and-paste-rendered-version-no-markdown-from-the-editor/74252) |
| Typora | **不适用**：语法字符在 WYSIWYG 面从不露面，不存在「选不到」的形态 | 默认复制是纯文本 / 富文本（无标记）；**显式**的 `Copy as Markdown`（⌘⇧C）才把选中内容转成 Markdown 源码，另有「Copy Markdown source as plain text」可设为默认 | [Typora — Copy and Paste](https://support.typoraio.cn/Copy-and-Paste/) |
| iA Writer | **在**。编辑面本身就是带语法高亮的纯文本，格式化结果在独立 Preview 里看——语法字符从来就在文本流里，选区边界天然含它们 | 编辑器复制即源码文本 | [iA Writer — Features](https://ia.net/writer/support/basics/features) |
| VS Code（参照，非 Markdown 编辑器） | 选区不自动外扩；语义扩选是一个**显式命令** `Expand AST Selection`（⌃⇧⌘→ / `editor.action.smartSelect.expand`），另有对称的 Shrink | — | [VS Code — Default keyboard shortcuts](https://code.visualstudio.com/docs/reference/default-keybindings) |

双击 / 三击的口径（mission 要求覆盖的另一项）：三家能核到的都是编辑器通行语义——双击选词、
三击选行 / 段（CM6 的 `rangeForClick` 对三击取整行）。**本轮没有对 Obsidian / Typora 的
双击 / 三击做一手实测**，故这一项只作旁证，不作判据；Lumir 自己的双击 / 三击现状以本仓 CM6
源码为准（design §2 第 12 条：三击本来就选中整行源码，双击只选词）。

三条结论：

1. **「拖选中途自动把语法字符并入选区」不是多数软件的做法。** 唯一「选区里天然含标记」的
   iA Writer 是因为它根本不隐藏标记；隐藏标记的 Obsidian 把选区边界留在渲染文本上（跨隐藏
   标记的选区交给内部的专门处理），Typora 的标记不露面因此谈不上选中。
2. **「从渲染态取到 Markdown 源码」是通行能力，但都放在显式命令或偏好里**（Typora 的
   `Copy as Markdown`、Obsidian 的「编辑视图复制即源码」），没有一家把它做成拖选时的静默选区改写。
3. **语义扩选在编辑器里有成熟先例，但同样是显式动作**（VS Code 的 `Expand AST Selection`）——
   这支持「把外扩放在一个可预期的时机」，不支持「拖拽途中实时跟随」。

### 2. 这个不一致是 Lumir 自己的显露机制造出来的

别家隐藏标记的编辑器里，标记在选区期间通常不露面（Typora 永不露面），所以「选不到」不可见。
Lumir 的 live preview 把「显露」挂在**选区**上：**选区触及即显露源码**——标记一旦被触及就上屏。

1. 装饰层在渲染态隐藏标题的 `#` 串（连同其后一个空格）与强调系的 `**` / `*` / `~~` 定界符
   （`src/preview/livePreview.ts:1153-1165`、`:1169-1191`），标准链接隐藏 `[` 与 `](target)`
   （同文件 `:1322-1323`）。
2. 显露判据是「选区触及即显露」：标题按整行、含端点相接（M297，`src/preview/livePreview.ts:1153`），
   强调系按节点含端点相接（M168，`:1171`），标准链接按严格重叠（M145，`:1295`）。
3. 拖拽过程中，显露判定用**按下瞬间的选区快照**（M259，`src/preview/reveal-gate.ts:39-53`
   与 `:71-96`；接线在 `src/preview/livePreview.ts:601-617`），所以整段拖拽期间布局不动、
   标记仍然隐藏、高亮只覆盖渲染文本——与 Alex 截图看到的一致。
4. 松开：按压窗口关闭、装饰重建，`#` / `**` / `[label](target)` 上屏；**选区范围不变**，
   于是标记看得见、选不到。
5. 两个消费者都读选区，于是都丢掉标记：⌘C 走 CM 原生复制（读 `EditorState.selection`）；
   Quote to chat 在点击时恢复最后选区并 `doc.sliceString(from, to)`
   （`src/quote-gesture.ts:455-499` 记录、`:557-565` 取文本）。

换句话说：**「看得见但没选中」不是外部习惯问题，是 Lumir 自己的两条既有不变量在打架**——
「选区触及即显露」（M297 / M168）让标记上屏，「选区可见范围 = 编辑器选区范围」（M285）要求
高亮只画选区内的字符。两者同时成立时，屏幕上就出现一段没被高亮的上屏源码。

### 3. 为什么值得修

Quote to chat 是 Alex 的主要用途：引文进卡片、进模型上下文时，`##` / `**` 是结构信息，
缺了它，引用方看到的是一段失去层级的文本。修法不需要新增能力，只需要让「选中渲染文本」这个
动作与「显露出来的源码」对齐。

## What Changes

逐条对应 `specs/editor-live-preview/spec.md` 增量里的 ADDED requirement：

1. **指针选区结束时的语法包裹外扩（release-snap）**。指针拖选（非空）在**松开时**，若选区
   完整覆盖了某渲染态构造的全部渲染文本、而该构造的语法定界字符不全在选区内，选区 SHALL
   外扩到该构造的**源码范围**（节点范围：标题的 `#` 串与标题文字、强调系的两侧定界符与内容、
   链接的 `[label](target)` 整条）。只覆盖一部分时 MUST NOT 外扩；嵌套构造由内向外逐层外扩
   至不动点；已含全部定界字符的选区幂等不变。
2. **外扩目标是节点范围，上屏由既有显露判据保证**。三处判据各有其口径（标题行级 M297、
   强调节点含端点 M168、链接严格重叠 M145），它们只回答「什么时候撤下装饰」；撤下后上屏的
   源码就是该构造的节点范围。所以外扩不另造一套「哪些字符算语法」的清单，也不拿行级判据的
   扫描范围当外扩目标（否则引用块里的标题会把 `> ` 一起吞进选区）。实现上抽出同一个纯函数
   供装饰层与外扩共用（REVIEW.md「同一语义两处真源」条）。
3. **覆盖范围是封闭集合**（D4）：ATX 标题、强调系（`**` / `*` / `_` / `~~`，含嵌套）、
   标准 Markdown 链接。行内代码（反引号本就可见）、列表标记与 wikilink（整体替换为 widget、
   没有显露判据）、引用前缀与 callout 标记（块级前缀，v1 不做）、图片 / 公式 / mermaid /
   frontmatter / 分隔线（非文本整块替换）MUST NOT 被外扩覆盖。
4. **双击纳入同一规则**（D2）：双击粗体词后同样会显露 `**` 而只选中词，是同一个不一致；
   双击的词恰好覆盖某构造全部渲染文本时同样外扩。三击现状已选中整行源码（CM 的 `rangeForClick`
   对三击取整行范围，`node_modules/@codemirror/view/dist/index.js:5000-5015`），外扩自然空操作。
5. **不做键盘自动外扩**（D3）：shift+方向键连续扩选时，每敲一次都可能触发一次跳变，
   不能让选择过程中途被改写；键盘平价以独立命令承接，本 change 不做。
6. **与既有缺陷口径的边界**：M259 的「按压期间落点不跨布局」原样保留（外扩只在松开时发生）；
   M539 的隐藏尾标修正只作用于**空光标**，与本条的非空选区不相交；M285 的「选区可见范围 =
   编辑器选区范围」是外扩必须同时满足的判据。
7. **与 M650 的边界**（D5）：本 change 只管编辑器 live preview 里的指针选区；全屏遮罩
   （表格 / 代码块全屏）的选区与复制归在途的 M650（change `fullscreen-table-text-selection`）；
   块级复制钮（复制块源码）与 transcript 消息摘录不变。
8. **spec 增量与验证**：`editor-live-preview` 新增一条 requirement + 场景；纯函数单测矩阵
   （含反向区分度）；chromium 结构层断言（拖拽 → 松开后选区范围与底色覆盖）；真机层走
   「双击 → 摘录到对话 → composer 文本含 `**…**`」（真机套件只能注入双击族，拖选通道造不出
   编辑器选区，见 design §8）；拖选手感归 Alex dogfood。

## 裁决点（每项给倾向；不回即按倾向落地）

### D1 生效时机

| 选项 | 形态 | 评价 |
|---|---|---|
| **A（倾向）** | **松开时外扩（release-snap）**：指针拖选结束、按压窗口关闭的同一拍，把选区外扩到构造的节点源码范围 | 稳定态下所见 = 所得（上屏的定界符全在选区里）；拖拽期间布局不动，M259 不受影响；不干扰 CM 的拖拽状态机 |
| B | 拖拽过程中实时外扩 | 不推荐：按压窗口内标记仍隐藏、隐藏段零宽，选区带不会向隐藏段延伸 ⇒ 实时外扩在视觉上**没有收益**；若为此在拖拽中解冻显露，就复发 M259 的幻影选区缺陷（缺陷原卷见 `src/preview/reveal-gate.ts:1-19`）。且 CM 的拖拽每次 mousemove 按当时布局重算落点，会话中途改写选区会与它打架 |
| C | 仅 copy / quote 动作时补全 | **已证伪**（2026-10-23）：画面上没选中 `##`/`**` 而剪贴板/卡片里有，是新的所见≠所得；quote 卡片立刻把标记亮出来，使不一致更显眼。tower 同日承认该候选在 Lumir（标记可现身）上不成立 |
| D | 双击 / 三击语义选择 | 与 A 组合落地：双击纳入（见 D2）；三击现状已是整行源码范围，无需改动 |

**代价（A 的已知副作用，请一并确认）**：外扩后的选区被输入 / 删除替换时，语法字符会一起被
替换——例如选中整个标题后直接打字，标题会变成普通段落。这是「选中整个标题」的字面含义，
与 Alex「心理预期是选中整个标题」一致；若不能接受，回落成「只对复制 / 引用生效」是不成立的
（选区即状态，M285 也不允许画一个与 state 不同的高亮）。

### D2 双击是否纳入

| 选项 | 形态 | 评价 |
|---|---|---|
| **A（倾向）** | 双击与拖选同一条规则：双击的词恰好覆盖某构造全部渲染文本时外扩（如双击 `**粗体词**` 里的词） | 双击后同样会显露 `**` 而只选中词，是同一个不一致；且双击是**真机套件唯一能注入的编辑器选区通道**（`doubleClick`，见 design §8），纳入后真机层有可断言的路径 |
| B | 只拖选外扩，双击保持选词 | 更保守；但真机层只剩 dogfood 手感判断，且双击路径的不一致原样留着 |

### D3 键盘选区

| 选项 | 形态 | 评价 |
|---|---|---|
| **A（倾向）** | **不做自动外扩**：键盘扩选（shift+方向键 / ⌃⇧N 等）不触发外扩 | 连续扩选时每敲一次都可能跳变，选择过程中途被改写不可接受；本条的文字要求会明确写成「只适用于指针产生的选区」 |
| B | 增加显式命令（如 ⌃⇧↑「扩选到语法包裹」，VS Code Expand Selection 先例），与鼠标路径共用同一纯函数 | 键盘平价完整；代价 = 新命令 + 文案号 + 键位（须过键位表重复检查与配置覆盖语义） |
| C | A + B 都做（自动外扩只给指针，命令给键盘） | 能力最全，scope 最大 |

倾向 A：本次现场是鼠标；纯函数落地后命令接入成本低，适合另起小 change（B 随时可加）。
若你要键盘平价，选 B，本 change 的 delta 增加一条命令要求、tasks 补文案与键位两步。

### D4 覆盖的语法类型

| 语法 | 渲染态隐藏了什么 | 显露判据 | 处置 |
|---|---|---|---|
| ATX 标题 `#`…`######` | 定界串 + 紧随一个空格（闭合 `#` 串一并） | 整行含端点相接（M297） | **纳入（倾向）** |
| 强调系 `**` `__` `*` `_` `~~` | 两侧定界符 | 节点含端点相接（M168） | **纳入（倾向）**，含 `***` 与嵌套 |
| 标准链接 `[label](target)` | `[` 与 `](target)` | 节点严格重叠（M145） | **纳入（倾向）**：与「节点范围 = 外扩目标」同一条规则；代价是引用卡片会带上 URL（若嫌噪声，选下一行） |
| 同上的备选 | — | — | 不纳入链接：动一个小选区就带出一长串 URL；代价 = 链接仍留「`[` 与 `](target)` 上屏但未选中」的不一致 |
| 行内代码 `` `x` `` | 无（反引号本来就可见） | 无 | **不纳入**：不存在「选不到」，无需处理 |
| 列表标记 `-` / `1.` | 标记被 glyph widget 整体替换 | **无显露判据** | **不纳入**：纳入会让选区含一段永远不上屏的字符，直接破坏所见=所得 |
| 引用 `>` / callout `[!type]` | 行首前缀 | 行级（M110/M119） | **不纳入 v1**：跨行引用的每行都会带 `>`，选区形态与语义都要另立规则；留作后续 |
| wikilink `[[target\|label]]` | 整条替换为 label widget | **无显露判据** | **不纳入**：同列表标记——上不了屏的字符不能入选 |
| 图片 / 附件 / 块级公式 / mermaid / frontmatter / 分隔线 | 整块替换 | 各自判据 | **不纳入**：没有可拖选的渲染文本；引用它们走图片摘录与块级复制 |

### D5 与 M650（全屏复制，在途）的边界

| 选项 | 形态 | 评价 |
|---|---|---|
| **A（倾向）** | 互不重叠：本 change 只改编辑器 live preview 的指针选区；全屏遮罩内的选区、⌘A 与复制口径归 M650；块级复制钮与 transcript 消息摘录不变 | 两者改动面几乎不相交（M650 在遮罩 / 原生选区，本 change 在装饰层 + 选区事务）；可并行 |
| B | 等 M650 落地后统一定义「复制口径」再起草 | 阻塞本需求；M650 的复制口径是「原生纯文本」，与编辑器内的源码选区是两回事，没有需要统一的第二份定义 |

## Non-goals

- 不做「复制为 Markdown / 引用时转换格式」的显式命令（Typora 式 `Copy as Markdown`）——
  它不解决所见=所得（标记仍可见但未选中），且是另一个能力面。
- 不做键盘自动外扩，也不新增键位（D3=A；若裁 B 再补命令、文案号与键位）。
- 不改变显露判据本身（不把「触及即显露」改成「覆盖才显露」）——这是 M297 / M168 的既有裁决。
- 不改列表标记、wikilink、引用前缀、callout 标记的渲染与显露（D4 的封闭集合之外）。
- 不改 M539 的隐藏尾标光标修正（它只作用于空光标）。
- 不改全屏遮罩、块级复制钮、transcript 消息摘录的复制口径（D5）。
- 不引入配置开关：这是 md 模式的默认行为，不做成偏好项。
- 不改写文档（ADR 0003 §3）。

## Impact

- **影响的 specs**：`editor-live-preview`（ADDED「指针选区结束时的语法包裹外扩」）。
- **代码**：`src/preview/livePreview.ts`（节点范围 / 隐藏字符的单一出处抽取 + 外扩器的调用点）、
  新增纯函数模块（外扩判定）、`src/preview/reveal-gate.ts`（只读复用按压窗口的生命周期，
  不改变它的语义）、`src/quote-gesture.ts`（时序核对：点击时读到的必须是外扩后的选区；
  代码预期零改动，若时序需要则以最小改动保证）、`src/editor.ts`（若外扩事务需要装配层接线）。
