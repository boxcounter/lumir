## Why

Alex 的原话是「找不到想查询的快捷键」。上一轮只读 survey（`.local/reviews/settings-lookup-patterns-oct24.md`，M694）
把这句话拆成了四个彼此独立的缺口，而不是一个「82 行太长」的问题：

| # | 任务 | 今天的失败方式 | 硬证据 |
|---|---|---|---|
| A | 知道命令，找键（where-is） | 没有人类可读的命令标签；`doc` 列是维护者来由，不是「这条命令做什么」 | 71 命令 / 77 绑定 / 82 行 / 11 组（`src/keys.ts:459`、`:582-804`、`src/bindings-panel.ts:151-182`） |
| B | 知道键，找命令（describe-key） | 键列渲染原始 token（`Ctrl-Alt-KeyS`），没有按键捕获，也不显示 scope / `when` | `src/bindings-panel.ts:134-149` 只有 key / command / doc 三列 |
| C | 浏览学习 | 首屏 13 行、约 10–15 屏；键盘不能滚、`Tab` 被锁死、静止时无滚动条 | 1200×800 基线截图；隔离复现（Chromium + WebKit） |
| E | 入口 | 唯一入口是 `⌘/`，而这个键只写在面板自己里面——要找到「告诉你快捷键是什么」的面板，得先知道它的快捷键 | 全仓 `describe-bindings` 只命中 keys / main / bindings-panel / spec / 场景 |

两项决定性读数：

- **当前文本不是可搜索的用户词典**：对 82 行可见 doc 做子串匹配，「删除」只命中 1 条（还是 `toc.toggle`
  的来由里写了「已删除」），「全屏」0 条，「关闭」0 条，「折行」1 条（误命中字号命令），而「M447」命中 24 条。
  过滤只能放大这个缺陷，不能修复它。
- **行模型是高度的主因**：一条绑定一行，撤销 3 行、标签组 16 行（其中 9 条 `⌘1–9` 同模板、4 条同命令重复键）；
  改成「每命令一行 + 多键合并」后，71 行约 3.3 屏（估算口径见 survey §1.3），而不是 10–15 屏。

面板的模块头自己写明它是「dogfood 期的自用查看器……不是 UX 重设计的一部分，只回答一个问题『某个键现在归谁』」
（`src/bindings-panel.ts:1-2`）。Alex 现在要的「知道命令找键 / 知道键找命令 / 浏览学习 / 修改冲突」是它从未
设计过的任务。**内容不改造，换任何外壳都还是搜不到。**

### 与既有裁决的关系

- **S15 / S16（680px 三列）**：当时保留三列的理由是「命令列对排查自定义 `keys` 配置有实际用途」
  （`docs/backlog.md` 的「记录在案」）。本 change **保留 680px 与全部调试信息**，但把原始 token、命令 id、
  维护者来由移进**行详情**——调试价值不减，速查行不再承担它。这是呈现层的重排，不是把调试视图删掉。
- **「快捷键治理后置」**（Alex 2026-10-03 在 pane 化提案节点 1 裁定）：本 change 不改任何默认键位、不做跨功能
  键位体系，只改「怎么找、怎么读」。键位编辑仍留 `config.json`。
- **独立设置页**：不做。Alex 已认可「保留就地速查面板」；Apple HIG 也把「只影响某个任务的选项」放在任务里，
  查找键位发生在编辑中途（survey §3.1 的完整依据）。

## What Changes

逐条对应 `specs/keymap-commands/spec.md` 的增量：

1. **面板行模型与外观（MODIFIED「键位查看面板（app.describe-bindings）」）**：一条命令一行（不是一条绑定一行），
   同一命令的多条生效键合并到该行的键位区；每行有中英双列的人类标签、scope 徽标、`when` 短徽标；
   无绑定的命令仍是行，标注「未绑定」并说清成因与下一步。分组仍按功能族、保持现有组与组序；组头可折叠；
   空查询默认全量展开。面板外壳、680px 宽、遮罩与三主题 token 不变；`Tab` 从「锁死在面板内」改为
   「在面板控件之间循环」——输入框让旧理由（面板没有可聚焦子元素）过时，spec 的 Tab 条款必须改准。
2. **查找、捕获与详情（ADDED「键位面板的查找：文本查询、按键捕获与详情」）**：一个带标签的输入框；
   空查询 = 全量；文本查询匹配**人类标签（中英两列）+ 别名 + 命令 id**，大小写折叠子串匹配；
   **来由（维护者 doc）不进主搜索语料**（否则「M447」命中 24 条、「删除」误命中）。
   按键捕获是一个显式模式：按下组合键 → 用 `keyToken` 同源归一化 → 定位到该 token 的生效命令；
   **被捕获的键不执行任何命令**；捕获结果同样显示 scope 与 `when`；无绑定键给空态。
   行详情就地展开，承载来由、原始 token、命令 id、scope 说明、`when` 全文；未绑定行给出 `[keys]` 绑定方法。
   查询 / 捕获 / 作用域筛选都有计数与空态；键盘全程可用（输入框持焦、↑↓ / ⌃N⌃P、Enter 详情、Tab 循环、
   PageUp/Down 翻页、Home/End、分层 Esc、⌃G 关闭、IME 组合期不刷新、关闭后焦点交还编辑器）。
3. **非自指入口（ADDED「键位面板的非自指入口」）**：Help 菜单新增 **Keyboard Shortcuts** 项，点击经既有
   `app:menu_command` 与同一命令层打开面板；**不带加速键**——任何菜单 accelerator 都会在 NSApplication
   分发阶段截获物理键，既会把 `⌘/` 的 `[keys]` 重绑变成假开关，也会形成第二条分发路径。`⌘/` 仍是可重绑的
   默认键，菜单入口不依赖它。
4. **单一数据来源（ADDED「命令元数据与键位字形的单一来源」）**：每条 `COMMAND_ID` 恰有一个中英标签，
   标签住文案表（`文案-Copy.md` + `src/copy-data.ts`），由单测对账；别名是可选的**搜索专用**数据，不进上屏；
   scope 文案与 `when` 文案各只有一份；token → `⌃⌥⇧⌘` 字形由 `src/key-glyphs.ts` 唯一实现，复用 `normalizeKey`
   的归一化口径；面板不得逐条硬编码命令文本。字形顺序取 Apple HIG 的 `⌃⌥⇧⌘`（如 `⇧⌘O`），
   需要 Shift 的符号反解成物理键（`Cmd-}` → `⇧⌘]`、`Cmd-<` → `⇧⌘,`），不把 token 直接写给人看。

### 原型

`design/prototypes/keybindings-lookup-oct24.html`：自包含、可点击、内置控制面板（主题 / 场景 / 查询 /
作用域 / 捕获 / 分组 / 详情 / 入口条 / 菜单 / 面板开关），覆盖 P1 / P2 / P3 / P4 / P6 五个场景、
空结果、详情、折叠与三主题；命令与来由全为合成 fixture。P1–P6 已先写成机器断言

## Non-goals

- **不做独立设置页 / `⌘,` / 偏好设置面**：Alex 已裁决「保留就地速查面板」。应用偏好（editor / ui / harness）
  与本面板不混。
- **不做分页，不做 11 族页签**：11 组超过 HIG 的 6 组上限；跨页签查找会漏；`⌃Tab` 已是全局切标签键。
  作用域筛选是**筛选**（单选、即时、不换页），不是页签。
- **不做键位编辑 UI**：不提供「替换 / 新增 / 解绑 / 移动」写操作；`[keys]` 配置 + 重启仍是唯一写路径。
  可写面的冲突 / 回滚 / 热重载是另一个 change（`docs/backlog.md` 的「快捷键治理后置」）。
- **不把来由放进主搜索语料**：来由只在详情里按需展开，不参与匹配、不打分、不高亮。
- **不做模糊匹配 / 拼音 / 全半角归一 / 排序打分**：复用 `list-filter` 的大小写折叠子串语义，不另造一套匹配。
- **不改分发语义**：不改任何默认绑定、不改「一个 token 一条绑定」、不改 scope 派生、不新增命令或键位；
  `app.describe-bindings` 仍可被 `[keys]` 重绑 / 解绑，菜单入口不受影响。
- **不做 cheat sheet 导出 / 打印面**：学习面就是同一面板的分组 / 折叠 / 作用域筛选。
- **不持久化查询 / 折叠 / 捕获状态**：每次打开回到空查询与全量；这些是瞬态 UI 状态，不写 `config.json`。
- **不在本 change 引入 modeline 常驻按钮**：非自指入口先由 Help 菜单承担；常驻 chrome 是否值得由 D1 裁。
- **不改标题栏 / 编辑器 / 现有浮层的交互**：面板打开期间 global 键仍照常分发（既有模态边界），
  只有捕获态是例外。

## 裁决点（每项给倾向；不回即按倾向落地）

### D1 非自指入口放哪

- **A（倾向）**：Help 菜单 → **Keyboard Shortcuts**，无加速键。理由：macOS 的 Help 菜单自带菜单项搜索，
  键盘用户也能用；平台惯例、零常驻 chrome；菜单项与 `⌘/` 互不依赖，`[keys]` 重绑不会让它失效。
- B：Help 菜单 + modeline 常驻 `⌘/` 指示段。可发现性更高，但 modeline 已经在承载路径 / 大纲 / 主题 / 语言，
  再加一段是常驻 chrome 成本；且 `⌘/` 被重绑后指示段会过期（除非只写「快捷键」不写键）。
- C：只加 modeline 按钮。比 A 更显眼，但把入口藏在一个只在有文档时才完整的行里，且窄窗要退让。

### D2 字形顺序

- **A（倾向）**：Apple HIG 顺序 `⌃⌥⇧⌘`，如 `⇧⌘O`、`⇧⌘T`、`⌃⌥S`。与系统菜单一致，减少「⌘⇧ 还是 ⇧⌘」的歧义。
- B：沿用现有文档散文的 `⌘⇧O`。与部分 spec 文字一致，但与 macOS 系统菜单的写法相反；新生成的字形会成为
  第三个写法。倾向 A，同时在实现批把可见文案里的手写键位逐步收敛到生成字形（不在本 change 做全仓改写）。

### D3 详情形态

- **A（倾向）**：行内手风琴（一次只开一个）。单列、不新增第二栏、不新增嵌套滚动容器（REVIEW.md 的滚动条
  分档规则）；680px 继续够用。
- B：右侧详情栏。可同时看列表与来由，但 680px 要变宽（与 S15/S16 的 680 裁决冲突），窄窗还要退让；
  来由是「按需读」而不是「常驻读」，不值得常驻宽度。

### D4 捕获怎么进

- **A（倾向）**：显式「捕获按键」按钮（输入框旁），点击后进入等待态。保留面板打开期间 global 键照常分发
  的既有边界；不会把 `⌘F` / `⌘P` 静默吞成捕获。
- B：输入框里按下带修饰键的组合就自动捕获。少一次点击，但会与 global 键冲突（面板开着按 `⌘F` 是开搜索，
  不是查询 F 键），需要一个「哪些键不捕获」的黑名单，规则会长期漂移。

### D5 Esc / Tab / 捕获态的边界

- **A（倾向）**：
  - Esc 分层：捕获等待 → 取消捕获；已捕获 → 清除捕获；有查询 → 清查询；否则关闭。
  - Tab 四停循环：输入框 → 捕获按钮 → 作用域组（选中项）→ 结果列表 → 回输入框；Shift+Tab 反向；
    空态动作钮可见时追加在末尾。焦点不逃出面板。
  - 捕获等待态是唯一例外：**`⌃G` 被当作待查询的键捕获，不关闭面板**（否则无法反查 `⌃G`），退出捕获只用 Esc。
    已捕获态 `⌃G` / `⌘/` 照常关闭。
- B：捕获态也保留 `⌃G` 关闭。少一个例外，但 `⌃G`（取消选择）永远无法通过按键捕获查到，只能文本搜。

### D6 标签维护承诺

- **A（倾向）**：71 条命令全部要求中英标签；单测对账（缺一条即红），别名可选、只在自然措辞与标签不同时写。
  新增命令必须同批写标签——标签是命令的「人类名」，不是可选装饰。
- B：只给高频 20–30 条写标签，其余回退命令 id。成本低，但 where-is 对长尾又失效，且「哪些算高频」没有数据
  支撑（本仓无使用遥测）。

## 观测闸三问

- **怎么知道用户用了它**：菜单项与 `⌘/` 两个入口都通向同一个面板；每次打开都是可观察动作（无遥测，
  靠 dogfood）。「打开后有没有查询 / 捕获」是 Alex 下一次 dogfood 的观察点。
- **怎么知道它有效**：P1–P6 的机器断言在原型上全绿；实现后同一组场景落到视觉 / 真机验收。
  判据不是「面板打开了」，而是「≤3 次击键出现目标行」「一次捕获定位」「键盘能滚到最后一组」。
- **出问题怎么发现**：标签漏写由单测红；字形泄漏 token 由单测红；来由误入搜索语料由单测 + 视觉场景红；
  键盘 / 焦点回归由真机场景红；像素走样由 `m133` 视觉场景与 Alex 的并排截图对照发现。
