# Design: add-semantic-image-naming

> 本文件只回答「怎么落」；「为什么改」见 [proposal.md](proposal.md)，行为口径的正本在
> [specs/clipboard-image-paste/spec.md](specs/clipboard-image-paste/spec.md) 的增量里。
> 命名形态、撤销语义、引用更新的判据已由 Alex 2026-10-18 裁决（原文见 proposal 文首），
> 本文件不重开这些决定，只写落法、边界与代价。

## 1. 配置面

新增 `[attachments]` 表：`config.json` 顶层的 JSON 对象键（不是数据库表，也不改 TOML）：

```json
{
  "attachments": {
    "semantic_naming": true,
    "naming_model": null
  }
}
```

| 键 | 类型 | 默认 | 取值范围 | 生效时机 |
|---|---|---|---|---|
| `attachments.semantic_naming` | boolean | `true` | `true` / `false` | **运行期关掉立即生效**（后端命令每次调用现场 `config::load()`，读到 `false` 即跳过）；**打开需重启**（前端投递闸取启动装载值，关着时前端根本不投递任务）。方向不对称是隐私面的有意取舍：关是更严的方向 |
| `attachments.naming_model` | string \| null | `null` | 非空字符串；必须是 `[harness]` 当前 provider 的 `models` 清单里声明 `vision: true` 的 id。不满足 → 一条人话 warning + 按 `null` 处理 | 后端每次调用现场读一次 ⇒ 改动**下一次粘贴即生效**（无需重启）；前端不复制这条判据 |

> 生效时机的实现口径（评审 r1 观察 1）：canonical 文档
> `docs/specs/config-reference.md` §1.6 与 `config.rs` 的 doc comment 已按实现写准，本表与之
> 一致；「启动装载读一次、改配置需重启」是初稿的过时表述（只对 `semantic_naming` 的**打开**
> 方向成立）。

- 缺省即默认：整表缺席 / 单键缺席 = 出厂值；`null` 与缺席同义。
- 非法值（类型不符、`naming_model` 指向未声明或未声明 vision 的 id）按既有逐字段回落模板：
  回落默认 + 一条 warning，其余键照常生效（ADR 0002 §5）。
- `naming_model = null` 时用 `[harness]` 当前生效 provider 的当前 `model`；该模型未声明
  `vision: true`（mock provider 恒支持）时**不发起命名**，保留 hash 名。理由：配置里没有价格 /
  档位字段，自动从清单里挑「最便宜」等于猜；命名档位由用户显式指定，缺省跟随当前模型。
- **运行期 provider 切换**：校验只在装载时做一次，但命名任务发起时会按**当时生效**的 provider
  重新核对 `naming_model`（是否列出、是否声明 vision）；不再满足即跳过本次命名（MUST NOT 降级
  到清单里的其它模型——那等于替用户选模型）。mock provider 没有 `models` 清单，`naming_model`
  对其必须是 `null`（非空即装载 warning + 按 `null` 处理）。
- 不在配置面内的东西：命名形态（语义名 + 6 位短哈希 + 原扩展名）、slug 字符集、撤销窗口、
  扫描范围——这些是行为，不是偏好。

`config.rs` 侧形状：`AttachmentsConfig { semantic_naming: bool, naming_model: Option<String> }`，
挂在顶层 `Config` 上（与 `editor` / `ui` / `vault` / `harness` 平级）。ts-rs 导出
`src/bindings/`，前端不重算合法性（REVIEW.md「同一语义两处真源」）。

## 2. 命名身份：内容哈希与两种文件名形态

**身份 = 转码后字节的 SHA-256**（既有的内容寻址口径），文件名只是它的两个视图：

| 形态 | 何时出现 | 例子 |
|---|---|---|
| 暂存名 `pasted-<hash16>.<ext>` | 粘贴落盘、命名未完成 / 失败 / 关闭开关 | `pasted-a3f2c4d5e6f70819.webp` |
| 语义名 `<slug>-<hash6>.<ext>` | 异步命名成功后 | `harness-arch-a3f2c4.webp` |

- `hash6` = 同一 SHA-256 的前 6 位十六进制；扩展名与转码目标一致（不改写、不重编码）。
- 改名只换文件名，不换目录（仍在粘贴时落盘的目录，见 spec「落盘与命名去重」）。
- **去重探测改造**（`fs_io` 的 `find_vault_entry_by_name` 族）：粘贴时已知本次转码字节的
  `hash16`，探测两族名字：
  1. 精确名 `pasted-<hash16>.<ext>`；
  2. 同扩展名、stem 末段是一段十六进制短后缀且**其前 6 位等于本次 `hash6`** 的任何文件（覆盖
     6 / 8 / 12 / 16 位的后缀扩展形态）——命中后**重新计算该文件字节的 SHA-256** 与本次
     `hash16` 比对，相等才算去重命中。
  第二族的全量哈希复核是承重的：6 位十六进制在几百张图的规模上就有可见的撞名概率（生日问题），
  只凭后缀相同就判同图会把两张不同的图片静默合并成一张。
- 探测遍历沿用现行口径（hidden 档与配置 `lazy` 档目录整棵跳过；用户规则命中的惰性目录照旧
  遍历；不跟随符号链接），不为此新增第二套遍历规则。
- **改名撞名**：目标名在全 vault 已被占用且内容不同时 MUST NOT 覆盖；把后缀按 6 → 8 → 12 → 16
  位扩展，取第一个未占用名。内容相同的占用（同一内容已有语义名）直接放弃改名并复用既有位置
  ——这只会出现在并发 / 手工复制的边缘场景。**复用的落法**（评审 r1 P2-4）：把指向暂存副本的
  引用末段改指既有文件名，然后删除暂存副本（「MUST NOT 产生第二个副本」在这一支同样成立）；
  若有个别笔记未能改写（并发修改 / 读失败），保留暂存副本避免断链（多一份副本比断链便宜），
  并落一条诊断。复用结果不带撤销令牌——既有语义文件不是本任务改的名。
- **撤销后的名字回到暂存名**：`pasted-<hash16>.<ext>`；若该名已被别的文件占用，撤销放弃（见 §6）。

## 3. 异步链路时序

```
粘贴事件（编辑事务，<16ms）
  └─ fs_write_attachment ──► 落盘 / 去重 ──► 返回 path + name
  └─ 插入 ![[name]]（既有事务，零改动）
  └─ 满足条件时投递命名任务（不 await）
        │
        ├─ 读取字节 → 计算 hash16 / hash6
        ├─ 放弃判据（前置快检，同一规则）：文件不在了 / 字节哈希变了 / vault 已切走
        ├─ 组装请求（图片 + 上下文）→ 一次 vision 调用
        ├─ 放弃判据（改名前的最终判定，同一规则）：路径仍在、字节哈希未变、文件名仍是暂存名
        ├─ 解析 / 清洗 slug → 目标名（含撞名后缀扩展）
        ├─ 全 vault 扫描 + 解析式匹配（rename **之前**，见 §5）
        ├─ rename 文件（单文件原子 rename，不覆盖）
        └─ 逐篇改写命中笔记（tmp + rename；CAS 跳过并发修改）
              └─ 结果返回前端：旧名 / 新名 / 旧路径 / 新路径 / 被改写笔记 / 跳过计数 / 撤销令牌
                    └─ 前端对账打开中的会话 + toast（带「撤销」）
```

- **只在「本次粘贴新写盘」时投递**：去重命中（既有文件）不投递；文件名已是语义形态不投递。
  暂存名残留（上次命名失败）不自动重试——避免每次粘贴都补发后台调用。
- **同一路径去重**：同一文件路径同时最多一个命名任务；重复投递合并。
- **串行队列**：命名请求同一时刻至多一个（高频低价值密度，不抢 harness 会话的并发与配额）。
  队列积压时按 FIFO；任务超时（固定上限，实现期定值，建议 20 秒）即放弃。
- **vault 隔离**：任务捕获发起时的 vault 根；完成时当前 vault 根不一致则放弃（路径按 vault
  相对路径重新解析，防跨 vault 写）。
- **应用退出**：不持久化队列，未完成的任务随进程结束丢弃；文件保持暂存名（现状）。

## 4. 模型调用

- 复用 `harness::llm` 的 client 装配（provider / model / wire 方言 / 图片展开），**不建 harness
  会话、不写会话 JSONL、不进上下文装配**：这是一次性后台调用，不是对话轮次。会话留存因此
  零污染（`openspec/specs/harness/spec.md`「会话本地留存」的恢复判据不受影响）。
- 请求形态：单条 user 消息 = 文本指令 + `input_image`（图片字节），无工具、无历史、stream 关。
  `max_output_tokens` 收紧到只够一个 slug（实现期定值）；`thinking` 档位不显式设置（跟随模型
  默认，便宜档模型通常无该能力）。
- 上下文取材（spec 已定）：图片字节 + **粘贴时刻**光标前后的段落文本 + 笔记标题。段落各截断到
  固定字符上限（建议前 500 / 后 500 字符）；笔记标题 = 当前笔记文件名的 stem（无路径的新建
  文档取空串）。上下文在粘贴时**同步快照**后随任务携带——异步返回时用户可能已经继续写，重新
  读光标位置会取到毫不相干的段落。
- 输出约束：要求模型只输出一个短 slug（英文 kebab-case：`a-z` / `0-9` / `-`）、不带扩展名、
  不带引号。解析取第一行、去引号 / 反引号 / 代码围栏、去扩展名，再按 spec 的 ASCII 字符集
  规整（大写折叠为小写、空白 / 下划线折 `-`、非 ASCII 字符剔除且不音译、连续 `-` 折叠、首尾
  `-` 裁掉）。**规整后为空 = 失败**（保留暂存名）；模型若回纯中文名，剔除后为空，走这条失败
  路径——这是字符集裁决的直接后果，不做音译兜底。
- **提示注入的处置**：笔记标题与段落是用户内容，只作为请求里的文本出现，模型输出只经字符集
  规整与长度上限后当文件名使用，MUST NOT 被当作路径、命令或配置。图片字节与正文不落诊断日志。
- 失败分类（网络错误 / 非 2xx / 超时 / 输出不可用 / 无 vision 模型 / fixture 缺失）一律走
  「保留暂存名 + 诊断一条」；MUST NOT 弹失败 toast（高频路径，静默降级即现状）。
- **调度档位 = 便宜档**（harness-vision 的调度原则：按产物纠错成本分档，一次性产物的错误活得
  短、易发现）。落法：不自动挑模型——配置里没有价格 / 档位字段，自动挑「最便宜」等于猜；
  `attachments.naming_model` 是显式的成本阀门，缺省跟随当前生效模型。命名请求不进 harness
  会话的上下文装配与工具循环，单次成本只有一张图 + 一小段上下文，天生是同一档里最轻的调用。

## 5. 引用更新

### 5.1 扫描顺序（承重）

`link_graph` 的解析基于「当前 vault 的文件名索引」；文件一旦改名，旧名不再可解析。因此：

1. **rename 之前**做全 vault 扫描：第一遍只走目录收文件路径（与去重同一套剪枝口径），第二遍
   逐篇 md 读盘、`parse_links` 解析、按**解析结果**匹配旧路径，收集 `(文件, 改写点)` 与读时
   内容哈希。
2. rename 文件。
3. 逐篇改写：写前重读并核对内容哈希与第一步一致（不一致 = 扫描后被改过），一致才 tmp + rename
   原子写；不一致跳过并计数。

这样「异步窗口内新增 / 手改的引用」在第一步自然被覆盖（判据是改名时刻的磁盘内容），也不需要
第二套「窗口期间事件补偿」逻辑。

### 5.2 匹配与改写判据

- **链接源**：vault 内 `*.md` 文件（链接只存在于 md；其它文本类文件不解析）。hidden / lazy
  档目录跳过，与扫目录同一口径。
- **链接形态**：`[[target]]` 与 `![[target]]`（`parse_links` 的输出）。代码块 / 行内代码 /
  frontmatter 内的文本按解析器口径不是链接，天然不碰（spec「wikilink 词法识别与分解」）。
  标准 Markdown `![alt](path)` 不在射程（proposal 非目标）。
- **匹配**：`resolve` 的结果等于旧路径（root 相对路径的同一形态）；或（rename 之后 / 撤销时的
  反向匹配）链接 target 的**末段**与目标文件名相等（大小写折叠复用解析器同一条规则）。6 位
  后缀可能撞名，但完整文件名在全 vault 唯一（改名时做过可用性探测），末段匹配不会命中别的
  文件。
- **改写**：只替换 target 的**末段路径**为新文件名。`!` 前缀、目录前缀（`notes/` 这类原样
  保留）、`#heading`、`|alias` 与链接之外的正文逐字节不动。同一行多条链接时按 span 从后往前
  应用，避免偏移串联。
- **span 来源**：`WikiLink` 现在只有整条链接的 span；给词法层补一个 `path_span`（纯词法信息，
  不改变任何解析语义），fixture 增断言。前端 MUST NOT 另写一份「找 target 位置」的词法。
- **确定性**：同一输入两次扫描得到同一改写点集合；目录遍历顺序不影响结果（逐文件独立改写）。
- **与渲染侧的分工不变**：`attachment-display`「附件路径解析口径」按 `![[...]]` 的文件名唯一
  匹配渲染图片；改名保证新文件名在全 vault 唯一（§2 的可用性探测），因此渲染侧零改动、仍走
  同一条唯一匹配 + 歧义确定性逻辑。本 change 不把渲染解析搬进改名链路，也不在渲染侧新增第
  二份命名规则。

### 5.3 打开中的文档对账

后端改的是磁盘。前端拿到结果后逐条对账：

| 会话状态 | 处置 |
|---|---|
| 图片文件在标签中打开 | `editor.remapSessionPaths(旧路径, 新路径)` + `save.noteRenamed`（与既有文件改名同一条链路） |
| 笔记 clean | 从磁盘重载（复用既有 reload 路径，revision 推进）；用户无未保存内容可丢 |
| 笔记 dirty | ① 用**纯函数 IPC** 对当前内存文本重算改写（输入 = 文本 + 旧/新路径），得到当前坐标下的 span，按编辑事务应用（保留撤销栈、选区尽量不动）；② 若该文件在磁盘上也被后端改写（引用在扫描时已存在），结果携带新 revision，前端推进该路径的 CAS 基准；若引用只存在于内存（刚粘贴未保存的常见情形），磁盘零改动、不推进；③ dirty 状态保持 dirty（用户本来就有未保存修改） |

- ②的基准推进必须有专门的 save-controller 入口（例如 `noteRevisionAdvanced(path, revision)`）；
  否则用户下一次 ⌘S 会撞上「磁盘比你新」的假冲突。用户若放弃修改关闭标签：引用若本来就在
  磁盘上，磁盘已改对（无断链）；引用若只在内存（刚粘贴未保存），则随放弃一起消失（同样无断链）。
- **watch 回声抑制**：后端写盘会触发 `Modified` 事件；在 invoke 发起时按路径登记抑制（与
  `renameEcho` 同形，`src/main.ts` 的既有权衡），结果返回并推进基准后撤除。否则 dirty 文档会
  被当成「外部改写」弹冲突提示。
- 重载 / 改写只碰被改写的文件，未命中的打开文档零动作。
- **dirty 会话的发现口径**：前端对**全部打开的可编辑会话**调用纯函数命令（未命中的返回空变更），
  不能只按后端「磁盘命中列表」挑文件——刚粘贴、尚未保存的引用在后端扫描时不在磁盘上，只在
  内存里；漏掉这一条就等于最常见的那条路径不生效。

### 5.4 失败与半截

- 单篇笔记改写失败（权限、IO、并发修改跳过）**不回滚改名**：文件改名是能力本体，回滚会让
  「成功改名的图」与「失败」两种结果互相污染。结果携带未更新数量，前端弹一条人话 toast 点名
  （文案进 deck）。
- rename 失败（目标不可写、撞名且扩展后缀仍不可用）→ 整个任务放弃，保持暂存名，无引用改动。

## 6. 撤销

- 成功改名返回一个**撤销令牌**；后端在内存里保存一条改名记录（旧名 / 新名 / 旧路径 / 新路径 /
  内容哈希 / 发起 vault 根 / 过期时刻）。令牌只在 toast 可见期内有效（带动作的 toast 8 秒后
  自动消隐，`src/main.ts` 的 `showToast`）。
- 撤销 = 对称操作：以同一解析能力重新全 vault 扫描（此时匹配新名，见 §5.2 的末段匹配），把引用
  改回 `pasted-<hash16>.<ext>`，再把文件改回暂存名。
- 撤销的放弃条件（与命名保持同一组判据）：目标文件已不在记录路径 / 字节哈希已变（人工又改名、
  移走、替换）；或暂存名已被别的文件占用；或 vault 已切换。放弃时给一条人话 toast（撤销是用户
  显式动作，不能静默）。
- 撤销 MUST NOT 触发新一轮语义命名；撤销后该文件回到「暂存名 + 不自动重试」的状态。
- 令牌过期 / 不认识的令牌 → 命令返回「无可撤销」错误，前端按失败提示处理（正常路径不会发生：
  toast 消隐后按钮已不在）。

## 7. 提示与文案

- 成功：一条 toast，文本含新文件名，动作「撤销」（`文案-Copy.md` 新增 deck 条目，zh / en 两档）。
- 部分引用未更新：一条 toast 点名数量（不阻塞、不打断编辑）。
- 撤销失败：一条 toast 说明文件已被改动 / 无法撤销。
- 失败（无模型 / 调用失败 / 输出不可用 / 放弃）：无 toast，只有诊断日志（事件名固定、含
  `path` 与错误码，不含正文与字节）。
- toast 归属沿用既有 `toastOwnerMount()`（活跃 pane）；不做进度条 / 状态指示——后台任务的可观测
  面就是成功 toast 与诊断。

## 8. 性能与安全边界

- **性能合同**（ADR 0002 §6）：粘贴同步段 = 既有落盘 + 插引用，只多一次「投递任务」的常数开销；
  hash6 / hash16 在落盘时本就已算。扫描发生在 rename 时刻的后台线程，与键入、打开文档、渲染
  无关。打开 1MB Markdown 的路径零新增工作。
- **扫描成本**：一次改名 = 一次目录遍历 + 逐篇 md 读盘。与既有粘贴去重遍历同量级；只在命名成功
  时发生（每个新图片一次），且串行队列把它摊到后台。
- **写入安全**：rename 与笔记改写都走 tmp + rename；不允许覆盖既有文件（`RejectExisting` 或
  CAS 前置检查）。路径全部经 vault 根解析，防逃逸。
- **数据安全**：图片字节与笔记正文只出现在模型请求里；诊断日志不落正文、不落 base64。
- **不新增外部依赖**：模型调用复用既有 client；文件名清洗是本地纯函数。

## 9. 测试矩阵（机器验收面）

**Rust 单测 / 纯函数**

- 去重：语义名文件 + 同内容再贴 ⇒ 命中并返回既有路径；6 位后缀相同但内容不同 ⇒ 不命中、
  正常写盘（用一个改掉一个像素的合成图构造碰撞）。
- 改名：目标名被占 ⇒ 后缀 6 → 8 → 12 → 16 扩展；不可覆盖。
- slug 清洗：引号 / 反引号 / 围栏 / 扩展名 / 空白 / 下划线 / 非法字符 / 空串 / 超长各一例；
  非 ASCII 字符（中文 / 全角标点 / emoji）一律剔除且不音译，纯非 ASCII 输出 ⇒ 空 ⇒ 失败；
  大写折叠、连续 `-` 折叠、首尾 `-` 裁掉。
- 解析匹配：`![[name]]`、`![[dir/name]]`、`![[name|alias]]`、`![[name#h]]`、大小写变体、
  代码块 / 行内代码 / frontmatter 内同串不命中。
- 改写保字节：除 target 末段外全文逐字节不变（fixture 断言）。
- 放弃：文件被改名 / 移走 / 内容变化 / vault 切走各一例。
- 撤销：反向扫描 + 改回暂存名；暂存名被占 / 文件再被改名 ⇒ 放弃并报错。
- 配置：缺省 / 关闭 / 非法 `naming_model` 回落 + warning / 类型不符整文件回落。
- 打开文档对账：dirty 文本经纯函数重算后只改链接末段；revision 推进后保存不报 CAS 冲突
  （前端单测 + Rust 纯函数各自覆盖）。

**前端单测（`tests/unit`）**

- 粘贴成功即插入暂存名引用，命名任务不阻塞插入（端口调用顺序断言）。
- 开关关闭 / 无 vision 模型 ⇒ 不投递任务。
- 对账：clean / dirty 两条分支的调用形态；watch 回声抑制登记与撤除。
- toast 动作与撤销令牌的传递。

**验收套件（真机，`scripts/acceptance/`）**

- 新增场景：mock provider + 专用 fixture 驱动一次命名（`harness: { provider: mock, fixture:
  <semantic-naming fixture> }`，`config: { attachments: { semantic_naming: true } }`）；断言
  终态文件名 `<slug>-<6 hex>.webp`、正文引用同名、暂存名文件不残留、toast 带「撤销」。
- 同一场景续做撤销：点「撤销」后文件名回到 `pasted-<hash16>.webp`、正文引用同步改回。
- 回扫既有 112 / 113 / 116：在验收环境的默认配置下没有声明 vision 的模型（且默认 provider
  不是 mock）⇒ 不发起命名，既有「`pasted-<hash16>` 终态」期望不变；逐条核对并在场景注释里
  写明这条前提。
- 无 model 口径复用 112：粘贴后**稳定**保持暂存名（等一个明确的观察窗口，断言不存在语义名
  文件）——同时守住「失败不弹 toast」。

## 10. 已知边界（如实记录）

- **6 位后缀可能撞名**：两张不同图片可以有相同的 `hash6`。这不影响正确性（文件名包含完整
  slug 与全量哈希复核的去重），只影响「看后缀猜是不是同一张图」这种人肉判断。
- **中文笔记的图片名是英文转述**：字符集裁决为纯 ASCII kebab-case，语义名只能是模型给出的
  英文 slug；模型若回纯中文名，剔除后为空即按失败保留暂存名（不做音译）。这是裁决的直接代价，
  在此如实记录。
- **只更新 wikilink**：用户手写的 `![alt](pasted-…webp)` 引用在改名后会断（落占位，不静默）。
  这是显式边界：粘贴链路只产出 wikilink，标准 Markdown 链接的更新是后续扩展。
- **扫描是快照式的**：扫描与写盘之间被别的进程改动的笔记会被跳过并计数，不重试、不回滚改名；
  跳过的那几篇会留断链（占位可见）。
- **撤销窗口短**（toast 8 秒）：窗口外没有补偿通道；这是「提示即入口」的既有 toast 口径。
- **命名失败不补发**：暂存名文件不会在后续粘贴或后台重试中被命名；只有重新粘贴同一内容（去重
  命中）也不会补发。避免后台调用变成无人控制的自动流水线。
- **mock provider 恒支持 vision**：验收环境下粘贴即会触发命名，凡是「贴图 + mock provider」
  的既有 / 新场景都必须显式声明 `semantic_naming` 的期望，不能靠默认值碰运气。
- **不做文件名去重以外的语义检索**：本 change 只让名字可读，不建图片索引、不生成标题 /
  alt 文本。
