# Proposal: 新建文件时预填人类可读默认名

- Change ID: `add-default-note-name-nov24`
- 日期: 2026-11-24
- 角色: Alex Lee（评审/裁决），AI agent（起草与实现）

> 评审记录
> 节点 1：Alex 2026-11-24 裁决原话「批准。」——方向为「可开启的小特性，新建文件时预填人类可读
> 默认名并选中，降低起名字负担」。合同要点见下文「What Changes」，实现 MUST NOT 扩大范围。

## Why

当前新建文件时输入框为空，用户每建一个笔记都要先想一个名字，哪怕只是随手记一笔。文件树已有
内联编辑、默认补 `.md`、撞名预检与「新建后焦点落正文」的完整链路；在这个链路上预填一个可读的
默认名并全选，用户直接输入即替换、直接 `Enter` 即得到可接受的名字，不改变后端创建语义。

这是一个**默认关闭**的偏好（保持现状），由 Alex 2026-11-24 批准为可开启的小特性。

## What Changes

- 设置面板「自动化」节新增第五个开关「新建文件时预填默认名称」，配置键
  `editor.prefill_note_name`（`[editor]` 表，布尔，**默认 `false`**）。默认关闭时新建文件与
  今天逐字相同（空输入框 + 既有占位）。
- 开启后，内联新建文件（目录行菜单 / vault 根级菜单 / 空 vault 新建入口共用的同一条
  `beginCreate` 链路）预填当前界面语言的默认名：zh `未命名笔记`、en `Untitled note`。
  输入框只含主文件名（不含 `.md`），`focus()` 之后整段全选。
- 用户直接输入即替换全选内容；`Enter` 接受并按既有创建链路补 `.md`、落盘、自动打开，随后
  焦点按既有 `focus-created-document-nov23` 链交给正文；`Escape` 按既有取消语义撤销；`Tab`
  不新增任何行为（沿用原生焦点移动与失焦取消）。
- 默认名与同级既有条目撞名时自动递增（`未命名笔记 2` / `Untitled note 2`…），判据对最终
  落盘名（补 `.md` 后）作出；**用户自己输入的名称仍走既有撞名校验，不静默改名**。
- 只作用于 `create-file` 的内联编辑；重命名、新建子目录、wikilink 一键创建、未命名内存文档
  等链路不受影响。不调用 AI、不按 vault 分类、不引入模板设置或新 provider。
- 设置保存后立即生效（前端在保存成功的快照回调里更新读数），不需要重启。

## Non-goals

- 不引入模板、frontmatter 预填、目录级命名策略或按 vault 分类的默认名。
- 不改变后端创建命令、撞名拒绝、忽略集判定或 `.md` 默认扩展名规则。
- 不改变重命名（含其「原名预填 + 全选」的既有口径）、新建子目录或 wikilink 创建流程。
- 不新增 AI / provider 调用，不把默认名写进任何文档内容。
- 不把 `Tab` 变成接受键，不为预填引入新的键盘层或 escape 层。

  `src/bindings/**`、`src/settings-panel.ts`、`src/tree.ts`、`src/main.ts`、`src/copy-data.ts`
  与 `文案-Copy.md`、视觉桩与视觉场景、真机验收场景 728。
- 关联约束：`openspec/project.md` 的「配置即数据」与性能合同；`REVIEW.md` 的「同一语义两处

## 待裁决点

1. **配置域**：推荐 `editor.prefill_note_name`（新建文件是编辑器 / 文件树行为），面板仍按
   Alex 合同放在「自动化」节；不塞进 `harness`（避免把非 AI 偏好归到对话运行时）。
2. **撞名递增的可见范围**：自动编号只看当前已加载的同级条目；惰性目录未取回的子条目不可见，
   此时默认名可能撞上后端已存在但前端未见的名字——由后端拒绝并在行内回显，用户改名即可。
   推荐接受这个边界，不为它引入一次目录枚举或异步等待。
3. **生效时机**：推荐保存后立即生效（保存成功快照回传），不要求重启；与图片命名的方向不对称
   不同，本开关没有「打开需要重启」的理由。
