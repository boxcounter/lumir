# 承接清单：`REMOVED + 新名 ADDED` 的旧块 → 新块逐项核对

本 change 的两条旧 requirement 因**场景标题随语义改裁失效**，走 `REMOVED + 新名 ADDED` 的改名
通道（原因与先例见 `specs/keymap-commands/spec.md` 头部）。机器门禁在这条通道上只查结构：

- `scripts/openspec-archive-check.mjs` 对 REMOVED 只判「旧条在 living 里存在」，对 ADDED 只判
  「不与 living 同名」；
- `--archived` 只核新段落是否落进归档后的 living；
- 它**不比较旧块与新块的正文 / 场景**——对本 change 的实测口径就是 `0 条 MODIFIED / 对比 0 段`。

因此这份清单是「无静默丢合同」的人工判据：**reviewer 出 verdict 前 MUST 逐项核对并签字**
（`tasks.md` 的 10.2 / 10.3）。旧块共 13 个正文段落（7 + 6）与 20 个场景（11 + 9），全部有对应
物；没有删除任何旧场景，改名只发生在语义已不成立的 4 个标题上。
