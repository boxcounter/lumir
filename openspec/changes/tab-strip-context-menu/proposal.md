# Proposal: 标签栏右键菜单（三条关闭路径）

- Change ID: tab-strip-context-menu
- 日期: 2026-09-27
- 角色: Alex Lee（评审/裁决），AI agent（起草）

## Why

Alex 2026-09-27 原话：

> 「新需求：1. 鼠标右键点击 TAB 时增加三个关闭功能：Close、Close Other Tabs、Close Tabs to the Right」

现状里标签的关闭只有两条路径：标签上的 × 按钮，与 ⌘W（关前台标签，且要绕开 macOS 原生菜单的预置项——`src-tauri/src/lib.rs` 把它换成自定义项，经 `app:menu_command` 转发）。**关闭一组标签没有入口**：打开十个文件后想只留一个，只能逐个点 ×，每个脏标签还要各自走一次确认。

同批的 change `preview-tab-removal` 让单击树文件不再互相顶掉标签（标签会累积），这批关闭入口因此从「锦上添花」变成必要件：**打开不再有隐藏语义，关闭必须有显式入口**——两者是同一条交互的两半。

菜单形态沿用 M244 文件树条目右键菜单那一套（web 自绘浮层：`role=menu` + 项级 `role=menuitem`、↑↓ 与 ⌃N⌃P 导航、Enter 触发、Esc / 外部点击关闭、打开即持焦点、关闭归还焦点），不引入原生菜单（原生菜单的项要经 Rust 侧定义与 IPC 回传，且右键坐标在真机会话里有不可达前科，浮层是可控的那一半）。

## What Changes

1. **右键标签弹出关闭菜单**：三个项，文案取 Alex 给的英文原文对应的上屏中文（Close → 关闭、Close Other Tabs → 关闭其他标签、Close Tabs to the Right → 关闭右侧标签；英文原文逐字入文案 deck 的 English 列），顺序即上表顺序。
2. **三条路径的语义**：
   - **关闭**：关掉右键落在的那一个标签；
   - **关闭其他标签**：关掉除它以外的全部标签（本版没有 pinned 概念——标签只有一种形态，因此不做任何保留，语义按现状最小实现）；
   - **关闭右侧标签**：关掉标签栏里排在它右侧的全部标签（与浏览器同口径，锚点是右键那一条，**不是**当前激活项）。
3. **右键不改上下文**：右键 MUST NOT 切换前台标签（与文件树菜单同一条口径——右键即改选中的代价不对称；且「关闭右侧」需要一个不由激活项决定的锚点）。
4. **脏标签复用 M149 的既有确认**：三条路径命中脏标签时一律弹 M149 的 sticky 确认浮条（保存并关闭 / 放弃修改并关闭 / 取消，文案 D92 / D93），MUST NOT 新造确认 UI。批量路径**逐个问、逐个关**：一次只弹一条确认，用户取消（或点掉浮条）即停手，后面的标签不动。
5. **spec 增量**：`multi-tabs` 新增一条 requirement「标签的关闭操作」。

## Non-goals

- **不做「关闭左侧标签」/ 「关闭全部」**：Alex 只点了三项；多一项就是多一个需要确认文案与快捷键的入口，等有人要再加。
- **不做菜单项的禁用态**（右侧没有标签时把「关闭右侧标签」置灰）：三项都是幂等的（没有可关的就是空动作），禁用态需要「菜单打开时重算可用性」这条额外的状态，本版不做。
- **不做标签拖拽排序 / split view / 标签预览浮层**：`multi-tabs` 的既有禁令原样保留。
- **不给菜单项加速键 / 不进 keys.ts 的统一键位表**：菜单的就地键（↑↓ / ⌃N⌃P / Enter / Esc）与文件树菜单同口径——那张表的不变量是「一个 token 一条绑定」，这些 token 已被 editor 作用域占用；菜单非模态，Tab 等键照走原生路径。
- **不改 × 按钮与 ⌘W 的行为**：单标签关闭的两条既有路径一个字不动（它们与菜单的「关闭」同落到 `closeTab`）。
- **不把两处菜单抽成共用底层**：理由见 design §二（文件范围 + 项集模型差异），共用的是**皮肤**（`src/style.css` 里 `.ft-menu` / `.tab-menu` 的选择器对）。

## Impact

- 影响的 specs：`multi-tabs`（一条 ADDED）
- 影响的代码/系统：`src/tabs.ts`（菜单浮层 + 三条路径的落点 + 批量关闭的顺序控制）、`src/main.ts`（`toast` 增一个「浮条被点掉」的回调口）、`src/style.css`（`.tab-menu*` 进入共用皮肤的选择器对）、`文案-Copy.md`（D148–D151）
- 关联约束：ADR 0002 §3（webview 不直接触文件系统——本 change 零文件系统动作）；ADR 0006（键位与入口形态：菜单不进统一键位表，理由如上）；真机验收套件场景 50 随本 change 同 PR
- 视觉基线：新增一处元素级基线（菜单浮层），归 M254 的过目包；标签栏的既有元素基线不受影响（菜单只在打开时存在，且挂点是 app-shell 根而非标签栏）
