## Why

**唯一「不改 JSON 就完不成」的用户任务，仍然没有界面。** 配置面盘点（50 个叶键）结论：
零设置页；首次接入模型所需的 `api_key` 与 `models[]` 没有任何界面，现有出口是三句把用户
指向 `config.json` 的文案（D402 / D403 / D404）。用户第一次打开 Lumir 想发一句话，必须
先手写一段 JSON。

**手改的代价比「配置多」更硬。** 50 个键里有 **41 个**在类型写错时会触发**整份配置回落
默认**——`last_vault` 一起丢，下次启动要重新打开 vault（`config.rs` 的解析模型：
表内类型不符 → serde 解析期失败 → 整文件回落；config-reference §2 有同口径说明）。
纯数值 / 布尔输入框只要把 `"font_size": 15` 打成 `"15"` 就命中这条路径。

**四个默认开启的自动行为没有可见面。** `auto_compact`、`session_naming.enabled`、
`attachment_naming.enabled`、`subagents.enabled` 出厂全开，其中图片命名会把图片字节与
前后各 500 字送出本机（`attachment_naming.rs:42-43`），子代理是唯一的花钱开关。
四个开关都只能手改配置文件——「默认开 + 会出域 / 花钱 + 无可见面」是本轮唯一同时成立的组合。

**现有写通道有三个硬缺口，设置页必须先补齐：**

1. **写通道不校验取值**（`commands.rs:606-613`）：`config_set_value` 把任意 JSON 值直接
   合并进文件，「非法值由下次启动的 `validate()` 兜」——设置页如果把一个字符串写进数值
   字段，下次启动就是整份配置回落。
2. **没有删键能力**（`commands.rs:637-703` 只做 merge）：所以「恢复默认」当前只能是「把
   默认值写死」而不是「删掉这个键、跟随默认」；config-reference §3 明确反对把默认值写进文件。
3. **`config_get` 只返回生效值**（`commands.rs:112-114` → `validate()`）：分不清「键缺席」
   与「显式写成默认值」；数组里的未知子键不可见；被丢弃的坏项也看不见。

**配置 warning 至今没有 UI 出口。** `main.ts:4135` 只写 console + 诊断日志；
`ConfigSnapshot.warnings` 没有界面消费者。设置页是它天然的第一个出口，但前提是 warning
带得上「属于哪个键」的结构——现在只有人话字符串。

**同批要收口的三个规格 / 实现漂移**（盘点 §7，均可复核）：

- `models[]` 的元素 schema 没有 living spec（config-reference §1.5 把它委托给 harness
  spec，而那条没列 models）。
- 模型声明指引四处漏 `vision`（`config.rs:3141`、`harness/llm.rs:618`、D402、D404）；
  `vision` 是图片发送与图片命名的唯一依据。
- 模型 chip 的 provider 选项恒为 kimi + deepseek，而 living spec 写的是「已配置的
  provider」（`harness/spec.md:623` vs `harness-panel.ts:1566`）：`HarnessProviders`
  三个字段恒序列化，前端 `id in configured` 永远为真。设置页会让「已配置」第一次成为
  用户能改变的事实，这条口径必须先定准。

## What Changes

|---|---|---|
| A 设置面板 | `⌘,`（或应用菜单「设置…」）打开一个模态面板，只有「模型接入」与「自动化」两节；其余配置不出现在这里 | 新增 capability `settings`：面板形态与范围 |
| B 模型接入 | 每个网络 provider 一张表单：API Key（掩码、可替换 / 清除）、模型清单（id / effort / vision / window 逐行编辑）、高级区（Base URL、Wire 方言）；Base URL 旁常驻「密钥会发往该地址」警示 | `settings`：模型接入编辑面；`harness`：模型清单声明、图片能力指引 |
| C 安全写通道 | 保存 = 一次强类型 patch：后端校验、冲突检测、原子写、按需删键；UI 不做取值校验，也不承担整文件回落风险 | `settings`：设置写通道 |
| D 自动化开关 | 四个开关逐项可见，带默认值、生效时机、出域 / 费用说明；图片命名的「关→开需重启」不对称显式写出 | `settings`：自动化开关 |
| E 校验与警告 | 字段级错误、配置级 warning、整文件回落 / 文件损坏横幅、保存状态；warning 带键路径，不靠字符串匹配 | `settings`：校验与警告呈现 |

| G 入口 | 命令 `app.settings-open`，默认 `⌘,`；应用菜单「设置…」是同一个命令的鼠标路径（不带 accelerator，不制造第二套键位） | `keymap-commands`：设置面板入口 |

### A · 面板形态与范围

- **模态面板**，形态与既有键位查看面板（`⌘/`）同族：全屏遮罩 + 居中卡片，打开即完整可见、
  不越出视口（`docs/specs/overlay-visibility.md` O1/O2），关闭后焦点交还来源。
- **只放两类内容**：模型接入（B）与四个自动化开关（D）。主题、语言、字号、栏宽、权限模式、
  忽略规则、cron、键位等一律**不搬进来**——它们各有更近的使用位置（modeline / chip / 拖拽 /
  权限浮层 / 配置文件），搬进来只会让同一读数出现两处（盘点 §6）。
- 面板头部固定显示配置文件路径；API Key 字段旁常驻一句「`api_key` 以明文存储在该文件中」。

### B · 模型接入

- 顶部按 provider 切换（`kimi` / `deepseek`；`mock` 是验收专用档，不出现在设置里）。
- **基础区**：API Key + 模型清单。
  - API Key 是掩码输入：**已配置的 Key 永不回显**（`config.json` 里本来就能读到，但界面
    不把它当可复制字段）；只显示「已配置 · …末 4 位」或「未配置」，提供「替换」「清除」。
    字段旁常驻一句明文存储说明（Alex 已裁：掩码输入、明确明文存储）。
  - 模型清单逐行编辑四个字段：`id`（文本）、`effort`（开关）、`vision`（开关）、
    `window`（整数，tokens）。行可增删；保存前不允许空 id、重复 id、越界窗口。
- **高级区**（默认折叠）：Base URL + Wire 方言。
  - Base URL 为空 = 用官方地址；自定义值旁**常驻**一句「带密钥的请求会发往该地址」——
    这是「密钥目的地」警示，不是普通表单提示。
  - Wire 方言是选择控件：`responses` / `chat_completions`；`deepseek` 的 chat 档在 v1
    未实现，选项置灰并说明（不让用户选一个会被装载期回落的档位）。
- 每个字段（含两个高级项）在「键显式存在」时提供「恢复默认」——语义是**删键**，不是写死默认值。

### C · 安全写通道（本 change 的硬骨头）

设置页不复用「前端取整份配置 → 改 → 整份写回」的形态。它是一组**窄接口**：读一份只含设置面的
快照，写一次只含改动字段的 patch，校验与落盘全在 Rust。

四条不可妥协的边界：

1. **类型安全在 IPC 边界**：patch 是强类型结构（ts-rs 导出），未知字段拒绝；前端没有机会
   把字符串写进数字字段。这是「整文件回落」这条路径在设置页上的**结构性**关闭，不是靠 UI
   小心。
2. **校验单一来源**：合法性与 warning 都出自 Rust 的同一套 `validate()` 判据；前端只渲染，
   MUST NOT 在 TS 复制窗口区间、枚举表或互斥关系。UI 需要的默认值与能力矩阵（官方 base_url、
   wire 档支持情况、窗口上下限）由快照下发。
3. **写前可证「不会引入回落」**：patch 合并到当前文件的 raw JSON 上后，先按装载同一条解析
   路径校验一遍；任何**新增的阻断级诊断**（类型 / 结构 / 未知字段 / 重复 id / 窗口越界）
   出现即整笔拒绝，文件逐字节不变。文件本身已经解析不了时，设置页只读、保存禁用，并给出
   解析错误位置——MUST NOT 在不可 round-trip 的文件上盲写。
4. **多写者与冲突**：读—校验—写在同一把配置写锁内完成（复用 `update_json_atomic` 的锁与
   原子替换，不新增第二套落盘实现）；patch 携带「设置面 revision」，与锁内现读的文件比对，
   不一致即返回冲突，由用户选择重新载入或以本页为准。未知子键在模型清单里按 `id` 保留，
   保存不会静默丢掉未来版本写的字段。

### D · 自动化开关

四个开关逐项呈现：名称、一句行为、生效时机、敏感性（费用 / 出域），以及「当前是默认值还是
显式设置」。默认值全部为开。

| 开关 | 配置键 | 生效时机 | 敏感性 |
|---|---|---|---|
| 自动压缩 | `harness.auto_compact` | 下一回合 | 费用（多一次模型调用） |
| 会话命名 | `harness.session_naming.enabled` | 下一轮完成后 | 出域（会话内容送 provider） |
| 图片命名 | `harness.attachment_naming.enabled` | 关→开需重启；开→关立即 | 出域（图片字节 + 前后各 500 字） |
| 子代理 | `harness.subagents.enabled` | 下一回合 | 费用（唯一的总开关） |

- 两个命名开关的 provider / model 细项**不搬进设置页**（低频、依赖 models[]，留在配置文件）；
  它们失效时产生的 warning 由设置页的警告区展示，不让用户以为开关本身就是全部。
- 图片命名的重启不对称必须在行内写出，不能只说「需重启」——开→关是立即的。

### E · 校验与警告呈现

- **字段级**：保存失败时错误回填到具体行 / 字段（`aria-invalid` + 关联错误文本），焦点落到
  第一个错误。
- **配置级**：只显示**设置面范围内**的诊断（模型清单为空、当前模型不在清单、命名目标无效、
  wire 档回落……），带键路径；不把 theme / editor 之类的无关 warning 倒进这个面板。
- **文件级**：整文件回落或 JSON 解析失败时，面板顶部横幅说明「当前生效的是默认配置」或
  「文件无法解析」并给出路径 / 行号；后者禁用保存。
- **保存状态**：未修改 / 有未保存修改 / 保存中 / 已保存 / 需要修正 / 外部冲突，经 polite
  live region 宣告。

### F · chip 与声明指引收口

- `HarnessProviderConfig` 增加后端计算的 `configured` 读数（`api_key` 非空 **且** 模型清单
  非空），模型 chip 的选项 = 已配置 provider ∪ 当前 provider（仍是闭集合内、仍隐藏 mock）。
  前端 MUST NOT 用「键是否存在」推断已配置——那正是今天恒真的原因。
- D402 / D403 / D404 三句从「去 `config.json` 手写」改为「去设置面板」；三句的字段清单补
  `vision`（与 `effort` / `window` 同列）。
- `models[]` 的元素 schema 补进 harness living spec（`id` / `effort` / `vision` / `window`
  的缺省与非法口径）。

### G · 入口

- 命令 `app.settings-open`，作用域 `global`，默认 `⌘,`（macOS 惯例；表内与原生菜单均无占用）。
- 应用菜单加「设置…」一项，点击走既有 `MENU_COMMAND_EVENT` 到同一个命令；**不带 accelerator**
  ——否则 `[keys]` 重绑之后菜单仍会触发原键，制造第二套键位（与 Undo / Redo 菜单项让出 ⌘Z
  同一条纪律）。
- 不加常驻 modeline 钮：面板是低频目的地，chrome 退后（design brief 原则 2）；发现路径 = 菜单 +
  `⌘/` 键位面板。

## Non-goals

- **不把其余配置搬进设置页**：主题 / 语言 / 字号 / 折行 / 栏宽、权限模式与规则、vault 忽略
  规则、键位表、cron 任务、日志等级、`editor.*` 一律维持现有落点或仅配置文件。设置页不是
  「配置总览」，也不做成通用 schema 表单（`describe-config` 面板仍是 backlog 里另立项的中期能力）。
- **不做系统钥匙串 / 加密存储**：`api_key` 继续明文存 `config.json`（Alex 已裁），设置页把
  这一点写在字段旁；改钥匙串是另一个 change，且会推翻「配置即数据、人可读可改」的当前取舍。
- **不做 `cron.tasks` 编辑器**：对话式注册已是它的入口。
- **不做 per-vault 设置**：本页全部是全局配置。
- **不新增 provider / 不做模型目录**：仍是 `kimi` / `deepseek` 两家 + config-only 模型清单，
  不恢复任何内置模型表。
- **不热重载启动期配置**：本页只覆盖「每回合 / 每轮 / 每次粘贴现读」的键，唯一的重启提示是
  图片命名关→开；不为设置页引入文件监听。
- **不改模型 chip 的视觉形态**：只改选项口径与空态去向；不重做选择器浮层。
- **不碰权限浮层、不碰 harness 其他 UI**：`permissions.deny`、`loop_max` 等仍只在配置文件。
- **不做「配置回滚 / 备份 / 历史」**：冲突处理只到「重载 / 以本页为准」。
- **不重构 `config_get` 的暴露面**：它仍返回完整生效配置（含 `api_key`）。设置面改用独立快照
  （只回末 4 位），但收窄既有命令的契约会影响启动装配与既有面板，须另立 change。

## 裁决点（本提案新增）

每项给倾向；Alex 只否掉不同意的项即可。编号 Q 与 design.md §13 一一对应。

- **Q1 面板形态与入口**：模态面板（`⌘,` + 应用菜单「设置…」，不加 modeline 钮）还是独立全窗页？
  **倾向模态**：与 `⌘/` 键位面板同一族，打开即可对照底层界面；全窗页要新增导航与「返回」语义，
  对一个只有两节的页面过重。菜单项不带 accelerator 是为了让 `[keys]` 重绑仍然有效（见 G）。
- **Q2 保存模型**：显式「保存 / 取消」（草稿态）还是逐字段即时写？
  **倾向显式保存**：模型清单是多行结构，逐行即时写会在用户还没填完 window 时写入半条；
  且「保存状态」本身就是需要被看见的信息（见 E）。
- **Q3 `api_key` 的已配置提示**：只显示「已配置」，还是显示末 4 位（`…3f9a`）？
  **倾向末 4 位**：文件本来明文可读，末 4 位不增加实质暴露，但能区分多把 Key、确认替换是否
  成功。无论哪种，完整 Key 都不回显。
- **Q4 半配置（有 Key、无模型）是否阻断保存**：**倾向阻断**——「接入」的完成态是可用，
  半配置保存后模型选择器为空、发送报错；阻断时给两条出路（加一个模型 / 清除 Key）。
  备选：仅警告放行（允许先存 Key、稍后补模型）。
- **Q5 外部修改冲突**：阻断保存并给「重新载入（丢弃草稿）」与「仍然保存（以本页为准）」，
  还是静默覆盖？**倾向阻断 + 两个显式动作**：设置页打开期间用户可能在别处编辑同一文件；
  静默覆盖会丢别人的改动。
- **Q6 模型清单里的未知子键**：按 `id` 匹配保留（未来版本写的字段不被旧版 UI 洗掉），
  还是整表替换、未知键丢弃？**倾向保留**：整表替换是「旧 UI 降级写回」最典型的静默丢数据
  场景；重命名 `id` 视为新条目、旧键不跟随，这一点在 design 里写死。
