# Design: Quick Open 高亮项必须等于 Enter 目标

## 1. 不变量

**同一输入、同一时刻**：

1. 若结果区高亮某一行，则 Enter 打开的目标就是该行对应的文件 / 目录（目录行 = 进入下一层）。
2. 若 Enter 打开的是候选之外的精确路径（索引外惰性文件、vault 外绝对路径、超出渲染上限的候选），
   结果区 MUST NOT 高亮任何行，`aria-activedescendant` MUST 缺省。
3. `aria-selected` / `aria-activedescendant` 与 `.is-active` 指同一行；至多一行。
4. 两段式（折叠多命中 / 裸目录）的第一次 Enter 只揭示、不打开，第二次 Enter 起受第 1 条约束。

不变量按**判决形态**成立，而不是按「有没有候选」成立：候选存在但判决路径不在其中时，仍然不得用
首行冒充。

## 2. 起点策略（纯函数 `quickOpenStartIndex`）

`quickOpenStartIndex(resolution, rows)` 返回渲染出的 `rows` 下标（-1 = 无高亮）：

| 判决 / 状态 | 起点 | Enter 目标 |
|---|---|---|
| `open`，判决路径是真实候选 | 该行 | 判决路径（带行号则落行） |
| `open`，判决路径不在候选里 | -1 | 判决路径（direct-only） |
| `undecided`（目标未定：探测在途或待发起） | -1 | 探测落地后重判：命中 ⇒ 候选外精确路径；不成立 ⇒ 首行 |
| `missing` / `invalid`，有候选 | 首行 | 当前游标行 |
| `ambiguous` / 目录语境 | 首行 | 两段式的第二次消费当前游标行 |

`rows` 为空一律 -1。目录语境优先于判决形态（`dir` 判决同时带 directory 上下文）。

**为什么判决未定不亮**：`undecided` 只说明「这条查询串既不在索引里、也不是目录」，它有两种结局
——探测命中（Enter 打开候选之外的精确路径）或探测不成立（Enter 落到首行）。两种结局在探测落地前
分不出来，先亮首行就是在**有直接打开可能**时替一个可能被推翻的目标作保。`path:line` 的阶梯、
「候选为空」与「普通子串查询」在这一点上没有区别：普通查询串同样可能恰好是某条索引外文件的精确
路径（被忽略规则挡在枚举之外、但仍在 vault 内），而它按定义不会出现在候选里（在索引里就会同步
命中）。因此探测对**每一个未定判决**发起。

**为什么这不缩水普通搜索**：探测在输入停稳 120ms 后才发一次，且只探当前查询串（普通查询是一次
单路径往返，`path:行` 沿既有阶梯至多两级；不是逐键 IPC）。这份判决由结果区补帧与 Enter 共用
（`resolutionFor`：已落地复用、在途加入），停驻后的 Enter 不再重复探测。落地为「找不到」后按上表
回到首行——普通搜索的默认承诺（首行 = Enter 目标）在判决明确之后照旧成立。落地为可打开时 Enter
打开那条精确路径，候选列表不做任何视觉伪装。代价是普通查询的高亮比输入晚一个去抖窗口，这是
「未定期间不作错误承诺」的直接结果。

## 3. 实现落点

- 行构造收口为 `quickOpenCandidates(resolution, files)`（普通候选按索引序、目录候选按一层扫描序），
  DOM 与测试共用同一份，MUST NOT 在测试里另写一份行映射。
- `apply()` 用 `quickOpenStartIndex` 取代 `setActive(0)`；异步补帧的「按行身份保位」由纯函数
  `quickOpenCursorIndex` 收口（保位行在新候选里消失时回落到策略起点，不再无条件回首行）。
- `shouldProbe` 对每个 `undecided` 判决返回真：探测是判决落地的唯一途径，也是「未定期间不承诺」
  能收尾的前提。去抖见 `PROBE_DEBOUNCE_MS`。
- `confirm()`：先取与结果区**同一份**判决（`resolutionFor`：已落地复用、在途加入，输入改变才重新
  探测），再把游标同步到该判决的起点。用户主动移动过 ⇒ 打开游标行（既有语义，`open` 判决同样适用）；
  例外是游标行**就是判决路径本身**（例如探测在途时按 ↓ 落在唯一候选上）——此时仍走 `openDirect`，
  保住 `:行` 落点（行与目标同一文件，「只打开游标行」不被违反）；若改走 `openRow`，一次光标微动就会
  静默丢掉粘贴时给的行号。未主动移动时**先按策略把游标同步到该判决的起点**（判决行 / 清空 / 首行），
  再按判决动作；同步对所有判决形态生效，因此被抑制的游标不会让「有候选」误报成「找不到」。同步只改
  游标，不重建行、不改提示。
- `resolutionFor(raw)` 是判决的唯一入口，也是「一次停驻一次探测」的收口：`settled` 命中同一原文 ⇒
  复用、`inflight` 命中 ⇒ 加入同一 promise、都没有 ⇒ 发起一次。`settled` / `inflight` 只在
  `dismiss()`（关闭浮层）与 `enterDirectory()`（换了输入）时清空；**清空输入不清**——`raw === ""`
  的渲染走早退分支，不碰这两个变量（这正是「离开再回到同一输入」能复用的机制，见 §6）。
- `move()` 的 `userMoved` 语义不变：钳制到边界（位置没变）不算「移动过」，此时 Enter 仍走精确路径。

## 4. 与既有合同的关系

- **direct action 伪候选**：仍不生成、不占列表 / ARIA / 鼠标入口 / 渲染上限；本 change 不新增任何
  视觉行来解释目标。
- **目录**：裸目录两段式、尾斜杠一次接受、进入子目录后游标复位首行——全部不动。
- **折叠多命中**：第一次 Enter 只揭示、第二次打开游标行——不动；起点仍是首行。
- **lazy / vault 外**：判决可打开、没有对应候选行 ⇒ 不高亮，Enter 仍打开 / 只读打开——能力不缩水。
- **异步迟到**：`renderSeq` + 输入原文丢弃迟到结果；用户移动过游标时按 `quickOpenRowKey` 保位——不动。

## 5. 判据与证据

- 纯函数矩阵（`tests/unit/quick-open.test.ts`）：唯一候选、多候选（判决行不在首位，含折叠等值
  第二位的现场）、direct-only（有其它候选 / 零候选）、判决未定（普通过滤 / `path:line`）一律 -1、
  探测落地为 `missing` ⇒ 首行、角落（普通查询 = 索引外精确路径且是其它候选子串）判前判后都不亮、
  异步保位与「保位行消失 ⇒ 策略起点」、目录 / 多命中 / 找不到 / 空行。
- 浏览器矩阵（`tests/visual/scenes/quick-open-active-target.spec.ts`）：每条同时读高亮行文本、
  `aria-selected` / `aria-activedescendant`、以及打开后的文档 marker 与光标行号（`expectActiveRow`
  另断言全列表至多一行 `aria-selected=true`）；角落用例用带延迟的探测桩把「在途」与「落地」两段
  分别钉住。**探测次数是判据的一部分**：普通查询停驻后恰好 1 次、停驻后的 Enter 不新增；`path:行`
  沿既有阶梯恰好 1 次、Enter 不新增（`probeAnswers` 逐次计数，不是 `>0`）。
- 先红后绿：新判据在旧实现上跑红（浏览器矩阵 1 红 = 角落用例；纯函数探针在旧实现返回 0、修后
  返回 -1），实现后全绿；红绿日志落 `.local/missions/quick-open-active-target/`。
- **探测次数的两个边界各有专门用例**（都是「发起次数」与「应答次数」双计，不是 `>0`）：
  ① 输入后 <120ms 立即 Enter——Enter 先发起那唯一一次，停驻计时器到点后加入在途 promise；旧实现
  这里会变成 2。② 离开再回到同一输入——清空后重输同一串直接复用旧判决，回到时高亮同步到位（一次
  读 `.is-active`，未定实现这里是 0），并在离开期间 re-stub 探测桩（模拟盘上新增同名文件）：不发新
  探测、不重新验证，Enter 仍打开旧判决的游标行。
- 既有 42 条（`quick-open.spec.ts` + `quick-open-directory-stable.spec.ts`）随行为变化更新一条
  时序断言（普通查询要等探测落地后再按 ↓），其余逐值不变。

## 6. 已知边界

- vault 外普通文件路径的存在性仍只在按下 Enter 之后才被证实（既有边界，不依赖任何视觉行）。
- 普通查询的高亮比输入晚一个去抖窗口（120ms）+ 一次探测往返：这是「判决未定不承诺」的代价，
  不是可消除的抖动——探不到就不知道 Enter 的目标。
- **`settled` 只按输入原文键控**：同一浮层内清空再回到同一串复用旧判决——不再探测，返回时高亮
  立即到位（中途若有另一条输入已落地判决，记忆会被它替换，回到旧串就重新探测）；**外部文件 /
  索引在探测之后的变化不在复用点重新验证**（复用是「停驻后 Enter 不重复探测」的直接代价，Alex
  已批准该方向）。因此在浮层开着时新建一条恰好等于当前查询串的文件，要关闭并重开浮层
  （`dismiss()` 清空 `settled` / `inflight`）才会被识别；进入目录换了输入同样复位。
  这是有意的取舍，不是遗漏：每次回到旧串都重探等于放弃 ④ 的复用，用户感知到的会是一次无谓的
  往返延迟。
