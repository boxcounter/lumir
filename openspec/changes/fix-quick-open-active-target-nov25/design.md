# Design: Quick Open 高亮项必须等于 Enter 目标

## 1. 不变量

**同一输入、同一时刻**：

1. 若结果区高亮某一行，则 Enter 打开的目标就是该行对应的文件 / 目录（目录行 = 进入下一层）。
2. 若 Enter 打开的是候选之外的精确路径（索引外惰性文件、vault 外绝对路径、超出渲染上限的候选），
   结果区 MUST NOT 高亮任何行，`aria-activedescendant` MUST 缺省。
3. `aria-selected` / `aria-activedescendant` 与 `.is-active` 指同一行；至多一行。
4. 两段式（折叠多命中 / 裸目录）的第一次 Enter 只揭示、不打开，第二次 Enter 起受第 1 条约束。

不变量按**判决形态**成立，而不是按「有没有候选」成立：候选存在但判决路径不在其中时，仍然不得用
首行冒充。

## 2. 起点策略（纯函数 `quickOpenStartIndex`）

`quickOpenStartIndex(resolution, rows, { probing })` 返回渲染出的 `rows` 下标（-1 = 无高亮）：

| 判决 / 状态 | 起点 | Enter 目标 |
|---|---|---|
| `open`，判决路径是真实候选 | 该行 | 判决路径（带行号则落行） |
| `open`，判决路径不在候选里 | -1 | 判决路径（direct-only） |
| `undecided`，探测在途 | -1 | 探测落地后重判 |
| `undecided`，无在途探测（普通过滤） | 首行 | 首行（探测不成立后进入 missing 分支） |
| `missing` / `invalid`，有候选 | 首行 | 当前游标行 |
| `ambiguous` / 目录语境 | 首行 | 两段式的第二次消费当前游标行 |

`rows` 为空一律 -1。目录语境优先于判决形态（`dir` 判决同时带 directory 上下文）。

**为什么探测在途不亮**：`path:line` 的同步判决是 `undecided`——判决可能是阶梯任意一级（整串字面
文件名 / 剥后缀），探测落地前 Enter 的目标无法确定。先亮首行会在「字面文件存在」与「落到剥后缀
那一级」两种结果里各错一次；不亮是唯一不撒谎的渲染。落地后起点回到判决行（或 -1）。

**为什么普通过滤仍亮首行**：普通过滤不发起探测（`shouldProbe` 只为「候选为空」与「带合法行号后缀」
发起），Enter 的兜底是 `missing` → 当前游标行，首行即真实目标。只有「查询串恰好是索引外文件的精确
路径、同时又是其它候选的子串」这一角落会让 Enter 改判为 direct——该形态要求索引外文件名是索引内
路径的子串（例如被忽略目录下的文件与普通文件同名前缀），现实可忽略；`confirm` 在动作前仍会按判决
同步游标（清掉不成立的高亮），不留下「按了高亮行却打开另一条」的持久错觉。

## 3. 实现落点

- 行构造收口为 `quickOpenCandidates(resolution, files)`（普通候选按索引序、目录候选按一层扫描序），
  DOM 与测试共用同一份，MUST NOT 在测试里另写一份行映射。
- `apply()` 用 `quickOpenStartIndex` 取代 `setActive(0)`；异步补帧的「按行身份保位」不变，行消失时
  回落到策略起点（不再无条件回首行）。
- `confirm()` 的 `open` 分支：用户主动移动过 ⇒ 打开游标行（既有语义）；例外是游标行**就是判决路径
  本身**（例如探测在途时按 ↓ 落在唯一候选上）——此时仍走 `openDirect`，保住 `:行` 落点（行与目标
  同一文件，「只打开游标行」不被违反）；若改走 `openRow`，一次光标微动就会静默丢掉粘贴时给的行号。
  未主动移动时先按策略把游标同步到判决行（或清空），再 `openDirect(verdict)`。同步只改游标，不重建
  行、不改提示。
- `move()` 的 `userMoved` 语义不变：钳制到边界（位置没变）不算「移动过」，此时 Enter 仍走精确路径。

## 4. 与既有合同的关系

- **direct action 伪候选**：仍不生成、不占列表 / ARIA / 鼠标入口 / 渲染上限；本 change 不新增任何
  视觉行来解释目标。
- **目录**：裸目录两段式、尾斜杠一次接受、进入子目录后游标复位首行——全部不动。
- **折叠多命中**：第一次 Enter 只揭示、第二次打开游标行——不动；起点仍是首行。
- **lazy / vault 外**：判决可打开、没有对应候选行 ⇒ 不高亮，Enter 仍打开 / 只读打开——能力不缩水。
- **异步迟到**：`renderSeq` + 输入原文丢弃迟到结果；用户移动过游标时按 `rowKey` 保位——不动。

## 5. 判据与证据

- 纯函数矩阵（`tests/unit/quick-open.test.ts`）：唯一候选、多候选（判决行不在首位，含折叠等值
  第二位的现场）、direct-only（有其它候选 / 零候选）、普通首项、探测在途、目录 / 多命中 / 找不到 /
  空行。
- 浏览器矩阵（`tests/visual/scenes/quick-open-active-target.spec.ts`）：每条同时读高亮行文本、
  `aria-selected` / `aria-activedescendant`、以及打开后的文档 marker 与光标行号。
- 先红后绿：新判据在旧实现上跑红（单测 3 红、浏览器 3 红），实现后全绿；红绿日志落 `.local/missions/`。

## 6. 已知边界

- vault 外普通文件路径的存在性仍只在按下 Enter 之后才被证实（既有边界，不依赖任何视觉行）。
- 普通过滤恰好等于「索引外精确路径」且同时是其它候选子串的角落：见 §2 第三段。
