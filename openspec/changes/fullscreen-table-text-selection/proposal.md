## Why

Alex 2026-10-23 的需求原话（逐字）：

> 「当 table 全屏显示时，可以选中复制」

Alex 2026-10-23 的现场确认（逐字）：

> 「不是，我当时是用鼠标拖选，但没有出现选择块/状态。」

现状是**两类事实**，取证方式不同，不能混谈（读数与来源见 design §1）：

**① 代码结构可证的缺口：`⌘A` 越界（已实测，两个引擎一致）**

- 遮罩持焦时按 ⌘A，选区落在**整份文档**上——标题栏、文件树、**蒙层后面的编辑器正文**都在选区内。
  实测选区长度 chromium 601 字符 / WebKit 627 字符，锚点在遮罩之外；随后 ⌘C 复制出来的是整页内容
  （剪贴板首行是 `scene.md`，不是表格）。代码块全屏同一现象（201 / 223 字符）。
- 机制三环，逐处读过源码：M627 把 Edit 菜单「全选」的原生 ⌘A 加速键让给了前端
  （`src-tauri/src/lib.rs:485`，菜单项保留、加速键刻意不设）→ 前端只给**两个文本面**补了绑定
  `Cmd-a → editor.select-all`（`src/keys.ts:599`），作用域闸对「焦点不在编辑器内容区、也不在
  composer」的事件不消费（`src/keys.ts:1083`）→ 全屏遮罩是第三个能持焦、有可选文本的面，但没有
  任何全选实现 ⇒ 事件落到引擎的文档级全选。

**② 真机实测的事实：拖选没有选区反馈（Alex，WKWebView）**

- 同一次动作在引擎层探针里却有选区：chromium 与 Playwright WebKit（真机同款 UA）都能得到 29 / 32
  字符的选区，⌘C 复制的正是这段文本。**两者的分叉本身就是证据**——Playwright 的 WebKit 不能代表
  真机 WKWebView 的选中行为，因此真机根因**未定位**（候选与判据见 design §2.1，探针见 design §6.1）。
- 其中一条候选已有量化证据：应用的**原生**选区带 `::selection` 取 `--accent-tint`，与遮罩底色
  `--preview-bg` 的对比只有 **1.13:1（light）/ 1.28:1（dark）**，而编辑器里那条**自绘**选区带
  `--sel-band` 是 1.70:1 / 2.05:1。全屏快照是应用里少有的一处「只能靠原生 `::selection` 显示选中」的
  面（编辑器里看到的那条是 CM 自己画的），所以「没有出现选择块」很可能不是「没选中」，而是「选中了
  看不见」（design §2.1 H2）。这一条决定修法可能不在「怎么选中」，而在「选中了要看得见」。

**为什么值得做**：全屏是宽表 / 长代码块唯一能读的形态；选中一段复制出去（贴进对话、贴进文档）是读长表
的自然续动作。今天在遮罩里按 ⌘A，复制出来的是整个应用 + 蒙层后的正文——用户很难察觉自己复制错了。

**实施顺序（由 Alex 的现场确认激活）**：拖选的根因未定位 ⇒ 本 change 的第一步不是写产品代码，是
**真机探针**（tasks §1、design §6.1）；探针结论决定实现面，合同断言跟随探针结论落地，MUST NOT 在探针
之前按猜测打案例级补丁（[rendering-defect-contract-first.md](../../../docs/process/rendering-defect-contract-first.md)）。
`⌘A` 那一半不受影响：根因链已被评审逐环核实，条款与判据可以直接落地。

## What Changes

逐条对应 `specs/editor-live-preview/spec.md` 增量里那条 ADDED requirement（全屏遮罩内的文本可选中可复制）：

1. **遮罩里的「全选」归遮罩**。遮罩持焦期间 ⌘A SHALL 选中遮罩内容（表格快照 / 代码块内容），
   MUST NOT 把选区落到遮罩之外，MUST NOT 移动焦点。该键 MUST NOT 写进统一键位表——就地消费，
   与既有 Esc 同一条先例（表的不变量是「一个 token 一条绑定」，同 token 第二条绑定会被构造期拒绝，
   `src/keys.ts:1010`）。
2. **菜单「全选」同一口径**。Edit 菜单的「全选」项没有加速键、点击经 `app:menu_command` 回到前端
   （`src/main.ts:3220` 的 `selectAllByFocusedFace` 按焦点路由）；遮罩在场时它 SHALL 选遮罩内容，
   而不是蒙层后编辑器的全文。
3. **「可选」从继承值变成契约**。表格快照容器今天没有显式 `user-select`（靠继承来的 `auto` 成立），
   代码块全屏有显式 `user-select: text`（`src/style.css:1881`）——两处口径对齐，快照容器显式声明
   `user-select: text`；遮罩内的 `user-select` MUST NOT 为 `none`。
4. **「选中了要看得见」**。选中态 SHALL 在遮罩底色上可辨——选区带与遮罩底色的对比 MUST NOT 弱于编辑器
   内既有选区带（`--sel-band`）与正文底色的对比；具体取哪档 token 由探针结论决定，MUST NOT 新增色值。
   这一条直接对应 Alex 的「没有出现选择块」：无论真机根因是「没选中」还是「选中了看不见」，它都必须成立。
5. **复制口径 = 浏览器原生纯文本**。不新造 Markdown / TSV 序列化（D4）。
6. **既有退出路径逐条不变**。Esc / 点击遮罩 / 再次 toggle / 焦点离开四条关闭路径、以及关闭后的焦点
   交还口径一字不改；关闭后 MUST NOT 残留可被 ⌘C 复制的遮罩文本（实测现状已满足——关闭时焦点交还
   使 DOM 选区坍缩，写成不变量 + 断言，防回归）。

## 起草期取值（请评审时一并裁）

| # | 取值 | 倾向与理由 | 若你选另一侧 |
|---|---|---|---|
| D1 | 覆盖**表格全屏 + 代码块全屏**两个面 | 实测两处同病（601 / 201 字符的整页选区），根因同一份；只修一个，另一个会在同一天被报同一问题 | 只修表格：代码块面的 ⌘A 仍会选中整页，且两处行为分叉 |
| D2 | 遮罩**就地消费** ⌘A（不写进统一键位表） | 与 Esc 完全同一先例：`editor.widget-escape` 已占 Esc，遮罩仍就地消费（`src/code-block-fullscreen.ts:22` 的头注写明理由）。写进表则同 token 第二条绑定被构造期拒绝 | 走「键位表按面路由」的实现：要给键位层加第三个面的判据，并把 `text` 作用域对遮罩放行、再用 `commandGate` 逐命令收敛——改动面从 2 个遮罩模块变成键位层 + 装配层两处语义 |
| D3 | 菜单「全选」**同口径**（遮罩在场时选遮罩内容） | 不改的话，从菜单点「全选」会选中蒙层后的正文——同一能力两条入口两个结果，用户会以为复制到了表格 | 只修键盘：菜单路径留作已知边界（design §7） |
| D4 | 复制口径 = **原生纯文本** | 最小改动、与编辑器里复制一致；要表格结构的人自然会用块级复制 / 摘录 | 要 Markdown 源或 TSV：那是另一条能力（要定「表格 → 纯文本」的列序 / 转义口径），本 change 不夹带 |
| D5 | 与 M634（harness 块全屏，已合并、待归档）的关系：**实现覆盖、条款分两次** | 两个面共用同一份遮罩模块（`createTableFullscreen` / `createCodeBlockFullscreen`），本 change 的修法对 harness 面**自动生效**；但 `harness` 的那条 ADDED requirement 还在 M634 的 change 里、未进 living spec，本 change 写它的 MODIFIED 会让 `validate --strict` 失败 | 连 harness 条款一起写：必须先等 M634 归档进 living spec，本 change 再补一条 MODIFIED——条款仍被归档顺序绑死 |

## Non-goals

- **不做表格 / 代码块的序列化复制**（Markdown 源、TSV、带列序的纯文本）——D4，另一条能力。
- **不改块级复制与消息级复制**（`block.copy`、harness 消息级复制）的既有口径。
- **不做 harness transcript（非全屏面）的 ⌘A 落面**：同一机制在那一面同样成立（它不是两个文本面之一，
  因此 ⌘A 今天也会选中整页），但它不在 Alex 原话的范围里，本 change 不覆盖，登记在 design §7。
- **不改摘录手势**：遮罩内容不在编辑器 contentDOM 内，摘录钮本来就不响应（现状保持不变）。
- **不改四条关闭路径、焦点交还、单实例语义**。
- **不做全屏内搜索 / 高亮 / 打印**。

## Impact

- **影响的 specs**：`editor-live-preview`（ADDED：全屏遮罩内的文本可选中可复制，含「选中态可辨」一条）。
  `harness` 的同族条款待 M634 归档后另立（D5）。
- **影响的代码 / 系统**：
  - 前端：`src/table-fullscreen.ts` / `src/code-block-fullscreen.ts`（遮罩内 ⌘A 就地消费，各接自己的
    内容根）、新建一个共享助手（`src/overlay-select.ts`：一份「选中某个子树」的实现，两处调用）、
    `src/style.css`（快照容器显式 `user-select: text`；若探针结论是「选区带太弱」则另动 `::selection`
    的取值口径）、`src/main.ts`（菜单「全选」的落面多一档）。
  - 后端：零改动。
- **关联约束**：
  - ADR 0003 §3：全选与复制只读，MUST NOT 改写文档与留存。
  - ADR 0002 §6：全选是一次 DOM 选区操作，零解析、零测量、零新监听以外的运行时成本。
- **范围风险（如实登记）**：拖选的根因未定位。若探针指向跨切面原因（全局 CSS、Tauri 注入脚本、webview
  配置这类），命中 AGENTS.md 的影响面升级线——**停下报 tower → Alex**，不在本 change 里顺手改；
  若结论是 H2（选区带太弱），修法会改三主题的 `::selection` 观感，属视觉变化，需 Alex 过目并按基线
  纪律处理。

## 观测闸三问

- **怎么知道用户用了它**：选中 + 复制是显式动作；dogfood 可感知；无埋点。
- **怎么知道它有效**：在表格 / 代码块全屏里按 ⌘A，选中的是遮罩内容（不是整页）；⌘C 拿到的是遮罩文本；
  真机里拖选**看得见选中带**且 ⌘C 粘出的是表格文本；Esc 关闭后焦点回编辑器、⌘C 不再拿到遮罩里的旧文本。
- **出问题怎么发现**：第一步的**真机探针**（`pnpm tauri dev` + Safari Web Inspector，读数与截图落
  `.local/probes/`）；之后视觉场景守 ⌘A 的**范围**（锚点必须落在遮罩内，配「选区不含蒙层后正文」的
  负向断言）、WebKit 真机同款 UA 的 project 做引擎族回归（不能替代真机，见 design §6.4）；真机通道
  断言不了选区与复制（AX 不暴露选区、⌘C 注入不落地），选中的观感归 Alex 手感裁决。
