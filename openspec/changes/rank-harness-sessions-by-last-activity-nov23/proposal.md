## Why

### 现场：列表里的「时间」不是最后交互

| 取数点 | 位置 | 实际含义 |
|---|---|---|
| `SessionSummary.ts` | `src-tauri/src/harness/session.rs:661-667`；赋值 `src-tauri/src/harness.rs:1121` | 首行 `session_open` 信封 ts = **文件创建时刻** |
| 后端排序 | `src-tauri/src/harness.rs:1127-1128` | session id 字符串倒序；id = `s<unix_millis>-<随机>`，即创建时刻 |
| 前端二次排序 | `src/harness-panel.ts:1288-1297` | 又按同一口径排一遍（REVIEW.md「同一语义两处真源」的形态） |
| 行时间格 | `src/harness-panel.ts:9828-9833` | 显示上面那个创建时刻 |
| `last_opened_at` | `src-tauri/src/vault_registry.rs:83`、`:374-395` | **vault 级**字段，与会话无关，不能借用 |
| `last_activity` | —— | 全仓不存在 |

### 两个直接后果

1. **点开即置顶**。恢复会在内存里铸一个新 session id；新文件在写入 `inherit`（源会话有标题时）
   或 `notice_delivered`（有未投递通知时）时立即落盘，两者都没有时惰性到首次发送才落盘
   （`src-tauri/src/harness/jsonl.rs:520-558` 创建只挂起 `session_open`）。新文件的 id 更新，
   按创建时刻排在列表最前；源文件仍在，于是同一段逻辑会话出现两行同名记录。**这是现有行为，
   本 change 只修排序与行时间，不去重**（见下方范围收缩说明）。
2. **只用不置顶**。一个老会话连续聊了很多轮，id 不变，排序不动；行时间格显示的仍是它被创建的
   那天。

### 范围收缩（必须明示）

最初的提案用 `session_open.restored_from` 谱系折叠，把恢复产生的同名两行合成「链头一行」，以
同时满足「列表只代表一个逻辑会话」。评审判定该方向在 A 档读路径内无法闭合：

- **删除语义**：删链头后父代重新成为链头并出现，与「删除了一个会话」的预期冲突；按逻辑会话
  删除则要扩写路径，A 档不再成立。
- **分支能力**：源文件被折叠后不可再经 UI 恢复，「同一源恢复两次」无法达成。
- **异常谱系**：纯环没有链头，要额外兜底才能保证每文件恰好一行。
- **compact 身份**：压缩文件没有源 id 链接，无法与源文件安全合并。

因此本 change **删除谱系折叠与 M392 同批收口**，改为**每个 JSONL 文件独立一行**；活动时间沿
`restored_from` 链计算，使恢复本身不置顶，但不隐藏、不去重、不合并。

**这条收缩的直接代价**：本 change **不满足**「恢复产生的同名两行合一」这一原始诉求；恢复 / 压缩
产生的多份文件仍各占一行。重复行是现有行为，M392 另立。若 Alex 要求「一行代表一个逻辑会话」，
需要另行设计删除、祖先恢复与 compact 的身份语义，不能靠读路径折叠偷偷实现。

### 为什么仍然值得做

- 排序与行时间格是用户判断「上次聊到哪」的第一眼信号；当前读数在两个方向上都说错。
- 修正只需读路径：列举本来就把每个 JSONL 完整读进内存（首条用户消息、有效标题），再沿
  `restored_from` 链算一个最大值与最早创建时刻，不新增 IO、不写记录、不迁移。
- 每文件一行保留了全部现有操作：源行与恢复行都能独立恢复 / 删除；从源行再次恢复即可形成分支。

## What Changes

### 1. 行身份：一份 JSONL 文件一行

会话清单 SHALL 以 `session_id`（= 文件名）为行身份；每个文件独立一行。MUST NOT 折叠、隐藏、
合并或去重源文件；恢复 / 压缩产生的多份文件各占一行。源行与恢复行 SHALL 各自可恢复、可删除
（活跃会话拒删的既有规则不变）。

### 2. 排序与展示的时间：该文件及其 `restored_from` 链上的最后活动

定义（单一语义，排序与显示共用）：

> `last_activity_ts(file)` = 该文件及其 `session_open.restored_from` 祖先链上、
> `kind ∈ {llm_request, llm_response}` 的记录信封 `ts` 的最大值；
> 链上没有任何轮次时，回落链上**最早**的首行 `session_open` 信封 ts；
> 都没有时为无值。

- 用「最早」而不是「链根」：正常线性链上它等于链根创建时刻；遇到环 / 缺失父时仍然有定义，
  不需要额外的根身份算法。
- 恢复产生的新文件没有自己的轮次时，活动时间继承源文件的最后活动，**不因新文件创建时刻而排到
  活动更晚的会话之前**。
- 同值时按 session id 倒序：恢复行通常与源行相邻（新 id 在上），这是确定性的相邻关系，不是
  「置顶」。

**计入**：`llm_request`（含失败轮、被停止轮、工具循环的每次迭代、点击发起的 cron 运行、唤醒链
自动回合）与 `llm_response`。它们都是一次真实发送 / 产出。

**不计入**：`session_title`（含 `inherit`）、`notice_delivered`、`approval`、`turn_aborted`、
`error`、`loop_limit`、`subrun` 等 sidecar。否则改一次标题、恢复一次会话、投递一条通知都会伪造
活动时间；而 living spec 明文要求「标题变化 MUST NOT 改变清单顺序」。

**不改排序的情形**：被拒的发送（`harness_busy` / provider 缺失 / 图片能力闸——没有
`llm_request`）、无人值守 cron（隔离 runtime，不写交互会话文件）。

### 3. 后端唯一排序，前端只保序

- 排序只在后端 `harness_list_sessions` 一处产生：`last_activity_ts` 倒序 → 同值按 session id
  倒序 → 无值者排最后（同按 id 倒序）。
- 前端 `sessionEntriesOf` **删除**二次排序，保持后端数组序；这条口径收成一处（REVIEW.md
  「同一语义两处真源」）。
- 改名仍走既有原地更新路径，MUST NOT 触发重排。

### 4. 当前会话：自然排序

当前活跃会话 SHALL 按同一排序自然落位，**不钉顶、不加「当前」标记**。理由：它通常本来就是最近
活动的那条；刚恢复还没说话时它继承链上的活动时间、停在原位，不会假性置顶。加「当前」标记需要
快照补一个当前 `session_id`（今天只有 `session_token`），本期不做；删除保护已有
`harness_session_active`。

### 5. 行时间格与浮层行为

- 行时间格改显示 `last_activity_ts`（「上次实际对话是什么时候」）；链上与文件自身都没有可信
  信封 ts 时不显示时间格（延续「不伪造读数」的既有纪律）。
- 会话浮层每次打开现拉现建，天然只读、天然新；**打开期间不实时重排**（否则行会在指针下标位置
  跳动），不轮询、不订阅。
- 同名：不合并、各占一行，行时间格足以区分；悬停提示仍给未截断的全名。
- 标题：每行仍取该文件的有效标题（`inherit` 已使恢复 / 压缩后的标题连续）；不改标题生成与
  回落口径。

### 6. compact：无链，按自身一行

自动压缩开出的新文件只标 `opened_from=compact`，**没有** `restored_from`，因此 MUST NOT 被当作
任何文件的续写链；它按自身活动时间 / 创建时刻落位、独立一行。压缩模板作为回落名、与源文件同名
等残余行为是现有行为，本 change 不合并、不特判。

### 7. M392 另立

「会话浮层快速关→再开重复历史行（M392）」不在本 change 收口：本 change 不删
`docs/backlog.md` 条目、不改删除语义、不做任何去重。M392 另行立项。

## Non-goals

- **不做谱系折叠 / 去重 / 隐藏源文件**：不把恢复产生的两行合成一行；不实现「一行代表一个逻辑
  会话」。这是本期的显式范围收缩（原因见 Why）。
- **不收口 M392**：不删 backlog 条目，不修重复行的渲染来源。
- **不做 B 档（开不落盘）**：恢复仍会在有标题 / 有通知时立即写 `inherit` / `notice_delivered`；
  不停止写 `inherit`、不改 `effective_title` 的读取面、不改「会话本地留存」条。B 档若重开，属
  影响面升级线（session 文件边界语义），另行提案。
- 不新增 `last_opened` / 活动时间记录，不写任何写路径、不做迁移、不回填旧文件。
- 不改删除语义：删除仍只删一个 JSONL 文件；活跃会话拒删不变；不按链删除。
- 不改会话名 / 标题生成 / 搜索 / 分组 / 多选；不新增手动重命名入口；不做链上回落名解析。
- 不给当前会话加钉顶 / 标记 / 独立区段。
- 不做实时排序（浮层打开期间不重排）、不做后台轮询。
- 不改 `session_open`、`llm_request` / `llm_response` 的记录形状；只读既有字段。
- 不改 vault 级 `last_opened_at`，不把它借给会话排序。
- 不引入 compact 链 / compact 合并 / compact 特判。
