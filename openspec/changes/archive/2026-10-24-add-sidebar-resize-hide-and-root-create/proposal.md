## Why

Alex 2026-10-23 的需求原话（逐字）：

> 「左栏：可以通过拖拽调整宽度；可以隐藏，需要有快捷键；在 vault 根下右键，可以创建目录和文件
> （现在只有 Reload）」

后续澄清裁决（同日）：左栏隐藏快捷键用 **⌘B**，按一下隐藏、再按一下恢复显示。

**现状**（起草时逐处读过源码）：

- **宽度是写死的 token**：`src/style.css:220` 的 `--layout-sidebar-w: 236px`；`.app-shell` 的
  网格列读它（`src/style.css:340`），标题栏左侧 traffic 区宽也读它（`src/style.css:374`，
  标识块与原生交通灯因此与侧栏对齐）。没有任何拖拽把手，也没有运行期写入点——用户改不了。
- **没有收起通道**：`.pane-filetree`（`src/style.css:692`）恒在场；统一键位表（`src/keys.ts`
  的 `KEY_BINDINGS`）里没有任何左栏命令，`Cmd-b` 当前无绑定。
- **vault 根右键是死路**：树的 `contextmenu` 监听（`src/tree.ts:449`）只在命中**某一行**时才
  `preventDefault` 并弹自绘菜单；树头部（vault 名那一行）与列表尾部空白命不中行，事件原样交给
  webview，于是弹出 webview 自带的页面菜单——那条 Reload 是**页面刷新**，不是产品能力。
  而「在目录下新建」的能力**已经存在**：目录行菜单的「新建文件 / 新建子目录」
  （`src/tree-menu.ts:95`）就是这件事，根目录只缺一个入口。
- **拖拽改宽的实现先例有两套**：阅读栏宽的对称手柄（`src/content-width.ts:90`，松手写一次
  `ui.content_width`）与 pane 分隔条的指针拖拽（`src/pane-layout.ts:191`）。左栏分隔条与后者
  同形（一条可拖的竖线），持久化与前者同路（`configSetUiValue`，`src/ipc.ts:69`）。

**为什么值得做**：左栏是长期驻留的导航面，宽度是**设备与场景级**的偏好（外接屏 / 笔记本、
是否常看长文件名），写死一个值必然有一半场景不合适。收起则是把宽度让给正文的最小代价，且
必须一按即可逆——这正是 ⌘B 的形态。vault 根的新建入口补的是**结构缺口**：目录行能建、根目录
不能建，用户只能先造一个多余目录或去 Finder 里建，与「本地文本工作台」的定位相悖。

**三条硬保证**（前两条已裁决，第三条是本提案的基线纪律）：

1. **⌘B 来回一键**：一个键同时承担隐藏与恢复，不设第二套「显示左栏」动作。
2. **宽度持久化**：拖完下次启动还是那个宽度；走既有合并写通道，失败只提示不回滚
   （与阅读栏宽 D3 同口径）。
3. **出厂默认宽度保持 236px**：宽度是用户拉出来的，不是我们换掉的口径。既有整页视觉基线因此
   零更新（1200×800 下仍是 236px 骨架）。

## What Changes

逐条对应 spec 增量里的一个 requirement：

1. **左栏可拖拽调宽**（ui-design-system，MODIFIED：应用骨架布局）。侧栏与内容区之间出现一条
   可拖的竖直分隔条（静止态只保留既有的 1px 右侧 hairline，不新增常驻视觉）；拖拽实时重排、
   松手写一次 `ui.sidebar_width`。宽度区间与默认值见「起草期取值」D1。
2. **⌘B 收起与展开左栏**（keymap-commands，ADDED：左栏开关命令与默认键位；ui-design-system
   的同一条 MODIFIED 承载几何与焦点语义）。收起 = 侧栏列宽归 0、标题栏 traffic 区回到
   「原生交通灯 + 产品标识块」的最小宽；展开 = 回到收起前的宽度。焦点在左栏内时收起，焦点
   先交还活跃文档 pane（不留一个「焦点在不可见元素上」的状态）。
3. **vault 根右键新建**（file-tree，ADDED：vault 根的新建入口）。右键落在树的**非条目行**
   区域（树头部 vault 名那一行 + 列表尾部之下的空白）时，弹既有的自绘菜单皮肤、项集为
   「新建文件 / 新建子目录」两条；提交走既有的内联编辑与后端创建链路，行为与目录行菜单逐条
   相同（撞名拒绝、创建后打开文件、不自动展开父目录）。这一区域**拦下 webview 默认菜单**——
   Reload 不在产品语义里，文件树由 watcher 增量维护，没有需要手工刷新的状态。

## 起草期取值（已裁决之外，请评审时一并裁）

| # | 取值 | 倾向与理由 | 若你选另一侧 |
|---|---|---|---|
| D1 | 宽度区间 `[180, 480]`，默认 236 | 180 是「vault 名 + 箭头 + 十来个字符」的下限；480 ≈ 默认值两倍，够放 30 字符的长文件名。默认不动 = 视觉基线零更新 | 若你要更宽的余量（如 600），改两处常量与 Rust 侧区间；超出窗口 40% 的宽度在应用时仍会被运行期钳制 |
| D2 | 收起状态**不跨启动**（每次启动都显示左栏） | 启动就看不到左栏容易被读成「坏了 / UI 缺失」；恢复只差一个 ⌘B | 若你要记住，则与宽度同路落盘（per-vault 或全局二选一，需再裁一档） |
| D3 | 恢复通道**只有 ⌘B**（不加标题栏恢复钮） | 单入口 = 单真源；你自己就是唯一用户，⌘B 已在键位面板可查 | 若担心忘记，可加一个「左栏收起时出现在标题栏左端」的恢复钮（多一个常驻 chrome 元素） |
| D4 | 根菜单项集 = **只两条新建**，不保留 Reload | Reload 是 webview 默认菜单的残留，语义是刷新整个页面；产品侧没有「刷新文件树」的能力（watcher 增量维护） | 若你要保留一条刷新，需要先定义它刷什么（重扫 vault？代价与 watcher 的关系），属另一个能力 |
| D5 | 根新建的命中面 = **树头部 + 列表尾部空白**（两处同一判据） | 与拖拽落点「vault 根」的既有判据同源（M538 已把这两处定义为「vault 根」），用户心智一致 | 若只想在树头部生效，列表尾部空白将退回 webview 默认菜单（同一面板里两种右键行为） |
| D6 | 收起时**不**保留一条边缘把手（悬停唤出） | 与 D3 同一条理由：单入口；且边缘把手是常驻隐形热区，会与「拖拽分隔条」的手感打架 | 若你要悬停唤出，需要先定热区宽度与它和分隔条的优先级 |

## Non-goals

- **不做左栏折叠成图标条**（只做全隐藏）。折叠条要另一套图标语义与宽度记忆，不是本能力。
- **不改文件树的行形态**：行高、缩进、选中 / hover 配色、字体一律不动（`ui-design-system` 的
  「chrome 表面与动效纪律」原样有效）。
- **不做 per-vault 的宽度分档**（一个用户一个宽度；换 vault 不换宽度）。
- **不改拖拽移动条目的既有语义**（M530 / M538 的落点判定不动，本提案只共用「vault 根」这一
  概念）。
- **不新增文件树刷新 / 重扫命令**（D4）。
- **不改 webview 默认菜单在左栏以外区域的处置**（正文、标签条等的右键行为不在本提案范围）。
- **不给左栏加第二套快捷键**（不在本提案里做「聚焦左栏」之类的导航命令）。

## Impact

- **影响的 specs**：`ui-design-system`（MODIFIED：应用骨架布局）、`keymap-commands`（ADDED：
  左栏开关命令与默认键位）、`file-tree`（ADDED：vault 根的新建入口）。
- **影响的代码 / 系统**：
  - 前端：`src/style.css`（宽度 token 的运行期写入点、分隔条与收起态的几何）、`src/shell.ts`
    （分隔条元素与左栏容器 state class）、`src/main.ts`（拖拽编排、⌘B 命令实现、菜单命中面接线）、
    `src/tree.ts`（非行区域的根右键命中）、`src/tree-menu.ts`（root 项集）、`src/keys.ts`
    （`view.toggle-sidebar` 与默认键位）。
  - 后端：`src-tauri/src/config.rs` 新增 `ui.sidebar_width`（区间校验 + 回落 + warning，照
    `ui.content_width` 模板）；`src/bindings/UiConfig.ts` 由 ts-rs 重导出（属预期的漂移面）。
  - 无新 IPC 命令：宽度写盘复用 `configSetUiValue`（`src/ipc.ts:69`）。
- **关联约束**：
  - ADR 0002 §6 性能合同：拖拽每帧重排必须走 rAF 合并、零 IPC，不得掉帧。
  - 视觉门禁：默认宽度不变 ⇒ 既有整页基线零更新；收起态与拖宽态是**新形态**，按「新增场景 /
    如实登记未覆盖」处置（见 design §7）。
  - 仓库信息卫生：视觉场景与验收 fixture 一律合成路径与合成文件名。

## 观测闸三问

- **怎么知道用户用了它**：宽度写盘与 ⌘B 都是显式动作，dogfood 时自己就能感知；无埋点（沿用
  产品零埋点口径）。
- **怎么知道它有效**：拖完下次启动宽度还在；⌘B 一键收起、再按一键恢复且焦点可用；根右键能建
  出文件与目录并自动打开。
- **出问题怎么发现**：机器面兜底——宽度钳制与键盘命令的单测、骨架几何的视觉门禁断言
  （列宽 token 读值、收起后网格列宽、traffic 区位置）、真机验收场景（拖拽 + 重启后宽度、⌘B
  来回、根新建两条）；菜单项集与创建链路有既有单测可扩展（`menuItemsFor` / `menuActionsFor`）。
