# Proposal: md 内容块的「复制」入口（表格 + 代码块）

- Change ID: block-copy-affordance
- 日期: 2026-09-27
- 角色: Alex Lee（评审/裁决），AI agent（起草）

## Why

Alex 需求原话（2026-09-27 晚追加）：**「沿着前面说的 markdown 代码块支持放大查看的需求增加一个需求：
markdown 文件里的表格和代码块支持『复制』。」**

### 一、诉求面：这两类「整块物」的复制今天要手眼配合

表格与围栏代码块是 md 文档里两类**块级整体物**——用户对它们的心智是「这一整块」，而不是「这一段文字」。
但今天的复制动作必须落回字符选区，于是每次都要和渲染形态搏斗：

| # | 现状事实 | 可复核锚点 |
|---|---|---|
| 1 | 围栏行是块内**真实文字**（渲染态把它样式化为头部条，语言标记就是那一行的文字），因此从块首拖选必然把 ``` 与语言标记一起带走 | `src/preview/livePreview.ts:1004-1012`（头部条取 `CodeMark` 所在行）、`src/preview/theme.ts:250-255`（`.cm-line.cm-lp-codeblock-head` 只改样式） |
| 2 | 表格的渲染态是自然宽 grid，装在可横滚容器里：宽表要「滚一段、选一段、再滚一段」 | `src/style.css:1051-1067`（`.cm-lp-table-scroll` 横滚容器）、`:1072-1085`（grid 自然宽） |
| 3 | 表头分隔行（`\|---\|`）在渲染态被 replace 隐藏，但**文档文本里在**——按选区复制拿到的是含分隔行的源码，按屏幕「看到的」理解会以为它是多余的 | `src/preview/livePreview.ts:655-658`（分隔行 line class + `Decoration.replace`） |
| 4 | 「块上浮出一个小钮」这个形态**已经是 Alex 划过稿的**（M235 划稿 → M240 落地，表格全屏触发钮），本 change 不发明形态，只把同一个钮扩到「复制」，并回答「两个钮怎么排」 | `design/prototypes/table-fs-trigger/NOTES.md`（三轴取舍与推荐档 `inside-corners-hover`）、`src/preview/table-trigger.ts`（实现的坐标系与形态纪律） |

结论：本 change 的价值不在「剪贴板怎么读」——那条链路今天已经在；价值在**把「这一整块」变成一个单击动作**，
并让「复制」与刚做完的「放大」在同一个块上**有序共存**。

### 二、剪贴板通道今天已可用，不引插件、不新增 capabilities

「复制完整路径」已用纯前端通道 `navigator.clipboard.writeText`（`src/main.ts:528-551`），
且真机验收场景 47 有逐字剪贴板断言（套件的 `clipboard` 断言形态与 `clipboardRead` 动作，M244）
——**WKWebView 下这条通道已实证**。本 change 沿用它：零剪贴板插件、零后端命令、零 capabilities 增量。

### 三、两条必须在提案里答清的现状（否则实现期会各写一套）

- **复制的内容必须取自文档模型，不能取自屏幕**。渲染态 DOM 里表头分隔行不存在（上表第 3 条）、
  cell 内是渲染后的 inline 形态、被 widget 整块替换的块（mermaid）里连源码行都没有。
  「复制这一块」的正确语义是**复制文档里的那段写法**（用户要粘到别处去）。
- **触发钮的鼠标路径在真机层今天没有判据**。真机场景 40 走的是命令路径（`config.keys` 绑 ⌘J + 键注入），
  hover 触发钮由 chromium 视觉场景覆盖（`tests/visual/scenes/m240-table-fullscreen.spec.ts:146`）。
  本 change 若只给鼠标入口，这条能力在真机上就只剩「坐标点击 + 悬停态」这条未验证通道——
  这是裁决点 5（是否给键盘入口）的主要论据之一。

## What Changes

（以下按裁决点的**推荐项**写；裁决改备选时按裁决点表的「备选」列改写 delta 与 tasks，不静默扩 scope。）

1. **新增「复制」触发钮，与既有全屏触发钮同族同组**：md 模式下，渲染为 grid 的表格与
   （围栏 / 缩进）代码块在 hover 块的可视盒时浮出动作钮群。形态逐值沿用 M235 划稿 / M240 已实现的
   那一套（壳 = `--preview-bg` + 1px `--border`、圆角 r6、26×24、图标 `--text-2` → 热态 `--text`、
   无阴影、`--dur-hover`、eink 黑框反白、**零新 token**）；出现时机 = hover（静止态零足迹：
   不可见、不占位、不进读屏树、不进任何整页基线）。
   **组的不变量**：全屏（放大）钮贴可视盒右上角内侧（`top: 6px; right: 6px`，**即 M240 已实现的
   现状，一字不动**），复制钮贴它左侧（间隙 4px、尺寸相同），组内自左至右为「复制 → 放大」。
   （delta：ADDED `editor-live-preview / 块级复制触发钮`）

2. **复制内容 = 文档里的那块源码，不是屏幕上的那堆 DOM**。
   表格：该表源码的**逐字节切片**（含表头分隔行、含用户自己写的对齐填充与短行写法）；前后不补空行、不追加尾换行。
   代码块：**纯内容**——围栏行与语言标记不在结果里；缩进代码块剥掉「它是代码块」的那层语法缩进、
   保留内容自身的相对缩进；同样不追加尾换行（空块复制空串）。
   机制已核实：lezer md 语法树里，围栏块的 `CodeText` 子节点正好是围栏之间的内容、缩进块的每个 `CodeText`
   子节点**已经不含**语法缩进（探针读数见 [design.md](design.md) §3）。
   （delta：ADDED `editor-live-preview / 块级复制的内容与反馈`）

3. **反馈复用既有 toast 机制**：成功 = success tone（✓ 前缀，与「已复制完整路径」D137 同族），
   文案「已复制表格」/「已复制代码块」；失败（剪贴板不可用 / 权限被拒）给「复制失败：{原因}」并另记一条
   console 线索（M244 同款处置：不借语义不符的诊断事件名）。新文案编号见裁决点后的「文案 deck 登记」。

4. **新增命令 `block.copy`（默认不绑键）承担键盘路径**：caret 落在①一张渲染为 grid 的表内、
   或②一个围栏 / 缩进代码块内时命中并复制该块（内容口径与触发钮逐字相同）；命中条件不满足时
   MUST NOT 消费事件。作用域 `editor`（与 `table.toggle-fullscreen` 取 `global` 的理由不同：
   复制没有「焦点在遮罩里」的第二种状态，命中也必然要求编辑器持焦），默认不绑键并登记进
   `KEYLESS_COMMAND_IDS`（M180 / M240 先例），`⌘/` 键位面板自动列出「未绑定 + 成因」。
   （delta：ADDED `keymap-commands / 块级复制命令`。若裁决点 5 取备选「只做鼠标钮」，本 delta 整份撤掉。）

5. **结构性边界，不加开关**：降级表 / 非矩形表**没有**复制钮（它们没有 grid DOM，源码就在正文里可直接选中
   ——「没有钮」是结构性事实，MUST NOT 加提示或旁路）；被 widget 整块替换的围栏块（mermaid 图表态）
   **没有**钮（块内没有源码行可挂），点图表显露源码后钮随之出现，且命令路径在这两种形态下都仍可用。

6. **点击不改文档**：`EditorState.doc` 与磁盘文件逐字节不变（ADR 0003 §3）、选区与光标落点不变
   （钮的 `mousedown` 显式 `preventDefault`，同 M240 手法）；不新增配置项、不新增 token、`src-tauri/**` 零改动。

## Non-goals

- **不做 TSV / HTML / 富文本多 flavor 复制**（裁决点 1 备选①②③）：若 Alex 要，本 change 内追加一条裁决后改写 delta。
- **不做「复制为纯文本表格」之外的格式族**（CSV / 富文本 markdown 变体 / 带标题的引用块）。
- **不做整块「剪切」**：剪切要改文档（ADR 0003 §3 的边界与撤销语义都要重答），诉求里没有它。
- **不做代码块的「复制行号 / 复制带围栏 / 复制为引用块」等多口味菜单**：一个钮一个动作，
  多口味菜单是另一个形态（裁决点 1 备选②若被选中，也只到「两个钮」为止，不做下拉菜单）。
- **不给列表 / 引用块 / callout / 段落加复制钮**：本 change 的对象是「有渲染态形态的块级整体物」
  （表格是 grid、代码块有头部条），列表与段落没有这个形态，加钮是另一类需求。
- **不动既有全屏触发钮的任何一项**：位置、尺寸、图标、读屏名、`eq` 策略、断言选择器一字不改。
- **不改表格与代码块的渲染口径**：宽度合同、横滚、降级判据、折行开关、着色一律不加不减。
- **不新增配置项、不新增 token、不新增后端命令与 capabilities**：剪贴板走既有纯前端通道。
- **不引入 hover 之外的常驻视觉面**（M235 的 `dim` 档已被否过一次：常驻钮会进所有含表格 / 代码块的整页基线）。

## capability 归属：为什么是 `editor-live-preview` + `keymap-commands`

**结论**：内容与触发钮的增量落 `editor-live-preview`（ADDED ×2）；命令登记落 `keymap-commands`（ADDED ×1）。
本 change **不新建 capability**，`ui-design-system` **零增量**。

理由（与 M240 的 table-fullscreen-view 同一条论证，逐条适用）：复制动作作用的对象是**装饰层的渲染块**
（grid 表 / 围栏块），内容取自同一个文档模型的同一段范围，判据（「哪些块有钮」）就是渲染判据
（是否有 grid DOM、块内是否有源码行）——拆到别处就会各自漂移（[REVIEW.md](../../../../REVIEW.md) 第 8 条）。
钮的形态是**既有 token 与既有 chrome 纪律的复用**（零新 token、零新组件级色值），因此不需要
`ui-design-system` 的 delta——M240 的先例同样只动了 `editor-live-preview`。
反方（如实记录）：若裁决点 1 选备选③（多 flavor 剪贴板）或裁决点 2/3 改成给「块级动作钮群」立一套通用
组件规范，那时这套形态会从「编辑器内的装饰」升格为设计系统条目，应重新评审归属（而不是在本 change 里硬塞）。
