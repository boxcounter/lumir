## Why

Alex 2026-10-17 的需求原话（逐字）：

> 「如果 agent 输出在 harness pane 里的 vault 内路径支持点击、在 content pane 里打开」
>
> 「我希望做行定位。另外，卡片路径也做。」
>
> 「新标签。」

**现状**：harness 面板把 agent 的回复按 Markdown 渲染，但正文里的 vault 路径、工具调用卡片上的
路径都只是纯文本。用户读到「我改了某份文档的第 42 行」这类回复时，只能自己去文件树或搜索里找。
面板与编辑器之间因此缺一条最常用的通路：**从对话直接落到文档的指定位置**。

**为什么值得做**：agent 的工作成果越来越集中在「读了哪个文件、改了哪个文件、在哪一行」上；路径
就是它与用户之间的指代物。把路径变成可点入口，收益不在「少点两下」，而在**让 agent 的叙述可以直接
核对**——用户看到「第 42 行」，一按就能看到那一行。

**扫描证据（用于指导识别规则，不用于评估功能价值）**：对本机 harness 会话留存做了一次只读扫描
（脚本为本次会话临时编写、未入库；按仓库信息卫生纪律，本文不引用任何真实路径样例）。样本：158 条
非空 agent 回复，61 条含路径候选（38%），其中只有 9 条含**能解析到 vault 文件**的路径（5%）。候选
形态分布：

| 候选形态 | 次数 | 存在性校验后 |
|---|---|---|
| 中文行文里的对照式斜杠（两个中文词以 `/` 并列，不是路径） | 105 | 全部不命中 → 滤掉 |
| 反引号内的仓库相对路径（vault 外，如代码仓目录） | 34 | 全部不命中 → 滤掉 |
| 围栏代码块里的相对串 | 6 | 全部不命中 → 滤掉 |
| vault 外绝对路径（`/…`、`/tmp/…`） | 12 | 不链接化（已裁） |
| **命中 vault 文件的相对路径** | **12**（纯文本 8 + 行内代码 4） | 可链接化 |
| 命中 vault 目录的相对路径 | 8 | 不链接化（v1 已裁） |
| 带 `:行号` / `:行号:列号` 后缀 | 0 | 行号规则靠 prompt 纪律段推动 |

两条结论直接进了设计：① 候选**必须允许中文**——锁定 ASCII 的正则会漏掉真实引用；② 存在性校验
能把噪音**干净**滤掉——105 条中文行文斜杠与 34 条 vault 外仓库路径全部不命中，没有一条需要靠
「像不像路径」的启发式判断。样本量小是事实（dogfood 使用量低），本文因此**只拿它指导噪音形态与
识别规则，不拿密度数字质疑功能价值**。

**三个必须守住的设计事实**（已裁决）：

1. **行号锚定**：正文里的 `路径:行号` 与 `路径:行号:列号` 要能被解析，点击后打开文件并滚到该行。
2. **阅读位置不变量 CL-2（只记录用户自己造成的视口位置）**：点击跳转是应用推动视口，必须走既有的
   「转场让位窗口」，否则中间态会静默覆盖用户的阅读位置。
3. **打开链路唯一**：走既有的文件打开链路，落点为**新标签**；与 wikilink 的「点开即创建」语义分叉，
   绝不创建不存在的文件。

## What Changes

逐条对应 `specs/harness/spec.md` 增量里的一个 requirement：

1. **正文里的 vault 路径可点**（harness，ADDED：输出中的 vault 路径可点击）。段落 / 标题 / 列表 /
   引用 / 表格 cell 的纯文本与行内代码里，命中 vault 文件索引且按既有分类可打开的路径上屏为可点
   元素；行内代码在列是有意的——扫描里 12 处可解析引用中有 4 处写在反引号内，那是 agent 最常用的
   路径写法。围栏 / 缩进代码块不链接化（样本里 0 处可解析引用，且代码块的复制与选择手感优先）；
   锚元素内部不链接化（不产嵌套锚）。
2. **行号锚定**（同上 requirement）。`路径:行号` 打开后滚到该行并居中；`路径:行号:列号` 同样识别，
   列号 v1 只解析、不参与落点。行号越界时按编辑器既有口径钳到最后一行，不报错。
3. **工具调用卡片上的路径可点**（同上 requirement）。Read / Create / Patch / Delete 的 `path`、Move
   的源与目标、以及 diff 头里的文件名：点击打开文件；Read 的 `offset` 作为落点行。路径来自**结构化
   工具参数**，不对卡片上的任意文本做路径正则——参数摘要被截断时保持原样、不可点。
4. **打开落点 = 新标签**（同上 requirement，引用 `multi-tabs` 的既有不变量）。以「新标签」意图打开；
   该文件已在任一处打开时切到既有标签、不产生第二个标签（尚无文件的空文档按既有语义被复用）；不创建
   任何文件；目录、图片 / 二进制文件、vault 外绝对路径、含 `..` 的路径保持纯文本。
5. **跳转守 CL-2**（同上 requirement）。点击造成的视口位移包进既有的转场让位窗口：中间态那一拍到达
   的滚动事件不被阅读位置捕获；窗口边界由写回落地定义，不用时长量。TOC 跳转与 harness 跳转**捕获
   语义一致**（TOC 跳转今天没有开这个窗口，已核实现场，本次一并收口）。
6. **路径引用纪律**（harness，ADDED：路径引用纪律）。系统上下文新增一段与「摘录回指纪律」同构的
   固定段：引用 vault 文件写完整相对路径含扩展名、指向具体位置带 `:行号`、只引用工具结果里真实
   出现过的路径、不用 Markdown 链接语法包裹 vault 相对路径。**验收口径是抽样观察，不进机器断言**
   ——验收套件跑在 mock provider 上，测不到真实模型的遵从度。

## 起草期取值（已裁决之外，请评审时一并裁）

| # | 取值 | 理由 | 若你选另一侧 |
|---|---|---|---|
| 1 | `路径:行号:列号` 里的第二段按**列**解读，v1 只滚到行 | 与编辑器 / 编译器通行的 `行:列` 写法一致；扫描样本里行号后缀出现 0 次，规则本身要靠 prompt 培养 | 若你要的是「行范围 N 到 M」，落点与 prompt 文案都要改（v1 仍只滚一行，只是含义不同） |
| 2 | **行内代码里的路径也链接化** | agent 最常用反引号写路径（扫描：4/12 处可解析引用在反引号内）；目录与噪音仍被存在性校验挡住 | 若你要求「只有正文纯文本可点」，实现面缩小、命中率也随之下降 |
| 3 | **围栏 / 缩进代码块里的路径不链接化** | 代码块优先保证复制与选择的原始手感；样本里 0 处可解析引用 | 若你要代码块也可点，形态与点击冲突需要另行设计 |
| 4 | 路径候选**不允许含空格**（含空格的文件名本次不识别） | 扫描的候选规则本身不覆盖空格，样本无法证明其频率；正文里带空格的文件名与普通短语无法用字符规则区分，取保守一侧 | 若你要覆盖，需要另一套边界规则（如引号包裹才识别） |
| 5 | 工具卡片点击同样过「文件索引」校验，**不给 `vault_create` 开特例** | 一条规则、零特例；代价是刚创建的文件在索引增量到达前可能不可点 | 若你要求新建卡片立即可点，需要为 `vault_create` 增加一条按工具名放宽的例外 |
| 6 | 只链接化**可打开的文本类文件**（md / code / text）；图片与二进制保持纯文本 | 点开只会得到既有的「暂不支持预览」，是死路；分类复用既有注册表，不新写扩展名集合 | 若你要图片路径也可点，可改成打开图片遮罩或附件预览——那是另一条落点，需要单独裁 |

## Non-goals

- **目录引用不链接化**（已裁：v1 不做，落点另行裁决）。
- **vault 外绝对路径不链接化**（已裁）。
- **不创建不存在的文件**：与文档内 wikilink 的「点开即创建」语义分叉；未命中的候选保持纯文本。
- **消息级 next-error 遍历**（已砍）、**反向链接**（已砍）、**wikilink 形式输出**（已裁：渲染器不认、
  带不了行号）。
- **不新增工具、不改工具参数 schema、不新增后端命令**：存在性校验用前端已有的 vault 文件索引。
- **不做行范围高亮 / 选中**：行定位只把目标行滚到视口居中。
- **不为路径建第二套样式体系**：复用既有链接的色值与下划线语义，不引入新 token。
- **prompt 纪律的遵从度不进机器断言**（mock provider 测不到真实模型行为）；也不因一次抽样不合规
  就判本次实现失败。

## Impact

- **影响的 specs**：`harness`（ADDED ×2：输出中的 vault 路径可点击 / 路径引用纪律）。`multi-tabs` 的
  「打开语义」与单标签不变量被引用，不修改——本次的落点属于既有的「新标签」意图，不新增意图类别。
- **影响的代码 / 系统**：
  - 前端：harness 面板的 Markdown 渲染与工具行渲染（路径识别、链接元素、卡片路径）、装配层（文件索引
    的下发与打开链路）、编辑器跳转原语与 TOC 跳转（转场窗口）、`src/harness-path-link.ts`（新纯函数
    模块：候选提取、行号解析、工具目标提取、跳转编排）。
  - 后端：仅系统上下文的路径引用纪律段（新 prompt 文件 + 装配清单条目）；不动工具、权限、会话留存。
- **关联约束**：
  - 阅读位置合同 CL-2（应用推动视口必须开让位窗口；窗口边界不用时长定义）。
  - ADR 0002 §6 性能合同：路径识别在渲染路径上，必须同步、零 IPC、零额外解析轮；流式重渲不得因此
    掉帧（用内存索引，候选数很小）。
  - ADR 0003 §3 铁律：不写源文件、不在 vault 里产生文件（打开失败只走既有提示）。
  - 仓库信息卫生：验收 fixture 一律合成路径与合成文件名，不落真实 vault 内容。
- **不影响的既有行为**：模型输出原文、wire 请求体、工具参数与权限判定、标签与 pane 语义、外链点击、
  会话留存结构——全部不变。

## 观测闸三问

- **怎么知道用户用了它**：点击是显式动作，dogfood 时 Alex 自己就能感知；无埋点（沿用产品零埋点口径）。
- **怎么知道它有效**：回复里出现路径 → 点一下就能落到目标行；若常出现「看着像链接但点不开」或
  「路径没被识别」，就是识别规则或索引边界的信号。
- **出问题怎么发现**：机器面兜底——纯函数单测（候选 / 行号 / 工具目标）、渲染单测（只对命中项产
  链接、代码块与锚内不产）、跳转编排单测（CL-2 窗口）、真机验收场景（点击落点 + 反向验证）；识别
  规则的抽样观察（prompt 遵从度）如实登记为未覆盖，不伪装成机器判据。
