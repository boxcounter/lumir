- Change ID: harness-message-excerpt
- 日期: 2026-10-10

> 节点 1（提案评审）：留白（待 Alex 裁决）。

## Why

Alex 原话（2026-10-10）：「Harness 里的消息也可以摘录（类似摘录正文那样）」。

现有摘录能力（living spec `摘录引用卡片` / `引用消息序列化协议` / `混排对话输入区` / `摘录失锚降级`，change `add-harness-quote-cards` 已归档）覆盖**文档 → 对话**单向：编辑器选区 → 浮动钮 → 引用卡片入 composer → `<quote>` 序列化投递 → 点击跳回原文。对话进行几轮后，用户想追问的片段常常**已经在消息里**（上一条 assistant 结论、自己此前的问题），此时没有等价手势——只能手动复制粘贴，丢失出处、无法在模型侧结构化引用、也无法跳回。

本 change 把摘录能力的来源端从「编辑器 pane 的选区」扩展到「harness transcript 消息内的选区」，产物、手势、序列化、跳回全部与文档摘录对齐；对齐不了的地方（数据模型、序列化元素、跳回粒度）在 design.md 逐条写明差异理由。

## What Changes

每条对应 `specs/harness/spec.md` 增量中的一个 requirement：

1. **消息摘录卡片**（harness，ADDED）：transcript 中用户消息与助手消息体内的选区 → 浮动「摘录到对话」钮 → 片段以 block 级**消息摘录卡片**进入混排输入区（与文档摘录卡片同视觉族：竖条 + 至多两行摘录 + 出处行 + 移除钮）。卡片数据携带 role（user/assistant）、上屏时间戳 at（可无）、摘录原文（所见文本）。点击卡片跳回 transcript 中对应消息并瞬态高亮整条消息；找不到按三层降级（role+at 定位 → 全文搜索摘录原文 → toast 失锚，MUST NOT 静默跳到别的消息）。快照恢复时消息摘录卡片从留存原文解析还原（round-trip 与 `<quote>` 同口径）。携带消息摘录卡片的消息 SHALL 同文档摘录口径跳过视口注入（「上下文注入与可见性」的「携带卡片」扩展涵盖两类卡片）。思考块、工具行、批准卡与卡片内部的选区 MUST NOT 产出消息摘录。
2. **消息摘录序列化协议**（harness，ADDED）：混排序列化新增 `<msg-quote role="…" at="…">摘录原文</msg-quote>` 元素——每段消息摘录一行，问题文字按交错顺序排布在标签之间；`role` 必选（user/assistant），`at` 可缺（ISO 8601 本地时间串，秒级；上屏戳不可考的消息允许 role-only 出处）；属性与文本 XML 转义；**协议与 UI 均无编号**（一致性原则，与 `<quote>` 同）；投递给模型的出处要素（role / at）对人必须也可查——transcript who 行显示角色与相对时间、卡片 hover 显示完整摘录与绝对时间。会话 JSONL 留存记录序列化后的完整消息（含 `<msg-quote>` 块，与 `<quote>` 同纪律）。会话层指引 agent 按摘录内容与角色/时间回指。

## Alex 裁决点

| # | 裁决点 | 选项 | 起草倾向 |
|---|---|---|---|
| 1 | 产物形态 | A. 新卡片变体（消息摘录卡片，独立数据模型）；B. 复用 QuoteCard、file/lines 留空 | **倾向 A**——QuoteCard 的 file/lines 是文档锚且 `createQuoteCard` 对空 lines 抛错；留空复用会污染文档摘录的必选不变量与失锚降级链（行号定位对消息无意义） |
| 2 | 摘录文本口径 | A. 所见文本（`selection.toString()`，渲染形态照录）；B. 从 DOM Range 重建源 Markdown | **倾向 A**——面板内 Markdown 渲染不保留源偏移，重建是独立子系统且成品不确定；摘录的价值恰在「用户读到的那段话」，所见即所得 |
| 3 | 可摘录范围 | A. 仅用户/助手消息体；B. 含思考块、工具行、批准卡 | **倾向 A（MVP）**——消息体覆盖 Alex 原话的「消息」；思考块是折叠的瞬态呈现、工具行是结构化记录，摘录语义不清，留 dogfood 后另裁 |
| 4 | 序列化元素 | A. 独立 `<msg-quote role at>` 元素；B. 扩展 `<quote>` 加可选来源属性 | **倾向 A**——来源语义不同（会话消息 vs 文档行范围），独立元素不让 `<quote>` 的「file/lines 必选」不变量被稀释；两者交错规则完全一致 |
| 5 | 跳回粒度 | A. 消息级（滚动到对应消息、整条瞬态高亮）；B. 位置级（在消息体内定位到摘录片段） | **倾向 A**——渲染后的 Markdown DOM 无源偏移，位置级定位要重做渲染器的偏移映射，代价与收益不成比例；消息级已满足「跳回来看上下文」的用途 |
| 6 | 出处行信息密度 | A. `对话 · 助手`（时间与完整链进 hover）；B. 行内带相对时间 | **倾向 A**——与文档卡「文档名 · 标题」同密度；一致性原则由 who 行（相对时间）+ hover（绝对时间）双可查面满足 |

## Non-goals

- **摘录思考块 / 工具行 / 批准卡**：MVP 仅用户与助手消息体，理由见裁决点 3。
- **位置级跳回高亮**：渲染 DOM 无源偏移，见裁决点 5；消息级高亮外的精确性是后续独立议题。
- **跨会话跳回**：「新会话」重置后旧消息不在 transcript，失锚 toast 承接（与文档摘录「文件不存在直接第三层」同纪律）。
- **消息摘录进文档**：摘录落点恒为 harness composer，不进编辑器、不产生文档侧制品。
- **右键菜单 / 快捷键入口**：沿用文档摘录的裁决（浮动钮唯一手势，add-harness-quote-cards 裁决点 6），不新增默认键位。
- **复制钮改造**：消息复制钮（copySources 链路）维持现状，本 change 不动。
- **卡片编号**：协议与 UI 均不含（一致性原则），与文档摘录同。
- **视口注入策略重裁**：仅把「携带卡片跳过视口」从文档卡扩展到消息摘录卡，注入策略本身不变。

## 观测闸三问（低成本口径）

- **怎么知道用户用了它**：产品零埋点，天然使用痕迹在 wire 留存——含 `<msg-quote>` 块的 `llm_request` 记录可直接在会话 JSONL 里 grep 到；dogfood 期 agent 批次收尾顺手统计即可，不立新埋点。
- **怎么知道它有效**：主判 Alex dogfood 手感（摘录消息片段追问是否比复制粘贴顺手）；辅判抽看 JSONL 中后续轮次模型对消息摘录的回指是否对题（回指错位=有效性的负信号）。
- **出问题怎么发现**：机器面兜底——新验收场景（创建/交错编辑/序列化结构/跳回三层/快照恢复 round-trip）+ 序列化不变量单测 + 视觉基线；失锚与用户可见 toast 同面；协议层畸形（属性缺失/未转义/出现编号）会被 mock provider 验收场景与单测直接判红。
