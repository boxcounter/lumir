# Design: 正文末尾的「到底了」标记

- Change ID: document-end-marker
- 日期: 2026-09-21
- 读者：实现 mission（技术方案）、Alex（只看有用户可见后果的取舍；本文件的技术结论不进节点 1 裁决）

本文件只写**技术方案与权衡**：机制选型、判据、几何与测量、可访问性、与既有能力的关系、未验证项、反向验证配方。为什么做、做什么、不做什么在 [proposal.md](proposal.md)；任务在 [tasks.md](tasks.md)。

## 1. 机制：两条候选，以及对「滚动高度恒定」这条不变量的不同代价

需求是「正文末尾多一个装饰」。在只有一个 `EditorView` 的架构下（`src/editor.ts:1049-1353`），只有两条落点：

### 1.1 候选 A（推荐）：`.cm-content` 的生成内容（CSS 伪元素）

标记作为 `.cm-content` 的生成内容（`::after` 一类）挂在阅读栏的末尾，样式落 `src/preview/theme.ts`（该文件头明确 preview 装饰的样式在这里、不碰 `src/style.css`）。文本与几何由 CSS 给，不进 CM 的任何数据结构。

- **优点**：不参与 heightmap、不参与「只为可见区域构建」的增量义务（`src/preview/livePreview.ts:585`）、无 widget 测量、**不随滚动位置出现或消失**——「滚动高度在所有滚动位置恒定」这条不变量天然成立。
- **风险（未验证）**：CM 是否观测到 `.cm-content` 因生成内容而变高、并据此做出反应（滚动锚点复位一类）。CM 对内容尺寸有观察机制，但**本 change 未实测**，不得凭推断断言。判据与配方见 §8，若实测出现反应，退回候选 B。

### 1.1.1 实现期结论：候选 A 的**判据不可断言**，改用「同性质的独立元素」（实测已落 §7.1）

候选 A 的生成内容满足所有几何不变量的**前提条件**，但 spec 的三条判据都要读真实几何：渲染盒宽高
非零、横线总宽小于栏宽的一半、标记内存在文本节点。伪元素既没有 `getBoundingClientRect` 可读的盒子，
也没有文本节点——这三条只能退化成读 computed style（声明），而 REVIEW.md 第 1 条明确要求判据落在
渲染结果上。真机侧同理：这条 AX 通道对**文本节点**根本不携带几何（`@x,y w×h` 只出现在 `AXButton` / `AXImage` /
`AXScrollArea` 一类节点上），伪元素的盒子更没有落点——真机侧只能读「节点在场 / 缺席」，所以要读盒子的三条判据必须由真元素承担。

因此实现落在**同性质的第三条路**上：真元素（`div` + 两个线段 `span` + 一个文字 `span`）挂到
`.cm-scroller` 上，位置与 `.cm-content` 同级（`gridColumn: 2`、`gridRow: 2`）。它保留了候选 A 全部
被看重的性质——不进 `EditorState.doc`、不进 heightmap、不做 widget 测量、不参与按视口构建的装饰层、
与滚动位置无关——同时让三条判据都有真实盒子可读。与候选 B 的区别正是 §1.2 记的那条风险：它不随
视口出现或消失（元素在场与否只由判据决定，与滚动位置无关）。

**实测到的两个落点问题（都影响「紧贴正文之后」这条几何）**：

1. `.cm-content` 带 `min-height: 100%`（CM 基础主题），滚动容器只有一行时该行会被压到可用高度
   （隐式行的贡献算成 0）——正文其实溢出行外，任何「正文之下的行」都会叠在正文上而不是排在它后面
   （实测：标记落在 `y=652`，而正文内容盒到 `y=1228`）。修法：**标记在场时**给滚动容器
   `grid-auto-rows: max-content`。这条口径只在标记在场时生效，一屏装得下的文档与 code 模式不受影响
   （那里「点正文下方空白仍落在 `.cm-content` 内」这类既有行为不能变）。
2. 竖向位置因此不是「内容盒内、44px 内边距之上」，而是**内容盒之下**：标记上方那段呼吸来自
   `.cm-content` 自己的 44px 下内边距，下方由标记自己的 `padding-block-end: 44px` 补成对称。
   §3 的措辞按实测更新（间距仍全部走 `padding`，不动 `.cm-content` 的内边距）。

### 1.2 候选 B（备选）：文档末尾的 block widget

在 `doc.length` 处放一个块级 widget（`Decoration.widget({ block: true, side: 1 })`），与 frontmatter properties 区块（`src/preview/frontmatter.ts:104-179`、块级 replace widget）同族。

- **优点**：与既有装饰同形，位置严格钉在文档结构末尾。
- **风险**：现有装饰**只为可见区域构建**。落在视口外的 widget 不参与高度，接近底部时它进入视口、文档高度才补上这一段——用户看到的是「快滚到底时滚动条突然变长」，正是 `src/preview/theme.ts:163-166` 注释里记过的 M110 同族缺陷（那次是 margin 对 heightmap 不可见导致行映射错位）。若选候选 B，必须让标记的高度贡献**与滚动位置无关**（不随视口出现/消失）或给出与实际高度严格一致的 `estimatedHeight`，并把「滚动高度恒定」写成断言（§8 的配方必须能红）。

### 1.3 取舍与推荐

**推荐候选 A**：它对唯一那条真正的几何不变量（滚动高度恒定）的代价为零，而候选 B 需要额外证明它。两条候选都必须满足的不变量清单：

1. 不进 `EditorState.doc`、不进保存字节（ADR 0003 §3）；
2. 不被 ⌘A 复制带出、不被 ⌘F 命中；
3. 滚动高度在所有滚动位置逐像素恒定；
4. 纵向间距用 `padding` 不用 `margin`（CM 测量的高度是 border-box，margin 对 heightmap 不可见——既有注释 `src/preview/theme.ts:163-166`）；
5. 不在文档打开路径与键入路径上新增解析或测量（ADR 0002 §6）。

**与裁决点 3 的技术耦合（如实记录）**：若 Alex 选「只在滚到底时出现（淡入）」，则**占位必须恒定、只切换可见性**——否则「滚到底 → 标记出现 → 文档变高 → 滚动位置与滚动条跳变」会叠成一个组合缺陷。这条耦合是备选②的隐含成本，写在裁决表的取舍里。

## 2. 出现判据：为什么是「内容高度 vs 视口高度」，而不是「滚到底」

判据（推荐项）：**不含标记的文档内容高度 > 可用视口高度**时显示，否则不显示。两个量都是既有可读量（`src/editor.ts:762-764` 的翻页已经直接读 `view.scrollDOM`），不需要新语义；但**不能直接拿 `scrollHeight` 与 `clientHeight` 相比**——前者含标记自己的高度，见本节末「自我指涉」一条。

- **静态量**：它只由「文档内容 + 视口」决定，与滚动位置无关。判据是重算型（文档变更 / 视口尺寸变化时各算一次），不是逐帧监听。
- **不是第二份「当前位置」真源**：`src/toc.ts:151-158`、`:265-270` 那份可见行 / 当前标题的追踪是滚动位置语义；本判据不看滚动位置，也不复用它的状态（[REVIEW.md](../../../../REVIEW.md) 第 8 条的防线是「先 `rg` 全仓确认是否已有同类表」——这里结论是**不同语义**，因此允许各自存在，但要写明不共享）。
- **不抖**：图片异步加载只会把文档高度**单向**推高（从「装得下」推向「装不下」），跨过判据的方向与语义一致（一旦内容超过一屏，感知缺口就出现了）。若判据是滚动位置，同样的加载会让标记忽隐忽现。（本条只覆盖**图片加载**引起的抖动；判据自身的自我指涉是另一回事，它不产生抖动，但会造出一个标记高度宽的假阳性带，见下。）
- **边界取值**：`>` 而不是 `>=`——不含标记的内容高度恰好等于可用视口高度时，没有可滚动的余量、整篇都在视野内，不该显示。
- **自我指涉（M188 r1 指出，必须显式排除）**：候选 A 下标记在 `.cm-content` 的内容盒内（§1.1），它自己的高度计入**同一个** `scrollHeight`。判据若直接拿这个数去比，一份自身内容高度落在 `(clientHeight − 标记高度, clientHeight]` 区间的文档会**只因标记出现**而从「装得下」变成「装不下」——判据量到的是含自己贡献的量，逻辑上自我成立。两态各自自洽（显示后恒为真、隐藏后恒为假），所以它**不会抖动**，但「一屏装得下时不显示」这条在区间内被破坏。**判据的测量因此 MUST 剔除标记自身的高度贡献**：用于比较的量 SHALL 是「不含标记的内容高度」与可用视口高度（如减掉标记占位的高度，或比较 `.cm-content` 的内容高与可用高）。若实现上剔除不便，退路是**迟滞**——显示阈值与隐藏阈值错开（差值 ≥ 标记高度），代价是多一个状态位与两条阈值。两种修法二选一，但 MUST NOT 直接拿含标记贡献的 `scrollHeight` 判。

已知的预期行为（不是缺陷，须在 spec 的 Scenario 里钉住）：窗口高度跨越判据时标记随显随隐；一份恰好一屏的文档在窗口略微变矮后开始显示标记。这两条都是判据的直接推论。

**已知边界（判据的临界带）**：`(clientHeight − 标记高度, clientHeight]` 这一区间位于判据边界上，宽度等于标记高度（数行量级）；落在带内的文档按剔除标记贡献的口径**不该**显示标记。实现期必须带一份**恰好落在带内**的 fixture（内容高度略微小于可用视口高度）来覆盖它，否则这个缺陷（判据自我成立、装得下的文档也显示标记）跑不出来。见 §7 第 5 条、§8 与 [tasks.md](tasks.md) 的 5.2。

## 3. 几何与测量

- **位置**：紧贴正文内容盒之下、随内容滚动；水平居中于阅读栏。`.cm-content` 本身就是阅读栏那一列（`src/editor.ts:1212-1224` 的 `gridColumn: "2"` + `--measure` 80%），标记与它同列同宽，居中天然成立，不需要额外定位。
- **与既有 44px 内边距的关系**：`.cm-content` 的 `paddingBlock: "44px"`（`src/editor.ts:1222`）不动。实测落点是
  **内容盒之下**（见 §1.1.1）：标记上方那段呼吸就是 `.cm-content` 的下内边距，标记自己用
  `padding-block-end: 44px` 补出下方对称的呼吸。本 change MUST NOT 通过改 `.cm-content` 的内边距来
  「让标记更靠下」。
- **高度**：固定（由字号与行高派生），不随滚动、不随窗口宽高变化。
- **测量**：候选 A 不进入 CM 的高度测量；候选 B 必须给固定高度与一致的 `estimatedHeight`。无论哪条，「滚动高度恒定」都要实测（§8）。

## 4. 视觉形态

推荐形态（裁决点 2）是**短线夹字**：一段居中的短横线（`--bd-2`）两侧夹住弱化小字（`--dim` + `--font-display` 宋体 + 字距）。

- **与作者手写的分隔线必须可区分**（硬约束）。既有分隔线是**通栏**发丝线（`.cm-lp-hr` 的 `inlineSize: 100%`，`src/preview/theme.ts:139-146`）。标记的差别是**双重的**：线段**短**（断言：线段总宽 < 阅读栏宽的一半）+ **夹着文字**（断言：存在文本节点）。只靠「更短」这一条差别不够（裁决点 2 的备选②已被这个理由压过）。
- **配色**：文字取 `--dim`（`#8d8471`），线段取 `--bd-2`（`#cfc4a6`）；**不用朱红**。这条设计基线的原文就在分隔线那段注释里：「中性色暖发丝线……朱红留给链接与错误态」（`src/preview/theme.ts:136-138`）。标记是 chrome，不与链接抢注意力。
- **字体**：`--font-display`（Songti SC / STSong 一族）——与标题族同款，符合本仓 editorial 语气；字距适量放宽，让它一眼是「装饰」而不是「正文」。
- **不引入新的 CSS 变量**：一律复用既有 token（`src/style.css:5-14`）。

## 5. 可访问性

- 与本仓质量合同的对账：[Foundation Markdown §5](../../../../docs/specs/foundation-markdown.md) 的那句「装饰隐藏标记时仍保留可理解的读屏文本或等价语义」针对的是**替换型**装饰（源码被顶掉、读屏读到空白）。本标记不隐藏任何源码，因此该条**不字面适用**。
- 但仍不得出现匿名元素——对照既有做法：`.cm-lp-hr` 被补了 `aria-label="分隔线"`（deck D76，`文案-Copy.md` 第 67 行；断言在 `tests/visual/scenes/render-hr.spec.ts`）。
- 推荐项（有可见文字）下，**可见文字本身即可读文本**，MUST NOT 另加 `aria-label`（读屏会听到两遍）。串的来源与 deck（D114）逐字一致，先例是 `tests/unit/image-widget.test.ts` 按 deck 表格行逐字断言 D111–D113 的组装函数。
- 读屏用户侧的「到底了」线索原本就来自读屏器自身的文档边界播报，本 change 不新增读屏专用文案；若裁决点 1 取备选③（无文字符号），D114 就从「可见文案」变成「读屏名」（与 D76 同形）。
- **实现落点的可访问性后果（实测口径）**：标记在 `.cm-content` 之外（§1.1.1），因此它的可见文字对读屏可读（不是匿名元素），
  而编辑器的文档文本（AX 的 `AXTextArea.value`）里没有它——读屏听到的是「到底了」这一句界碑，正文文本不被污染。
  真机场景 27 的断言按这个口径写：`ax` 里要求「标记的可读文本节点**在场**」（长文命中、短文缺席，同一个匹配器），
  `editor` 里要求没有它。**这条 AX 通道不给文本节点几何**（实测：标记节点是 `AXStaticText = "到底了"`、无 `@x,y w×h`；
  bbox 只给 `AXButton` / `AXImage` / `AXScrollArea` 一类节点），所以真机侧判的是在场 / 缺席，**可见性**由 chromium 层的几何断言 + 截图证据承担。

## 7. 已知边界与未验证项（如实记录，不许当成已验）

1. **CM 是否会因标记的尺寸变化做出反应——实现期已实测，结论：机制上不可能，读数也一致。** 实现把标记放在
   `.cm-content` **之外**（§1.1.1），而 CM 的观察面只有三处：`DOMObserver` 的 MutationObserver 观察
   `.cm-content`（构造处以 `view.contentDOM` 为根）、ResizeObserver 观察 `.cm-scroller` 的**盒子**（标记不改变它）、
   高度预言机读 `.cm-line` 的矩形（标记不是行）。实测读数（`test-results/m189/probe-before.json` /
   `probe-after.json`）：长文三种滚动位置上 `scrollHeight` 由 1228 变为 1288，增量 **60px 恰等于标记自己的
   渲染盒高度**——CM 没有为自己的高度账本补任何东西（没有填充块、没有滚动锚点复位）；四种滚动位置上
   标记状态与 `scrollHeight` 逐项恒定（§8 的配方即为此断言，绿灯现场见 `gate-visual.log`）。
   `document.fonts.ready` 之后 CM 自己那次重测也被覆盖：判据另挂 ResizeObserver 观察 `.cm-content`
   （内容尺寸变化）与 `.cm-scroller`（视口尺寸变化）。
2. **视口高度变化的判定时机**：窗口 resize、侧栏宽度变化（`--measure` 是百分比，栏宽随窗口变）都会改变内容高度，判据必须跟着重算；实现期已覆盖——判据的触发点是观察 `.cm-content` 与 `.cm-scroller` 的 ResizeObserver（不是逐帧监听，也不读滚动位置），chromium 场景里「压矮视口 → 标记出现」「放高视口 → 标记消失」两条配对断言即这条的现场。
3. **与字体无关的极端情形**（一屏内只有一两行的文档）：按判据不显示，不做特别处理。
4. **标记的观感本身**（线的长度、间距是否合适）**归 Alex**，门禁只判几何与语义（与本仓「手感/审美不下沉」的既有分工一致）。
5. **判据的临界带（M188 r1）**：候选 A 下标记自己的高度计入判据所量的 `scrollHeight`，`(clientHeight − 标记高度, clientHeight]` 区间内的文档会只因标记出现而跨过判据（自我指涉）。实现期取「剔除标记自身贡献」这条修法——标记在 `.cm-content` 之外，量的是 `.cm-content` 的渲染盒高度，这个数里没有任何标记贡献，自我指涉在机制上不存在；该带仍有专用 fixture 与断言（`tests/visual/scenes/end-marker.spec.ts` 的「临界带」用例，fixture 实测落在带内由断言当场证明），反向验证见 §8。宽度等于标记高度，属判据的固有临界带，不是可用测试消除的误差。

| 判据自我指涉（临界带，§2） | 用落在 `(clientHeight − 标记高度, clientHeight]` 带内的 fixture：按「拿含标记贡献的 `scrollHeight` 判」的错误实现，该 fixture 会显示标记而断言必须红 | `red-self-reference.log`：判据改成读 `scrollHeight` 且标记空间恒定预留后，临界带与两态两条都红 |
| 静态判据（不依赖滚动位置） | 判据临时改成「滚到底才显示」，「同一滚动位置读数逐项相同」的断言必须红 | `red-scroll-position-criterion.log`：回到顶后 `scrollHeight` 与第一次读数不同（1228 ≠ 1620），红 |
| 非文档性 | 标记临时改成往文末追加一行文本，⌘A 复制的断言必须红（ADR 0003 §3 也当场破） | `red-document-content.log`：复制出的文本里出现「到底了」，红 |
| 滚动高度恒定 | 滚到顶 / 中 / 底 / 回顶各读 `scrollDOM.scrollHeight`，四条须逐像素相同；标记随视口出现/消失的错误实现在回顶那次会读出不同值而红 | 绿灯现场：`gate-visual.log`；反向见上一行（同一批读数） |
| 与作者分隔线可区分 | 把标记的线改成通栏，区分断言必须红 | `red-full-width-line.log`：线段总宽 720px ≮ 栏宽一半 382px，红 |
| 不新增测量（ADR 0002 §6） | 判据排的那次测量搭 CM 自己的测量周期（`EditorView.update` 在重绘时已 `requestMeasure`），读的只有两个既有布局数（`.cm-content` 的渲染盒高、`.cm-scroller` 的 clientHeight），不遍历文档 | 未跑 1MB 端点读数（`gate.sh all` 需 release 构建）；该项**未实测**，如实记录，不宣称达标——机制上的依据是「新增的读只有 O(1) 两次且不产生新的布局趟」 |

## 9. 不采用的机制（备记，防止实现期绕回去）

- **往文末插一行文本**：违反 ADR 0003 §3 铁律，并污染 ⌘A / ⌘F——双重违规。
- **只加内边距、不加语义**：用户读不出任何东西，等于没做。
- **把标记钉在窗口底部（`position: sticky` / 固定 chrome）**：那是窗口级 UI，不是「文档末尾」的装饰；它在一屏装得下的文档上变成纯粹的占位噪音（proposal 裁决点 3 的备选②取舍已记）。
- **在每个标题块末尾加标记**：需求原话只到「文件底部」（Non-goals 已列）。
