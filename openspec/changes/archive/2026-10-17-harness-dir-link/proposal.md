# Proposal: harness 输出里的 vault 目录引用可点击，落点 = 左栏文件树定位

- Change ID: harness-dir-link
- 日期: 2026-10-17
- 角色: Alex Lee（评审/裁决），AI agent（起草）

## Why

Alex 2026-10-17 的裁决原话（逐字）：

> 「如果命名的是目录，那么点击效果是在左栏里定位到。你觉得这个点子如何？」
>
> 「立项，请你安排。」

**现状**：change `harness-path-link`（M552，已合并 master）让 agent 输出里的 vault **文件**路径可点开；
**目录引用被显式排除**（v1 裁决「目录不链接化」）。本次把那条裁决翻转：目录引用同样可点，
落点不是打开文档，而是**在左栏文件树里定位到该目录**（展开祖先链 + 滚动 + 短暂高亮）——
Emacs `dired-jump` 的直觉。

**扫描证据（change `harness-path-link` 起草期做过的只读扫描，用于判断覆盖面，不评估功能价值）**：
可解析到 vault 条目的命中共 20 处，其中**目录 8 处**（行内代码 7 / 围栏代码块 1），占 40%；
文件 12 处。不链接化目录等于放弃五分之二的真引用，其中 7 处正好写在 agent 最常用的行内代码里。
按既有规则围栏代码块不链接化，本 change 实际新增的覆盖面是 7/20。（扫描原文与计数见
`openspec/changes/harness-path-link/design.md` §1；按仓库信息卫生纪律，本文不引用任何真实路径样例。）

**为什么落点在树、而不是打开别的东西**：目录没有「内容」可打开，agent 说「这个目录下有一批材料」
时用户想知道的是**它在 vault 的哪一层、旁边有什么**——只有左栏树回答得了这件事。树侧已有
「把一个路径显现出来」的能力（`FileTree.revealPath`，M300），本次是给目录补一条不改当前行的定位语义。

## What Changes

逐条对应 `specs/` 的增量：

1. **目录引用可点，点击在左栏定位**（`harness`，MODIFIED：输出中的 vault 路径可点击）。
   正文（段落 / 标题 / 列表 / 引用 / 表格 cell 的文本与行内代码）里的目录路径，命中当前 vault 的
   **目录模型**时上屏为可点元素；点击只在左栏文件树里定位该目录：展开它的祖先链、把目录行滚进视口、
   给一次短暂高亮。**不打开任何文档、不切换标签、不创建任何条目、不改文件树的当前行标记。**
   围栏 / 缩进代码块与锚元素内部维持既有「不链接化」口径。
2. **可点性判据 = 树模型成员**（同上 requirement）。目录引用可点**当且仅当**文件树模型里存在该目录
   条目——与定位能力使用同一份数据，不再回答「能不能展开」这第二个问题。由此自然成立：内置规则挡住的
   目录（`node_modules` / `target` 等）不在模型里 ⇒ 不可点；vault 外路径与含 `..` 的路径在候选阶段就被
   拒绝；惰性目录**自身**在模型里 ⇒ 可点；惰性目录之下、本会话从未取回过的子目录不在模型里 ⇒ 不可点
   （「能展开定位则定位，不能则不链接化」）。不新增任何忽略名单（后端是唯一真源）。
3. **树侧新增目录定位语义**（`file-tree`，ADDED：目录定位不动当前行）。定位复用既有的可达性确认
   （逐段确认祖先、惰性祖先按需取回一层）与「只在需要时滚动」的几何口径；**但与文件定位有一处刻意
   分叉**：目标行 MUST NOT 被标成当前行（那是「当前打开的文档」的标记，目录不是文档），改以一次
   短暂高亮表达「定位到了这里」。
4. **展示形态不变**：目录链接与文件链接共用同一个行内元素与同一套样式/色值/下划线语义，可见文本
   逐字保留（含用户写下的尾斜杠）。不新增文案、不新增图标、不新增视觉 token。
5. **既有文件行为零变化**：文件链接的打开链路、行号落点、新标签意图、工具卡片路径、CL-2 让位窗口
   全部照旧；本 change 不给文件定位加高亮，也不改它的当前行语义。

## 起草期取值（已裁决之外，请评审时一并裁）

| # | 取值 | 理由 | 若你选另一侧 |
|---|---|---|---|
| 1 | 目录引用**允许单个尾斜杠**（`docs/`）：可点文本逐字含尾斜杠，成员判定按去掉尾斜杠后的路径 | agent 写目录时常带尾斜杠（「这个目录」的书写直觉）；不接受等于让这部分引用静默不可点 | 若你要求严格无尾斜杠，实现更省一层归一，但会漏一类常见写法 |
| 2 | 目录引用**不解析行号后缀**：`docs:12` 里只链接 `docs`，`:12` 留作普通文本 | 目录没有行上下文；把行号并进可点范围会让一次点击带上无意义的落点 | 若你要「目录:行号」也整个可点，行为与当前无差别（仍只定位），只是可点范围更大 |
| 3 | 点击只展开**祖先链**，不展开目标目录自身 | 与「定位到」的字面语义一致；展开目标会顺带触发一次惰性取数与非用户要求的列表展开 | 若你要 dired-jump 式的「顺便展开它」，目标目录的惰性取数会进入点击路径（多一次 IPC） |
| 4 | 短暂高亮取**既有选中底色** `--sel`，时长约 1.2s，无动画曲线（沿用行的既有时长过渡） | 与右键菜单作用行 / 拖拽落点行同一强度族，不引入新色值；`--sel` 在 eink 下有配套前景色 | 若你要更强的信号（如描边 / 闪烁），需要新视觉口径与基线更新，另裁 |
| 5 | 工具卡片上由结构化参数解析为**目录**的路径，与正文同口径（仅定位） | 一条规则、零特例：卡片与正文共用同一份解析与分发 | 若你要求卡片只认文件，需要按来源再加一条分支 |
| 6 | 目录链接与文件链接**外观完全一致**（不加图标 / 提示文案区分） | 不新增文案与视觉 token；两者都是「点一下去看某个东西」 | 若你要可区分，需要新增文案条目与样式（`文案-Copy.md` + 面板样式），另裁 |

## Non-goals

- **不创建 / 不打开 / 不切换**：目录点击不产生任何文档、标签或条目；不把目录当作「打开一个视图」。
- **不给文件链接加高亮、不改文件定位的当前行语义**：本 change 只新增目录路径的那一条分叉。
- **不新增目录索引 / 不新增 IPC / 不改后端**：目录可点性读文件树模型，零新增数据通道。
- **不新增忽略名单**：内置规则挡住的目录不进树，因此天然不可点；前端 MUST NOT 再抄一份名单。
- **不做目录内的遍历 / 递归展开 / 批量操作**（无 next-error 式“目录内下一项”）；不展开目标目录自身。
- **不改系统上下文的路径引用纪律段**：现有纪律已要求「引用目录时说清是目录」，本次不动 prompt。
- **不改文件树右键菜单项集**（不给目录加新的菜单动作）。
- **「内置名单分档」不在本 change**（见下方协同预留）。

## 协同预留（不在本 change 内实现）

若日后立项「内置名单分档」——把 `test-results` / `perf-results` / `target` 这类构建产物目录从
「内置规则完全隐藏」降为「用户规则式惰性可见」——那时 agent 输出里的这些路径会出现在树模型里，
本 change 的判据（模型成员即可点）**无需改动**即可让它们直接可定位。这是本 change 选「模型成员」
而不是「枚举快照」的附带收益。

## Impact

- **影响的 specs**：`harness`（MODIFIED ×1：输出中的 vault 路径可点击）；`file-tree`（ADDED ×1：
  目录定位不动当前行）。
- **影响的代码 / 系统**：
  - 前端：候选识别层（目录候选、尾斜杠归一、行号后缀只给文件）；harness 面板（按目标类型分发
    打开 / 定位）；装配层（把「这个路径是不是目录」与「定位目录」两条能力注入面板）；文件树
    （只读的目录判定 + 目录定位 + 短暂高亮的生命周期）。
  - 样式：目录定位的短暂高亮**需要在 `src/style.css` 增加一条行态规则**（复用 `--sel` 与 eink 的
    配套前景色，不新增 token）。当前 mission 的文件 scope 未含 `src/style.css`，实现前需由 tower
    扩 scope；动过它必须本地跑 `scripts/gate.sh visual`。
  - 后端：**零改动**（无新命令、无新参数、无 prompt 变更）。
- **关联约束**：
  - ADR 0002 §6 性能合同：目录判定在渲染路径上，必须同步、零 IPC、零额外解析（读内存树模型，
    Map 查找）；点击路径上的惰性祖先取数是既有 `fs_scan_dir` 的复用，且只由用户点击触发。
  - ADR 0003 §3 铁律：不写源文件、不在 vault 里产生任何条目。
  - 阅读位置合同 CL-2：本 change 只滚**左栏**（侧栏没有阅读位置捕获），不触编辑器视口，CL-2 不适用。
  - 仓库信息卫生：验收 fixture 一律合成路径与合成目录名。
- **不影响的既有行为**：文件路径的打开 / 行定位 / 新标签语义、工具卡片解析、外链、标签与 pane、会话
  留存——全部不变。
- **归档顺序**：本 change 的 `harness` 增量是 **MODIFIED**，目标是 change `harness-path-link`
  写入的 requirement。后者尚未归档，`validate --all --strict` 会提示「archive 会拒绝该增量」；
  本 change 归档前 MUST 先让 `harness-path-link` 归档并入 living spec（tower 已知悉此依赖）。

## 观测闸三问

- **怎么知道用户用了它**：点击是显式动作，dogfood 时 Alex 自己就能感知；无埋点（沿用产品零埋点口径）。
- **怎么知道它有效**：agent 提到目录后，点一下就能在左栏看到它所在的层级与邻居；若常出现「看着像
  链接但点不动」或「点了左栏没反应」，就是树模型成员判据的边界信号（惰性未取回、索引过期）。
- **出问题怎么发现**：机器面兜底——候选层单测（目录命中 / 尾斜杠 / 行号后缀不消费 / `..` 拒绝）、
  树定位单测（展开祖先、只滚一次、不写当前行、不可达空动作、连点只认最后一次）、面板渲染单测
  （按类型分发、卡片同口径）、真机验收场景（点击目录 → 祖先展开、无新标签、编辑器不变 + 截图）。
  高亮时长与观感归 Alex 手感裁决，不进机器判据。
