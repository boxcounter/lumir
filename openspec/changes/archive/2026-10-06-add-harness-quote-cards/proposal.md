## Why

ADR 0008 Decision 8 把 Phase 2 定为「harness 入 pane + chat UX 重做 + pin 式上下文块」。其中 **pin 式上下文块已被 Alex 2026-10-05 裁决推翻**（「我认为 pin 是一个糟糕的设计，我不需要」），替代机制是 Alex 自己提出的第三个方案：摘录正文选中的片段进入对话，点击可跳回原文并高亮。该机制经原型五轮迭代演进为 **block 级引用卡片**，原型已收官（Alex 2026-10-06「我对原型没有异议了」），屏 5「摘录卡片」为设计合同；设计合同现居本 change 的 `specs/harness/spec.md` 增量。五轮裁决原文原样记录在原型目录 `design/prototypes/phase2-harness-chat/` 的 NOTES.md——该目录已随实现落地退役（提交 `4e011d6`），原文见 git 历史。

本 change 是 Phase 2 实现三份提案的**第一份**（三份拆法 Alex 2026-10-06 已批准），只覆盖摘录引用卡片与消息序列化；对话基础框架（会话/ctx%/发送停止/复制/进度）与思考呈现归后续两份，见 Non-goals。

动机对应三条 Alex 原始需求：

- 对正文指定段落做针对性探讨（ADR 0008 Context 记录的 harness v1 痛点）。
- 「一次 pin 多个、然后一次发出去」（2026-10-05）——由「一条消息挂多张引用卡片」承接。
- 「摘录胶囊之间可以输入内容，让每个问题的目标更明确」（2026-10-06）——由混排编辑区（卡片与问题段落交错）承接。

同时落实 Alex 裁决的设计约束：**一致性原则**（2026-10-06）——投递给 AI 的上下文要素对人必须也可查，避免 AI 引用人看不见的标识（如「第 3 条摘录」）造成歧义与困惑。UI 无可见编号，序列化协议同样不带编号；agent 按摘录内容/出处回指。

## What Changes

每条对应 `specs/harness/spec.md` 增量中的一个 requirement（除第 6 条为文档任务）：

1. **摘录引用卡片**（harness，ADDED）：编辑器 pane 中选中片段 → 浮动「摘录到对话」钮 → 片段以 block 级引用卡片进入对话输入区。卡片 = 引号竖条 + 摘录截断（至多两行）+ 出处行（文档名 · 最近一级标题）+ 移除钮；数据携带 file / heading / lines（从选区捕获，必选）/ 摘录原文；点击卡片跳回原文位置并瞬态高亮；编辑器侧零常驻装饰（只有进行中的选区与跳回高亮两种瞬态）；摘录来源为「最近活跃编辑器 pane」的选区（ADR 0008 Decision 3 语义）。
2. **混排对话输入区**（harness，ADDED）：对话输入区改为混排编辑区且是唯一形态（无卡片时退化为纯文本输入）；卡片是原子 block 节点（删除/选择按整体作用），问题文字在卡片之间的段落里，任意交错；「摘录到对话」在光标处插入（段落中间拆段），**插入后光标落到卡片下一行的问题段落**（该处无空段落时新建——Alex 2026-10-06 裁决，便于摘录完直接写问题）；已发送的用户消息同构呈现（卡片无移除钮）；粘贴内容净化为纯文本。
3. **引用消息序列化协议**（harness，ADDED）：发送时混排内容序列化为 XML——每段摘录 `<quote file="…" heading="…" lines="A-B">摘录原文</quote>`，问题文字按交错顺序排布在标签之间；`lines` 必选（取不到行范围则不生成卡片）；`heading` 与卡片出处行显示的最近一级标题一致；属性与文本 XML 转义；**协议与 UI 均无编号**（一致性原则），agent 按摘录内容/出处回指，同文档多段相似摘录时用出处（标题 / 行范围）消歧。
4. **摘录失锚降级链**（harness，ADDED）：跳回定位三层降级——① 按 lines 行号定位并校验该处文本与摘录原文匹配；② 失配则文档内搜索摘录原文字符串；③ 仍找不到则告知用户摘录已失锚（toast），不静默跳到其他位置。
5. **上下文注入调整**（harness，MODIFIED「上下文注入与可见性」）：选区不再自动注入上下文（由摘录卡片显式策展承接）；当前路径注入保留；视口注入在无引用卡片时保留、存在卡片时跳过（用户已显式策展，避免重复与噪声）；可核对 chip 呈现口径相应更新。
6. **ADR 0008 措辞修订**（文档任务，非 spec）：Decision 8 与 Consequences 中「pin 式上下文块」相关措辞改为摘录引用卡片表述（pin 机制 2026-10-05 已被推翻，修订时机随本提案落，finding 已登记）。

## Non-goals

- **harness 入 pane 与标题栏改造**（提案 2）：harness 归位 pane、标题栏 harness 段、产品标识移位、会话切换/新建会话进标题栏。
- **对话基础框架其余项**（提案 2）：ctx% 移入 composer 控制行 + 压缩警示收 ⓘ、发送/停止钮两态、复制消息、不定态进度。
- **思考过程呈现与思考程度选择**（提案 3）。
- **accent 族 token 中性化**（去蓝色强调色）：全局视觉变更，触及 `src/style.css` token 层，建议随提案 2 落或独立小 change；本 change 新增 UI 不消费 accent 蓝色（卡片竖条/出处行均为中性灰阶）。
- **序列化开发者预览块**：仅原型调试用途，Alex 已裁决不进产品。
- **卡片编号**：协议与 UI 均不含（一致性原则，Alex 2026-10-06）；编号不以任何形式存在（含测试钩子之外的隐藏属性）。
- **编辑器侧「已讨论」留痕**（pin 唯一独有信息）：Alex 明确不要，不以任何形式复活。
- **新增键位**：原型建议的「⌘⇧N」等键位未经裁决；本 change 摘录手势只走浮动钮，不新增默认键位。
- **批准闸形态**（写类工具 / CLI 的采纳-拒绝流程，`src/harness-panel.ts` 既有能力）：沿用现状，本 change 不改。（原型文案中的「提案队列」是占位措辞，产品中的对应物即批准闸，并非另一个特性。）
- **多会话管理与历史回看**：探针期既有口径（一会话绑一 vault）不变。
