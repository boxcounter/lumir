# Design: add-harness-quote-cards

技术设计说明。节点 1 评审以 proposal.md 为准；本文记录实现期的技术选型与行为合同细节，供实现 worker 与归档评审对账。

**术语**（本文与提案通用）：**composer** = 对话输入区（harness 面板底部撰写、发送消息的区域；英文原义「撰写器」，聊天应用惯用叫法）。**contenteditable** = 浏览器内置的富文本编辑能力（给网页元素加该属性即可直接编辑，且允许混入卡片这类非纯文本元素；对照物：`textarea` 纯文本输入框、CodeMirror 代码编辑器组件）。

## 1. 设计合同与输入

- 设计合同：本 change 的 `specs/harness/spec.md` 增量（四条 ADDED requirement 的验收场景）。来源是原型屏 5「摘录卡片」（1280×900，三主题）——该原型目录 `design/prototypes/phase2-harness-chat/` 已随实现落地退役（提交 `4e011d6`），屏位原文见 git 历史。卡片视觉：3px 引号竖条（中性灰阶）+ 摘录原文 `-webkit-line-clamp: 2` 截断 + 等宽小字出处行（`文档名 · 最近一级标题`）+ composer 内 × 移除钮。
- 行为合同：NOTES.md 五轮决策节 + Alex 2026-10-06 提案评审讨论修订（index 移除 / 光标落卡片下一行 / heading = 最近一级标题 / 一致性原则），见 proposal.md 头部评审记录。
- NOT 清单：序列化预览块不进产品；编号不进 UI 也不进协议；编辑器侧零常驻装饰。
- **一致性原则**（Alex 2026-10-06 立，全文适用）：投递给模型的上下文要素，对人必须也可查——卡片出处行、hover 完整摘录与标题链、注入 chip 构成人的可见面；任何只给模型、人无从核对的标识（如序号）不允许存在。

## 2. 混排编辑器选型：contenteditable（MVP），CM6 为兜底

候选两个（NOTES「实现期选型提示」节），决策如下：

- **采纳：原生 contenteditable + `contenteditable=false` 原子 block 节点。** 理由：
  - 原子节点只有引用卡片一种，混排结构简单（顶层仅 `.qcard` / `.qpara` 两类块）；
  - 常驻内存实测已贴门禁（ADR 0008 Consequences：206–215MB vs 250MB），composer 再引入一个 CodeMirror 实例会进一步压缩余量——contenteditable 零此成本；
  - composer 是短文本场景（几段问题 + 几张卡片），contenteditable 的重灾区长文档编辑（性能、撤销栈规模）不触及。
- **contenteditable 四个已知 quirk 全部写进验收，不允许侥幸**：① 粘贴净化（只接受纯文本，富文本结构剥光）；② IME 组合态与原子节点的交互（组合中不允许删除/跨过卡片）；③ 撤销栈（浏览器原生 undo 对 DOM 干预不可靠，须自管或显式禁用并登记行为）；④ 序列化归一化（回车产生的新块一律归一化为 `.qpara`，不接受裸 `<div>`/`<br>` 进入数据层）。
- **兜底：若 dogfood 中上述 quirk 证明不可控，切换 CM6 block widget 方案**（仓库编辑器已是 CM6，心智同源；代价是内存与「输入框观感」重做）。触发与裁决归 backlog，不在本 change 内预先实施。
- **明确排除**：textarea + 覆盖层渲染（编辑态与显示态分离，光标/选中/IME 全要自己追）。

## 3. 数据模型与序列化协议

- **卡片数据是单一真源**：file（vault 相对路径）、heading（摘录上方最近一级标题；摘录在首个标题之前则为空，出处行仅显示文档名）、headingPath（完整标题链，如 `阅读工作流 › 筛选 › 倒序阅读`——**人侧 hover title 专用字段，不进序列化**）、lines（`A-B`，从选区经 CM6 `lineAt(from)/lineAt(to)` 捕获，必选）、摘录原文。heading 与 headingPath 都在创建时从文档语法树一次算出（复用 toc 的标题解析），随卡片固化，hover 不现查文档。卡片 DOM 只负责渲染；**序列化是卡片数据的投影**——walker 只取 file / heading / lines / 摘录原文四个要投递的字段，不从 DOM 反推、也不取人侧专用字段。
- **序列化格式**（示例，fixture 为合成内容）：

  ```
  <quote file="reading-workflow.md" heading="筛选" lines="9-10">先读结论再读论证——倒序阅读把大部分筛选成本压到最低</quote>
  这段内容是什么意思？
  <quote file="reading-workflow.md" heading="复盘" lines="16-17">每周把「可执行动作」从笔记里捞出来过一遍</quote>
  这里的「可执行动作」指什么？
  ```

- **不变量**：问题文字按交错顺序排布在标签之间（卡片阅读顺序 = 序列化顺序）；属性值与文本节点 XML 转义（`& < > "` 与文本中的 `<`）；lines 非空才允许生成卡片（裁决：「想不到获取不到的场景」，取不到则手势不产出卡片）；`heading` 与卡片出处行显示一致；**无编号**——协议不含任何序号属性（一致性原则）。
- **prompt 层**：序列化结构原样进入用户消息；系统/会话层指引 agent 按摘录内容与出处回指（「『倒序阅读』那段」），同文档多段相似摘录时用 heading / lines 消歧（两者对人也可查，不违反一致性原则）。模型侧适配在两 provider 的消息装配处统一处理，不散落。
- **JSONL 留存**：会话留存记录序列化后的完整消息（含 `<quote>` 块），与既有 append-only 纪律一致。

## 4. 失锚降级链（行为合同）

点击卡片（composer 内或 transcript 内）跳回时：

1. **行号定位 + 原文校验**：按 lines 跳到对应编辑器 pane 的对应行范围，比对命中文本与摘录原文（前缀匹配即可）。匹配 → 定位 + 瞬态高亮。
2. **全文搜索原文**：失配（文档已编辑、行号漂移）→ 在文档内搜索摘录原文字符串；命中 → 定位到命中处 + 瞬态高亮。
3. **告知失锚**：仍找不到 → toast 告知「该摘录已失锚」（复用 notice 组件），不静默猜位置、不跳到错误段落。

目标文档未打开时，先在最近活跃编辑器 pane 打开该文件再走降级链；文件已不存在直接进第三层。

## 5. 手势与装配

- **创建手势**：编辑器选区变化（selectionchange）时，在最近活跃编辑器 pane 的选区右下浮现「摘录到对话」钮；选区坍缩即消失。点击不依赖焦点保持——平时记录编辑器内最后选区，点击时恢复并在 composer 光标处插入卡片。harness 面板未打开时先打开（现行 ⌘⇧A 同路的唤起逻辑）。
- **插入落点**：卡片落在 composer 当前光标处（光标在段落中间则把段落拆为两段、卡片插中间）；**插入后光标落到卡片下一行的问题段落**——卡片之后已有空 `.qpara` 则复用、否则新建（Alex 2026-10-06 裁决：摘录完直接写问题）。
- **pane 归属**：摘录来源恒为「最近活跃编辑器 pane」的选区（ADR 0008 Decision 3）；harness 面板持焦不改变该归属。原型妥协点 12 的「活跃 pane 无可见表达」是既有开放问题，本 change 不解决、也不因之阻塞（摘录动作本身即隐含用户刚操作过哪个 pane）。
- **瞬态纪律**：编辑器侧只存在两种瞬态——进行中的选区（含浮动钮）、跳回高亮（~1.4s 消退，借用 pending-tint / find-in-page 黄语义，eink 转 10% 黑）。零常驻装饰。

## 6. 既有「上下文注入」改造点

- 现行 living spec：选区存在时自动注入选区内容。本 change 移除该自动注入——选中片段一律经卡片手势显式策展。
- 保留：当前 TAB 的 vault 相对路径始终注入；无引用卡片时注入视口行范围（chip 标明视口）。
- 新增跳过规则：消息携带引用卡片时，该条消息不再附加视口注入（用户已显式策展，避免同文重复进上下文）。
- 输入区上方的可核对 chip 保留（路径 + 视口摘要），卡片在 composer 内即可核对，不另设呈现位。chip 即一致性原则在自动注入侧的落实：模型拿到的自动上下文，人在 chip 里都能核对来源。

## 7. 验收面（机器判定锚点）

- **真机验收新场景**（scripts/acceptance）：① 选区 → 浮动钮 → 卡片入 composer（含面板未开时先开）；② 混排交错编辑（光标处拆段插入、插入后光标落卡片下一行、× 移除）；③ 序列化结构断言（file / heading / lines 三属性、lines 非空、交错顺序、转义、无编号属性）；④ 失锚降级三层（行号命中 / 漂移搜索命中 / 失锚 toast）；⑤ transcript 同构沉淀；⑥ 粘贴净化。mock provider 驱动，不依赖真实 API。
- **视觉**：harness 面板新 UI（卡片、浮动钮、跳回高亮）新增场景基线（Alex 过目后 --update）；既有 harness 相关基线按纪律核对时间戳。
- **单元/属性测试**：序列化 walker 的不变量（无编号、转义 round-trip、交错顺序、heading 与卡片显示一致）走属性测试口径（rendering-defect-contract-first 纪律）。
- **门禁**：`scripts/gate.sh quick` 全绿；动过 `src/style.css` / `src/preview` 级视觉面则补 `visual` 档。
