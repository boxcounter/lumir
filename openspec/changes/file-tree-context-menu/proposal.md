# Proposal: 文件树条目右键菜单（删除 / 重命名 / 复制完整路径 / 在 Finder 中显示 / 目录下新建）

- Change ID: file-tree-context-menu
- 日期: 2026-09-26
- 角色: Alex Lee（评审/裁决），AI agent（起草）

## Why

Alex 需求原话（2026-09-26）：**「左栏，也就是文件目录栏，增加右键操作项：删除、重命名、复制完整路径、
在系统文件查看器里打开、（如果是目录）创建文件、（如果是目录）创建子目录」**。

### 一、诉求面在哪：文件树的「文件级操作」今天全部要出 app

文件树（`src/tree.ts`）今天只有三种交互：单击打开（preview/pinned 分流，`:162-169`）、目录折叠
（`:157`）、树头部 vault 切换器（`:230-250`）。**任何文件级操作——改名、删除、新建、拿到路径去
别处用——都必须离开 Lumir 去 Finder 完成**，再依赖 watcher 把结果回响回来（`fs:entry_changed`，
`src/main.ts:869-897`）。dogfood 高频动作（整理想法、给笔记改名、归档旧文件）因此每一次都要
切换应用。这六个操作项是补齐「文件管理闭环」的最小集合，全部挂在条目上，不引入新的界面区块。

### 二、必须在提案层定死的三件事

| # | 设计点 | 为什么必须在提案层定死 |
|---|---|---|
| 1 | **删除语义与「不改写源文件」铁律的关系** | 铁律（ADR 0003 §3）约束的是**渲染/编辑对文件内容的改写**；删除/重命名是用户显式发起的文件级操作，不在铁律的字面范围内。但删除不可逆性是真实风险，护栏形态（废纸篓 + 确认 vs 永久删除）是产品裁决，不是实现细节 |
| 2 | **删除/重命名命中已打开 tab 时的行为** | 已打开文件被删除/重命名会撞上 M124/M127 保存链路（`save-controller.ts:562-586`）。watcher 把改名拆成 `deleted:old` + `created:new`（`fs_io.rs:468-516`）：session remap 到新路径后，`created:new` 会命中它并走 dirty 分支——用户自己改名被误报为「检测到外部修改」（暂停自动保存 + sticky 提示）——这是错误归因。处置口径是行为契约，必须裁决 |
| 3 | **菜单实现形态** | 仓内无任何右键菜单先例（`src/` grep `contextmenu` 零命中）。Tauri 原生菜单（tauri 2.11.5 的 `ContextMenu::popup`）与 web 自绘浮层（vault-switcher 浮层同形）是两条路，主题一致性、验收可断言性、键位体系的走向完全不同，裁决后不再回头 |

## What Changes

1. **文件树条目右键菜单**。文件行与目录行各自挂右键菜单（目录行多出「新建文件 / 新建子目录」两项）。
   菜单形态为 **web 自绘浮层**（裁决点 1 推荐项）：与 vault-switcher 浮层同一份模式（listbox 语义、
   ↑↓/⌃N⌃P 导航、Enter 触发、Esc 关闭、点击外部关闭），主题 token 与 eink 反白规则自动继承。
   （delta：ADDED `file-tree / 条目右键菜单`）

2. **删除 = 移到废纸篓 + 确认对话框**（裁决点 2，**已裁决 2026-09-26**）。目录删除连同全部子孙进
   废纸篓；确认对话框对目录明示「连同其中全部内容」。MUST NOT 提供永久删除入口。删除后树节点经
   watcher 回响统一收敛（不自绘补丁）。（delta：ADDED `file-tree / 条目删除（废纸篓）` +
   `fs-io / 文件级操作`）

3. **重命名 = 树内联编辑**（裁决点 3，**已裁决 2026-09-26**）。行名就地变输入框，Enter 提交、
   Esc 或失焦取消；即时校验（空名 / 含 `/` / 忽略集名 / 目标已存在）拒绝并给原因。v1 只支持同目录
   改名，不支持跨目录移动。（delta：ADDED `file-tree / 条目内联重命名` + `fs-io / 文件级操作`）

4. **复制完整路径 = 绝对路径**（裁决点 4，**已裁决 2026-09-26**）。写入系统剪贴板的是绝对路径
   （vault 根 + 相对路径拼接），纯前端 `navigator.clipboard` 完成，不新增后端命令。
   （delta：ADDED `file-tree / 复制完整路径`）

5. **在系统文件管理器中显示（reveal）**。macOS 语义 = Finder 中选中该条目，经既有 opener 插件的
   Rust 侧 API 落地（`OpenerExt::reveal_item_in_dir`，与 `link_open_path` 同一条最小权限路径，
   opener 的 webview ACL 保持默认拒绝、capabilities 零增量）。（delta：ADDED `file-tree / 在系统
   文件管理器中显示` + `fs-io / 文件级操作`）

6. **目录行：新建文件 / 新建子目录**。命名同样走内联编辑（与重命名同一形态、同一校验）；新建文件
   为空文件，创建成功后自动打开（md 进编辑模式）。命名冲突用 `create_new` 原子语义拒绝，不覆盖。
   （delta：ADDED `file-tree / 目录下新建` + `fs-io / 文件级操作`）

7. **已打开 tab 的联动**（裁决点 5 推荐项）：app 内**重命名**命中打开中的 tab 时，前端就地 remap
   session 路径（含目录重命名的前缀 remap），dirty 内容与 revision 基准保留（改名不改字节），并对
   watcher 回响做一次性归因抑制（`deleted:old` 与 `created:new` 两个事件都在 session 链路吞掉，
   树照常收敛）——MUST NOT 报「已被外部删除」或「检测到外部修改」。app 内**删除**命中打开中的
   tab 时，沿用既有 watcher 删除处置（tab 保留、自动保存暂停、sticky 提示、内容不丢，
   `save-controller.ts:564-569`），不另开分支。（delta：ADDED `fs-io / app 内文件操作的 tab
   联动`，MODIFIED 语义挂在既有「watch 增量事件流」旁注）

## Non-goals

- **跨目录移动**（拖拽或「移动到…」对话框）：重命名 v1 只改末段名；移动牵涉 link graph 重定向与
  wikilink 断链处置，单独成 change。
- **撤销（undo）**：删除的可恢复性由废纸篓承担；重命名 v1 无 undo，改名再改回来即可。
- **永久删除开关 / ⌥修饰删除**：任何绕过废纸篓的入口都不提供（裁决点 2）。
- **多选与批量操作**：右键只作用于单条目；多选是树的选中模型问题，不在本 change。
- **vault 根目录 / 树空白区 / vault 头部行的右键菜单**：根级新建与根操作留待 dogfood 后另行裁决
  入口形态；本 change 菜单只挂在条目行上。
- **新建文件模板 / 默认内容**：新建即空文件。
- **重命名/删除对 wikilink 与相对路径链接的重写**：改名后存量链接可能断链——断链表现沿用既有
  「链接目标不存在」提示（`link_resolve_note` 返回 None 的既有口径），本 change MUST NOT 改写任何
  文档内容去追随改名（ADR 0003 §3 铁律字面适用）。
- **键位绑定与命令面板入口**：六个操作项只有右键菜单一个入口，不进 keymap-commands（留待 dogfood
  后按使用频率裁决）。

## 裁决点

> 状态标注：**已裁决** = Alex 2026-09-26 预裁决（逐字记录见各条）；**待裁决** = 本提案给出推荐项，
> 等节点 1 拍板。

### 裁决点 1：菜单实现形态 —— web 自绘浮层 vs Tauri 原生菜单 【待裁决，推荐 web 自绘】

- **推荐：web 自绘浮层**。理由：
  1. **同形先例已在仓内**：vault-switcher 浮层（`src/vault-switcher.ts`）就是自绘 listbox 浮层，
     含 aria 语义、↑↓/⌃N⌃P 导航、Esc 关闭、外部点击关闭的完整模式；右键菜单复用这套模式，零新
     交互范式。
  2. **主题一致性结构性成立**：自绘浮层吃同一套 token（M211 token 层），深色与 eink 反白自动继承；
     原生菜单不随 app 主题，eink 主题下会出现系统默认配色的菜单，与 Restyle 批次的方向直接冲突。
  3. **可断言性**：验收套件与视觉门禁都在 DOM/AX 层工作，原生菜单在 WKWebView 之外，真机场景 47
     无法断言其内容与行为——选原生等于放弃验收下沉通道。
  4. **键位体系同构**：自绘菜单的就地键匹配可复用 `keyToken` 口径（bindings-panel 先例），原生
     菜单的键盘导航由系统持有，与本仓 Emacs keybinding 方向不连通。
- 备选：Tauri 原生菜单（tauri 2.11.5 `ContextMenu::popup`，本机 registry 实证存在）。优点是
  系统观感原生、免维护焦点管理；否决理由即上列 2/3/4。
- **实现期成本差**：自绘 ≈ 复用浮层模式 + 一份菜单定义；原生 ≈ 每次弹出前 Rust 侧动态构建菜单 +
  IPC 回调分发，且要新增一套菜单事件通道。自绘在两轴上都更便宜。

### 裁决点 2：删除语义 —— 移到废纸篓 + 确认对话框 【已裁决 2026-09-26】

- **裁决（Alex 原话「采纳你的推荐」）：移到废纸篓 + 确认对话框。** 永久删除进被否决项。
- **与「不改写源文件」铁律的关系（提案层必须写明）**：铁律（ADR 0003 §3）约束的是**渲染与编辑
  链路对文件内容的改写**——预览不碰字节、打开不产生改动。删除/重命名是**用户显式发起的文件级
  操作**，意图本身就是改变文件系统的组织而非改写内容，不在铁律字面范围内；但铁律背后的原则
  「Lumir 绝不静默改变用户的 vault」完全适用，因此护栏是：删除必须**两步**（菜单选择 + 确认
  对话框）且**可恢复**（废纸篓，而非 `remove_file`）；任何失败路径 MUST NOT 留下半删除状态。
- 被否决：永久删除（含 ⌥修饰绕过确认）。理由：vault 是用户的知识库原文，一次误击的代价是
  不可逆丢失；废纸篓在 macOS 上是零学习成本的恢复通道。

### 裁决点 3：重命名形态 —— 树内联编辑 【已裁决 2026-09-26】

- **裁决（Alex 原话「树内联」）：树内联编辑。** 对话框进被否决项。
- 落点：行名就地替换为输入框（Finder/VSCode 同形），Enter 提交、Esc/失焦取消，即时校验。
- 被否决：模态对话框。理由：改名是高频微调动作，模态打断「扫一眼树、就地改掉」的节奏；且内联
  形态与「新建文件/子目录的命名」可共用同一实现，对话框则要做两套。

### 裁决点 4：复制路径的内容 —— 绝对路径 【已裁决 2026-09-26】

- **裁决（Alex 原话：复制路径 = 绝对路径）：写入剪贴板的是绝对路径。** vault 相对路径进被否决项。
- 落点：绝对路径 = vault 根（装载时已知）+ 树内相对路径拼接，纯前端完成，零后端往返。
- 被否决：vault 相对路径。理由：复制路径的用途是把路径拿去终端 / 其他 app / 脚本里用，相对路径
  离开 vault 上下文即失效；相对路径的需求（写文档链接）由 wikilink / 相对路径链接链路承担，
  不经剪贴板。

### 裁决点 5：已打开 tab 的文件被删除/重命名时的行为 【待裁决，推荐如下】

- **推荐**：
  - **app 内重命名** → 打开中的 tab 就地 remap 路径（文件改名 = 单 session 路径替换；目录改名 =
    其下所有打开 session 的前缀 remap）。dirty 内容、revision 基准、滚动与光标状态全部保留
    （改名不改字节，CAS 基准依旧有效）。watcher 对这次改名的回响（deleted 旧 + created 新）做
    一次性归因抑制——两个事件都在 session 链路吞掉（树照常收敛），MUST NOT 走「已被外部删除」
    或「检测到外部修改」分支（机制细节见 [design.md](design.md) §3.2：remap 后 `session.path`
    已是 new，真正会误命中 dirty session 的是 `created:new`）。
  - **app 内删除** → 沿用既有 watcher 删除处置：tab 保留、自动保存暂停（`not-found`）、sticky
    提示「内容未丢失」（`save-controller.ts:564-569` 现状）。理由：删除经确认对话框已是显式
    两步，提示文案把「文件没了但内容还在」说清即可；强关 tab 反而会把未保存内容逼到崩溃备份
    通道，是更差的结局。
  - **外部发起的删除/改名**（Finder 等）→ 完全沿用 watcher 现状处置，本 change 不碰。
- 备选：删除时直接关闭对应 tab。否决理由：与 M127「内容不丢优先」的加固方向相反；dirty tab
  被强关会把恢复责任推给崩溃备份链路，而那条链路的定位是**事故**兜底，不是正常操作语义。
