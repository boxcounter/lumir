# Proposal: vault 切换的即时反馈与浮层定位修复

- Change ID: vault-switch-feedback
- 日期: 2026-09-27
- 角色: Alex Lee（评审/裁决），AI agent（起草）

## Why

Alex 2026-09-27 真机反馈原话，两条：

> 「需改进：4. 当左栏滚动到中部时，我通过 CMD + O 调出的 vault switcher 显示不全，导致我无法切换到某个 vault。」
>
> 「新需求：切换 vault 时，会卡住几秒。我会愣住，以为刚才点击没点中，然后才出现系统的转圈提示，我才明白在加载中。」

**一、浮层显示不全是一条定位算式与滚动位置的耦合缺陷。** 切换器浮层挂载在 app-shell 根上、`position: absolute`，纵向位置由入口的视口矩形算出（`src/vault-switcher.ts` 的 `place`）。而入口（树头部的 `.ft-vault`，`src/tree.ts`）落在左栏的滚动容器 `.tree-pane`（`overflow: auto`，`src/style.css`）里、**不是 sticky**：左栏一滚到中部，入口的视口矩形整个跑到窗口之上，旧算式 `anchor.bottom - host.top + 4` 于是给出一个远在窗口之外的负 `top`，浮层整块落在视口外——用户看不见列表，也就切不到任何 vault。这与「浮层宽度允许溢出左栏」的口径不冲突：溢出的是宽度，纵向却被窗口本身裁掉。

**二、切换期间没有任何即时反馈，用户把它读成「没点中」。** 现状的可见序列是：点行 → 浮层收起 → **界面不动几秒**（对方系统开始转圈）→ 整窗上下文一次性换掉。`vault_open_path` 是一条异步 command（Rust 侧做注册表对账、起 watch、全量枚举、逐文件读正文建链接索引），装载后的会话恢复又是逐标签异步的——两段都在等待，界面在等待期间既不重绘也无需重绘，用户没有任何可归因的信号。这是纯粹的反馈缺失：一次点击已经在处理中，界面却与「什么都没发生」不可区分。

**三、本 change 触及一条既有 spec 的显式禁令，必须一起改。** `vault-workspace` 的「vault 切换与整窗上下文替换」写着「本版 MUST NOT 引入进度条 / 遮罩 / 行内进度等过渡元素」，理由是「同步打开路径下界面在此期间不重绘，这类元素不可见」。这条理由的自陈前提已经不成立：M159 把启动恢复移出主线程（`startup-restore-off-main-thread`），`vault_open_path` 本身是异步 command，前端在等待它时事件循环是空的——界面**会**重绘，指示元素不但可见，而且正是缺的那件东西。因此本 change 以 MODIFIED 的方式改写这条要求：仍然不许加遮挡式/百分比式过渡元素，但把「无文案的不确定进度指示」变为要求。

## What Changes

1. **浮层定位夹进挂点矩形（修「显示不全」）**：`place` 把纵向位置夹在 `[0, 挂点高 − 浮层高 − 边距]` 内；入口在视口内时结果与现状逐像素一致（不引入位移），入口被滚出视口时浮层贴在视口上沿、列表完整可见且自身可滚。纵向余量小于浮层高度时（窗口很矮）把 `max-height` 压到实测可用空间——列表仍然是唯一的滚动容器。
2. **装载指示：标题栏右端的无文案转圈**：用户发起的装载（切换 / 重定位 / 新增）从「用户做出决定的时点」起显示一个不确定进度指示，直到**装载 + 会话恢复**跑完才消失；不使用任何新文案（不新增文案 deck 条目），不放遮罩、不挡交互、不改任何既有元素的常态布局（`hidden` 时 `display: none`）。
3. **装载各阶段的耗时读数（诊断面）**：`vault_open_path`、树重建、会话恢复三段各记一条超过阈值（250ms）的 `slow_callback` 诊断事件（既有事件名 + 白名单字段 `name`/`ms`，不新增事件、不动 Rust 侧）。它是本次「几秒卡在哪一段」的定位手段，也让 Alex 真实 vault 上的同类反馈可以就地量出读数，不必等 agent 复现。

## Non-goals

- **不把装载移出主线程 / 不优化装载本身**：几秒的根因定位与结论随本 change 交付（review-request + 诊断读数），但压缩它要么动 Rust 侧（不在本 change scope）、要么重写树的全量重建策略（跨 capability 的大改）。本 change 只保证「等待期间用户知道在等」。
- **不做进度百分比、不做遮罩、不做行内进度**：不确定进度指示（无文案转圈）是本次的全部过渡元素。
- **不给指示加文案、也不加读屏名**：文案 deck 是单一来源，本指示不对应其中任何一条；由此产生的可访问性缺口如实记在 design 的「已知边界」里，不靠自加一条文案补。
- **不改浮层的宽度语义、不改列表排序与筛选**：320px 允许溢出左栏、后端给出排序、每次打开重新拉取，全部照旧。
- **不给会话恢复加取消 / 中断入口**：用户在恢复途中再切一次 vault 的行为沿用既有世代让位规则。

## Impact

- 影响的 specs：`vault-workspace`（两条 ADDED、一条 MODIFIED）
- 影响的代码/系统：`src/vault-switcher.ts`（浮层定位、装载指示工厂）、`src/main.ts`（指示与三段耗时的装配）、`src/style.css`（指示的样式）；无 Rust 侧改动、无新增命令、无新增配置项
- 关联约束：ADR 0002 §6 性能合同（新增元素只在装载期间存在，空闲态零布局影响）；ADR 0003（不写 vault、不新增 IO）；ADR 0006（键位与入口形态不变）；真机验收套件场景 49 随本 change 同 PR
