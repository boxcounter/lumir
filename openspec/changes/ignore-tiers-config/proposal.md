# Proposal: 内置忽略名单分两档，落进配置默认

- Change ID: ignore-tiers-config
- 日期: 2026-10-17
- 角色: Alex Lee（评审/裁决），AI agent（起草）

> 评审记录：
> 节点 1（提案评审）：2026-10-17 Alex 批准（tower 转达），附三条裁决修正：
> ① 「缺省即默认」修正**采纳**（本文即此写法，保持）；
> ② **`.git` 恒护栏被拒绝**——删除已有提醒且只进系统回收站，重命名 / 移动是可撤销动作，产品立场是
>    不过度保护用户；实现与文档中 MUST NOT 出现该护栏，`.git` 与普通可见条目同规则；
> ③ 键名改为 **`hidden` / `lazy`**（原 `never_show` 更名 `hidden`），代码、schema、文档与验收场景统一。
> 节点 2（归档评审）：留白（实现完成后填写）。

> **对 Alex 原话的一处修正（已复核并采纳）**
>
> Alex 原话要求「一安装就会生成的配置文件里的默认配置」。本提案改为**「缺省即默认」**：
> `config.json` 里没有这两个键 = 用代码内置默认；写了 = 覆盖该档（显式写 `[]` 也是覆盖，表示这一档没有名字）。
>
> 理由：安装时把默认值快照进配置文件，会把默认名单**冻结在初装那一天**——未来版本调整默认值触达不到
> 存量配置，用户看到的是「升级了但行为没变」，而根因埋在几年前的一份 JSON 里。配置只承载**用户的偏离**，
> 默认值只有一个真源（代码）。这与 [config-reference.md](../../../docs/specs/config-reference.md) §3
> 既有的写回纪律同口径：应用只做单键合并、**不写全量默认**（该节原文已写明「不推荐把全量默认写进
> `config.json`」及其理由）。

## Why

Alex 原话（裁决，逐字）：

> 「『惰性』和『不显示』变成配置项，目前硬编码的值变成设置在配置文件里的默认值，也就是一安装就会生成的配置文件里的默认配置，我可以修改，这样我可以体验和调整，避免硬编码在代码里，我只能接受、想调整只能改代码打包。」

现状与问题：

1. **分档名单是产品硬编码**：[src-tauri/src/fs_io.rs:38](../../../src-tauri/src/fs_io.rs#L38) 的
   `BUILTIN_NAMES` 是 16 个名字字面量，[fs_io.rs:67](../../../src-tauri/src/fs_io.rs#L67) 的
   `LUMIR_TMP_PATTERNS` 是两条临时文件模式。16 个名字**全部落在「不可见」一档**——它们在树里没有行、
   不进索引、watch 事件被挡下。改动其中任何一个档位都要改代码、重新构建、重新安装，自用者也拿不到
   「试一下再改回来」的路径。
2. **配置面已有先例，语义不用另造**：[src-tauri/src/config.rs:169](../../../src-tauri/src/config.rs#L169)
   的 `[vault]` 表已经承载 `rule_files`（用户规则的来源清单），在 vault 装载时现场读一次
   （[commands.rs:456-459](../../../src-tauri/src/commands.rs#L456)）。本 change 把两个新键放进同一张表，
   沿用同一套解析、校验、warning 与生效时点，不新增配置机制。
3. **「惰性」不是新行为**：用户规则命中的条目今天就是「树里有一行、不递归枚举、不进索引、按需展开」
   （change `vault-open-ignore-set` 落地的 `EntryClass::Lazy`，[fs_io.rs:218](../../../src-tauri/src/fs_io.rs#L218)）。
   本 change 只是把这套既有去向接到配置给出的名字上——不是发明第二种惰性。
4. **同一份名单今天有两处真源**：[src/tree.ts:44](../../../src/tree.ts#L44) 抄了一份 16 名清单供内联编辑预检，
   逐项对账在 [tests/unit/tree-paths.test.ts:86](../../../tests/unit/tree-paths.test.ts#L86)（解析 Rust 声明）。
   名单一旦可配置，「抄一份默认」必然要么假拒（用户把某名字移出默认，前端仍拒）要么漏拒，对账链也失去意义。
   本 change 顺手把这条重复真源切断（见 What Changes 第 7 条）。
5. **合规基座**：ADR 0002 第 5 条「配置即数据，带 schema 校验，非法值落回默认值并给出人话错误」——
   两个新键的解析、逐项校验与人话 warning 按该条办。

## What Changes

对应 `specs/fs-io/spec.md` 的 4 条 MODIFIED 与 `specs/file-tree/spec.md` 的 3 条 MODIFIED。

1. **两个配置键**（`[vault]` 表内，与 `rule_files` 并列）：

   ```json
   {
     "vault": {
       "hidden": [".git", ".DS_Store"],
       "lazy": ["node_modules", "target", "dist", "..."]
     }
   }
   ```

   - 值是**名字数组**，不是模式：每项必须是单个名字（不含 `/`、不是 `.` / `..`、不含 gitignore 通配
     元字符 `* ? [ ] ! # \`、首尾无空白）。写模式的（如 `"*.log"`）逐项忽略并给人话 warning——本版
     不支持模式，`MUST NOT` 猜用户意图。
   - **缺省即默认**：某个键缺席（或缺整节）⇒ 该档取代码内置默认；键存在（即使 `[]`）⇒ 该档整体按
     用户给的名字解释。
   - **两个键都不含某个名字 ⇒ 该名字走用户规则 / 完全可见**：这就是「第三档」，不需要第三个键。
   - 逐项非法 ⇒ 丢该项 + 一条人话 warning，其余项照常生效（与 `rule_files` 同形）；整个字段给错类型
     （如 `"hidden": ".git"`）⇒ 既有解析模型下的整文件回落（与 `editor.font_size` 同族，如实登记）。
   - 同一个名字同时出现在两个键里 ⇒ **按 `hidden` 生效** + 一条 warning（不静默择一）。
   - 生效时点与 `rule_files` 一致：vault 装载时读一次，**下次装载生效**，不做热重载。

2. **默认分档（代码内置默认）**：
   - `hidden` = `[".git", ".DS_Store"]`。理由：`.git` 是仓库对象库、删除即仓库报废（破坏性操作面）；
     `.DS_Store` 是纯系统噪声。这两个名字「不显示」比「惰性可见」更符合它们的用途。
   - `lazy` = 其余 14 名：`node_modules`、`.venv`、`venv`、`__pycache__`、`.next`、`.nuxt`、`.cache`、
     `.pnpm-store`、`.tox`、`.gradle`、`test-results`、`perf-results`、`target`、`dist`。
     它们是构建产物 / 依赖副本 / 工具链输出——按结构可推导，但不含用户正文，默认给「树里可见、
     按需展开、不进全量枚举与索引」，与既有用户规则惰性**同待遇**。
   - **保存临时文件模式恒定硬编码**：`.lumir-*` / `.*.lumir-*` 不进配置面。那是数据损坏面（应用自己的
     保存中途文件与崩溃残留），不是「用户可调偏好」；即使把 `hidden` 写成 `[]`，它们仍被挡下。
   - **默认分档是一次有意的行为变化**：升级后首次打开 vault，14 个名字对应的目录会从「没有行」变成
     「一行惰性条目」（例如 `node_modules`、`target`、`dist`）。枚举代价不变（惰性条目本来就不递归），
     索引面不变（惰性条目仍不进索引），变化只在**可见性**——这正是 Alex 要的「看得见、点开才付费」。

3. **判定顺序固定为四层**：`hidden` 档（含恒定临时文件模式）→ `lazy` 档 → 用户规则（`.gitignore` /
   `info/exclude`）→ 可见。
   - 前两档命中即定格：用户规则里的取反（`!target/`）`MUST NOT` 把 `hidden` 或 `lazy` 档的名字翻走
     （惰性档被取反后若能翻成「完全可见」，就等于一行 `.gitignore` 把该名字拉进索引与全量枚举——性能
     护栏又回到用户可关的状态）。
   - **这是对 change `vault-open-ignore-set` §2.6 条款的显式修订**：原条款写「内置名单是产品硬编码、
     `MUST NOT` 被用户规则推翻」。修订后：**分档机制与判定优先级仍是产品硬编码、仍不可被用户规则推翻；
     变的是名字清单的来源——从代码常量变成「配置默认值 + 用户覆盖」**。原条款的论证（来源不同级、
     性能护栏不能由一行编辑关掉）逐条继续成立，只是「改名单」的出口从「改代码走 change」变成「改配置」。
     两份 spec 因此不打架：`.gitignore` 语义仍只管用户规则那一层。

4. **watch 增量事件流的判定按档分流**（与枚举同一份策略）：
   - `hidden` 档：路径任一组件命中（含最后一段）⇒ 丢弃（与今日内置规则的行为逐条一致）。
   - `lazy` 档：与用户规则同形——祖先命中且该目录**尚未被按需展开** ⇒ 丢弃；最后一段一律投递；
     payload 的 `lazy` 标记按同一份规则表算出（`lazy` 档或用户规则命中 ⇒ true）。因此外部 `mkdir target`
     现在会产生**一行惰性条目的 created 事件**（树里多一行，与枚举结果一致），但其中的子孙事件在展开前
     不投递。`.git` / `.DS_Store` / 临时文件仍然一个事件都不投递。
   - 惰性条目（无论来自哪一档）继续不进链接索引与附件索引；删除方向仍无条件移除。

5. **埋点口径**：`vault_scan_ignored`（[logging.rs:490](../../../src-tauri/src/logging.rs#L490)）只统计
   **被 `hidden` 档（含临时文件模式）剪掉的条目数**。惰性条目有行、看得见，不属于「文件不见了」的
   诊断对象；事件名、字段与隐私口径（只有计数）都不变。

6. **新建 / 改名的名字校验**：末段名命中 `hidden` 档（含临时文件模式）⇒ `fs_name_invalid`（沿用既有
   文案口径）；命中 `lazy` 档或用户规则 ⇒ `MUST NOT` 拒绝（该名字本来就可见、可打开，只是不进索引）。
   判定改由装载时编译的同一份策略给出，不再读某个进程级常量表。**没有任何名字级写操作特判**
   （裁决 ②）：`.git` 与其他名字同规则——它默认在 `hidden` 档，因此默认没有行、不可操作；用户把它
   配置成可见后，它就与普通条目一样可删 / 可改名 / 可移动。

7. **前端内联编辑预检的重复名单退役**：[src/tree.ts:44](../../../src/tree.ts#L44) 的 `IGNORED_NAMES`、
   对应的对账测试、以及 `validateEntryName` 里的名单判定一并删除。前端保留形状校验（非空 / 不含 `/` /
   不是 `.`/`..` / 不撞名），忽略集判定只由后端做；后端拒绝时把人话原因经既有通道回显在编辑行内
   （[main.ts:1803](../../../src/main.ts#L1803) 的 `tree.endInlineEdit(false, errorMessage(e))` 已是现成路径）。
   代价：从「按下 Enter 立刻红」变成「一次本地 IPC 往返后红」（毫秒级）。收益：名单可配置后再无第二份
   真源可漂移，`tests/unit/tree-paths.test.ts` 的对账链随之退役。

## Non-goals

- **不支持模式**（`*.log`、`build*`、`!foo`）：两个键只收名字。支持模式会引入「配置项其实是 gitignore
  语法」的第二套语义，且与「内置规则写成名字字面量」的既有等价承诺冲突。要忽略一类别名，逐个列出。
- **不做 per-vault 覆盖**：一份全局配置，与 `rule_files` 同口径。per-vault 覆盖是另一个配置面，另立 change。
- **不做运行期热生效**：改配置下次打开 vault 生效；不新增「重扫 / 重编」通道。
- **不做「显示被忽略项」开关**：想看某个名字就把两个键里的它删掉（变完全可见）或只挪到 `lazy`
  （可见但不进索引）。第三档由「两个键都不含」天然表达，不新增开关。
- **不把临时文件模式配置化**：`.lumir-*` / `.*.lumir-*` 恒定硬编码，见 What Changes 第 2 条。
- **不改用户规则机制**：`rule_files`、`.gitignore` 的匹配语义、优先级与生效时点一律不动。
- **不做配置文件自动生成 / 默认值快照**：见文首对 Alex 原话的修正。
- **不自动迁移存量行为**：默认分档按本文生效，不读旧版本、不留兼容分支（`AGENTS.md`「变更默认直接切断」）。
- **不改枚举 / 索引 / 按需展开的既有代价模型**：惰性条目不递归、不进索引这两条不变。

## 裁决点

| # | 裁决点 | 推荐 | 备选 | Alex 裁决 |
|---|---|---|---|---|
| 1 | `.git` 是否加「不可重命名 / 删除 / 移动」的**恒护栏**（与分档无关，即使 `.git` 被配置成可见） | 加 | 不加 | **拒绝护栏**（2026-10-17）。理由（Alex 原话口径）：删除已有提醒且只进系统回收站，重命名 / 移动是可撤销动作，产品立场是不过度保护用户。落点：`.git` 与普通可见条目同规则——默认在 `hidden` 档没有行；用户把它配置成可见后即可删 / 改名 / 移动，代码与制品中 MUST NOT 出现该护栏或任何名字级写操作特判。 |
