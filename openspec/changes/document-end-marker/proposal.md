# Proposal: 正文末尾的「到底了」标记（文档结束的可见终点）

- Change ID: document-end-marker
- 日期: 2026-09-21
- 角色: Alex Lee（评审/裁决），AI agent（起草）

## Why

Alex 需求原话（2026-09-21）：**「需求：文件底部有"到底了/完"的装饰，让用户意识到没有更多正文内容了。」**

**更正记录（tower Notes，2026-09-21）**：任务 context 里紧跟原话的那句「我在阅读这篇文章是遇到这个问题：`…/s08_context_compact/README.md`」系 Alex 说串了，它归属 M187（svg 滚动缺陷），**与本需求无关**。本需求是独立的一条：无特定触发文章，context 里「该文末尾紧接 svg 滚动缺陷的触发场景」的推断一并作废。本条改正在本 change 的制品里已落实——Why、Non-goals、design 都不再引用任何具体文章，也不把 svg 滚动缺陷当相邻问题承揽（改动见本节与 Why 二、Non-goals）。

### 一、诉求面在哪：正文末尾今天没有「终点」线索，滚到底与还在滚没有区别

现象：滚过正文最后一行之后再滚，界面上不会发生任何变化——用户无法区分「正文到此结束」与「下面还有，只是还没滚到」。这不是某一篇文档的特例：只要文档超过一屏，缺口的形态就一样。

| # | 现状事实 | 锚点（可复核） |
|---|---|---|
| 1 | 没有独立的 preview 栏：全应用只有一个 `EditorView`，「预览」是 md 模式下叠在同一个编辑器上的装饰层 | `src/editor.ts:1049-1353`、`src/editor.ts:1180-1254` |
| 2 | 正文末尾今天**只有一个 44px 内边距**，其后没有任何元素；顶部则是同一份 44px 内边距 +（文档有 frontmatter 时）properties 卡片——上下不对称 | `src/editor.ts:1222`（`paddingBlock: "44px"`）、`src/preview/frontmatter.ts:104-179`、`src/preview/theme.ts:167` |
| 3 | 文末的**空行连一点视觉差别都没有**：live preview 把空行渲染成 0 高的装饰行，再多空行也生不出留白 | `src/preview/livePreview.ts:620-634`、`src/preview/theme.ts:56` |
| 4 | md 模式没有行号、没有状态栏、没有滚动百分比；全应用唯一「我在哪」的读数是 masthead 的当前标题段，而它只在文档有标题时出现 | `src/shell.ts:39`、`src/toc.ts:283-290` |
| 5 | 现有装饰层只为可见区域构建、滚动时增量更新（打开 1MB < 100ms 的性能合同）——任何「末尾元素」都不能破坏这条义务 | `src/preview/livePreview.ts:585`、`:439-452` |

结论：今天「到底了没有」唯一的线索是原生滚动条，而它的可见与否取决于 macOS 的滚动条设置（默认仅在滚动时浮现）。诉求面因此是真实的、可复核的，且与「读的是哪一篇」无关。

### 二、与相邻问题的边界（本 change 只解第 1 条）

1. **「还有内容吗」的感知缺口** —— 本 change 的诉求面，用正文末尾的一个装饰标记回答。
2. **图片异步加载引起的文档高度变化** —— **不承揽**，归 [image-reading 质量合同](../../../docs/specs/image-reading.md) §1–§3（M182 已收口）。本 change 与它的唯一关系是**判据设计约束**：文档高度会随异步图片的到达而变，因此本 change 的显隐判据 MUST NOT 依赖滚动位置（理由与取舍见 [design.md](design.md) §2）。
3. **其它滚动缺陷** —— **不承揽**，含 M187 的 svg 滚动缺陷（tower 记录：这是另一个 mission 的诉求，与本需求无关）。本 change 不碰滚动行为，也不做任何缺陷排查。

### 三、另外三条在需求原话之外、但决定这个标记能不能站住

- **它必须是装饰，不是内容。** 不得进文档、不得被 ⌘A 带出、不得被 ⌘F 命中（ADR 0003 §3 铁律 + 「用户读到的正文不能被应用伪造成正文」）。这一条排除了「实现期顺手往文末插一行」的做法，也决定了它不能与作者手写的结构同形。
- **它必须与作者手写的分隔线可区分。** 文档里的 `---` 已经渲染成**通栏**发丝线（`.cm-lp-hr`，`src/preview/theme.ts:139-146`）。标记若也画成通栏线，用户无法分辨「这条是作者写的分隔」和「这条是应用说完了」——一个装饰一旦被误读成正文结构，就把「不改写源文件」的保证在观感层破掉了。
- **它不能成为第二份「当前位置」真源。** `src/toc.ts:151-158` 与 `:265-270` 已经有一份「可见区域 / 当前标题」的追踪。标记若按「滚到底」判定，就会长出第二份滚动位置语义（[REVIEW.md](../../../REVIEW.md) 第 8 条点名的形态）。

## What Changes

1. **md 模式下，正文末尾出现一个「到底了」装饰标记**：居中于阅读栏，紧贴最后一行之下，随内容滚动；颜色取弱化 token（`--dim`）与发丝线（`--bd-2`），不用朱红（`--accent` 留给链接与错误态）。**出现判据是静态的**——文档内容装不下一屏时显示，一屏装得下（含空文档）时不显示；MUST NOT 依赖滚动位置。（delta：ADDED `editor-live-preview / 正文末尾的结束标记`）

2. **标记是非文档性的、几何稳定的**：不进 `EditorState.doc`、不进保存字节、不被 ⌘A 复制带出、不被 ⌘F 命中；文档的滚动高度在**所有滚动位置**上逐像素恒定（不得出现「接近底部时高度突然变化」）；不在文档打开路径与键入路径上新增测量或解析（ADR 0002 §6）。（delta：ADDED `editor-live-preview / 结束标记的非文档性与几何稳定`）

3. **本 change 只加这一个装饰**：不改任何既有渲染口径（分隔线、表格、frontmatter、图片宽度、空行折叠一律不动），不加键位、不加命令、不加配置项，不改 code 模式。

## Non-goals

- **不做阅读进度读数**（百分比 / 进度条 / 状态栏 / 剩余行数）：这是另一个形态（常驻读数、跨 capability），本 change 只加一个「终点」标记。
- **不做滚动行为改造**（底部回弹抑制、滚动吸附、`overscroll-behavior`、到底提示音/触感）：本 change 不碰滚动行为本身。
- **不做「回顶」按钮、不做分页 / 懒加载、不做「继续阅读」**：与「让用户意识到没有更多内容」无关，且每个都会新增窗口级 UI。
- **不做分节结束标记**（每个标题块末尾）：需求原话只到「文件底部」。
- **不做字数 / 阅读时长等元信息**：不新增读取与计算。
- **不修图片加载引起的文档高度变化，也不修任何滚动缺陷**（含 M187 的 svg 滚动缺陷）：它们归 [image-reading 质量合同](../../../docs/specs/image-reading.md) 与各自的 mission / finding，不在本 change。本 change 的判据不依赖滚动位置，因此与这类缺陷彼此独立（标记只回答「正文到此结束」，不回答「你滚到哪了」）。
- **不新增配置项**（不做「显示 / 隐藏结束标记」的开关）：默认口径即唯一口径；[REVIEW.md](../../../REVIEW.md) 第 9 条记过「声明了却没有消费者」的假开关形态。
- **不改任何既有渲染口径**：分隔线、表格、frontmatter、图片宽度与空行折叠一律不动。
- **不做非 md 文件**：code 模式不加标记（推荐项；若裁决点 4 取备选①再改）。
- **不做跟随文档语言的本地化**：标记是应用 chrome（与 masthead、toast 同为中文），英文文档里也是同一句话。

## capability 归属：为什么是 `editor-live-preview` 的 ADDED，而不是新 capability

**结论**：两条新增 requirement 都落 `editor-live-preview`（既有 living spec，`openspec/specs/editor-live-preview/spec.md`），本 change **不新建 capability**。

| 本 change 的条款 | 与那份 living spec 既有条款的关系 |
|---|---|
| 标记是「md 模式的装饰层」的一部分（同一个 Compartment、同一个渲染路径） | 直接落在「live preview 装饰层」这条既有 requirement 的射程内 |
| 不得破坏「只为可见区域构建」的视口增量义务 | 是「live preview 装饰层」里那条性能义务的**同一条约束**，拆到别处就得两处互相引用才读得全 |
| 标记 MUST NOT 改变文档源码（ADR 0003 §3） | 该 spec 已有同一句话的条款（「装饰 MUST NOT 改变文档源码」），本 change 只是又一个受约束的装饰 |
| 光标在文末时标记照常显示（不从属选区显露口径） | 与「光标触及即显露源码」同属**显露口径**这一族：标记不隐藏任何源码，因此不参与显露，这条对照只在这份 spec 里说得清 |
| code 模式不出现（推荐项） | 「单内核双模式落地」那条 requirement 管的就是模式边界 |

**反方（如实记录）**：如果这个标记将来长成「阅读进度 / 阅读状态」这一类常驻读数（进度条、剩余时间、已读位置），那它就该单立一个 capability——那种形态跨窗口级 UI 与编辑器两处，还会与 `toc-outline` 的当前位置读数重叠。本 change 的形态只是「正文末尾多一个装饰」，与图片行的一个 widget、分隔线的一个 widget 同体量，所以归属不动。真长出上面那种形态时再拆（同语义两处真源是 [REVIEW.md](../../../REVIEW.md) 第 8 条点名的形态，现在拆反而制造它）。
