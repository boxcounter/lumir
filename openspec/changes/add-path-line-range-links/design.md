## 1. 现状实测（改动前的判别性输入）

对 `findPathCandidates` 实跑（索引只含 `notes/plan.md`）：

| 输入 | 可点范围 | 行落点 |
|---|---|---|
| `notes/plan.md:12:3` | 整段 | 12 |
| `见notes/plan.md:120-140的内容` | 仅 `notes/plan.md` | 无 |
| `notes/plan.md:12-` | 仅路径 | 无 |
| `notes/plan.md:40-12` | 仅路径 | 无 |
| `notes/plan.md:12 - 40` | `notes/plan.md:12` | 12 |
| `notes/plan.md:9-12-15` | 仅路径 | 无 |

两条结论：① 今天 `:起-止` 的效果是「能点、但不跳行」——比不可点更糟（行为与文字承诺不一致）；
② 空白与畸形形态的既有口径（不吞半截 / 空白即边界）已经是对的，新形态必须**沿用**它，不要另立一套。

## 2. 语法扩展

### 2.1 正则

```
LINE_SUFFIX = /:(\d{1,7})(?:-(\d{1,7})|:(\d{1,7}))?/y
```

- 第一段 = 行号；第二段为 `-N` 时是**行范围**，为 `:M` 时是**列**（既有语义）；
- 两者互斥（同一后缀里不叠加）——`起-止:列` 不在支持面内（proposal Non-goals）。

### 2.2 有效性判定（全部在 `lineSuffixAt` 内）

1. 正则不匹配 ⇒ 无后缀（`:12-`、`:-9` 落在这里或下一步）。
2. 「紧邻字符」守卫沿用现规则：后缀之后若紧跟 `[A-Za-z0-9_.\-/]`，整个后缀不成立。因此
   `9-12-15` / `12-40-` 一类**整段不成立**（`-` 是拒绝字符），不会只吞 `:9-12`。
3. 行范围额外判「`止 >= 起`」，不满足 ⇒ 整个后缀不成立（**MUST NOT 回退成只有 `:起`**——半吞会让
   可点范围与文字承诺错位）。
4. `起` 必须是 ≥ 1 的整数（既有判据）；`止` 的越界（大于文档行数）不在解析期判——落点由
   `revealLineAt` 的既有钳制处理（与 `:行号` 越界同口径）。

### 2.3 读数与「不声明死字段」

`PathCandidate` **不新增** `lineEnd` 字段：`止` 的唯一消费者是「后缀是否成立」这个判定，落点只用
`起`。展示文本本来就把整段当文本（`createPathLinkEl` 的 `title = text`），所以没有第二个消费者需要
`止`。按 REVIEW.md『值或开关声明了却没有消费者』条，不加一个无人读的字段——若将来要做行范围高亮，
届时再加字段并同时给它消费者。

## 3. 落点行为

- 点击 `path:起-止`：`openPathAtLine` 不变（打开 → 转场窗口内 `revealLine(起)` → 下一帧复核补发）。
- **不选中、不高亮**（D1）：不 dispatch 任何 selection 变更；文档内容与选区在点击前后逐字节 / 逐位置
  相同。这条要在单测里**反向**断言（点击后 `selection.main.empty === true` 且位置不变）。
- CL-2：同一让位窗口实现，无新窗口语义。

## 4. 待裁决点

| # | 裁决点 | 选项与倾向 | 若裁另一侧的影响面 |
|---|---|---|---|
| D1 | 行范围的落点语义 | **倾向只落起始行**（与「列号只解析不落点」同一取舍；避免「选中即准备覆盖」的数据风险） | 选中 N–M：要定「是否进编辑态、键入是否覆盖」；高亮：要新增色值与消退时机（视觉 token + 场景） |
| D2 | 形态严格度 | **倾向整段不成立**（畸形一律不吞半截；带空白沿用既有「空白即边界」） | 宽容解析需要第二套边界规则，且会与既有候选边界口径打架 |
| D3 | 提示词纪律段是否补 `:起-止` | **倾向补一句**（否则新形态出现率取决于模型自觉；既有扫描里带行号后缀的引用占 0/12） | 不补：只做识别不做引导，本 change 的收益取决于真实会话里模型怎么写 |
| D4 | 工具卡片 Read 的 `limit` 是否合成行范围 | **倾向不合成**（卡片只有 `offset` 一个落点读数；`limit` 不是「行范围声明」） | 合成则卡片点击要选 `offset..offset+limit-1`，与 D1 的另一侧绑定 |

## 5. 提示词（D3 的倾向侧）

`src-tauri/src/harness/prompts/path-reference.md` 补一句（措辞以实现为准，语义固定）：引用**一段连续
行**时写 `:起-止`（如 `:120-140`），两端的行号都取自实际读到的位置、MUST NOT 凭印象编范围。

不改 `context.rs`：固定段由 `include_str!` 装配，清单条目的字节数由 `len()` 派生，因此文本变化不会让
既有断言漂移（这是既有设计，MUST NOT 为本次改动另写一份长度常量）。

## 6. 验证策略（判别性优先）

- **纯函数单测**（扩 `tests/unit/harness-path-link.test.ts`）：
  - 正向：`:12-40` / `:1-1` / 中文紧邻（`见path:12-40的`）/ 行内代码内 / 同一段多条；
  - 负向（**必须先造一个会红的输入**）：`:40-12` / `:12-` / `:-9` / `:9-12-15` 一律不产行落点；
    `:12 - 40` 只认 `:12`；
  - 回归锚点：`:12` / `:12:3` 的既有读数逐字不变；目录候选仍不吞任何后缀。
- **编排单测**：行范围点击走 `open → duringTransition(reveal) → 下一帧复核`，`reveal` 的入参是**起**行；
  点击后不产生 selection 变更（D1 的反向断言）。
- **视觉场景**（chromium，`tauri-stub` 的 harness fixture）：回复正文含 `notes/x.md:3-5` → 整段
  是一个可点元素、文本逐字不变；点击 → 新标签打开、目标行文本在视口内。
- **真机验收**：mock provider 回复里放一条行范围引用 → 点击落点与「不选中」；如实登记 prompt 遵从度
  为抽样观察（不进机器断言）。
- **门禁**：`gate.sh quick` 全绿；无视觉样式改动（不新增类 / token），`gate.sh visual` 按常规跑。

## 7. 已知边界（如实登记，不包装成覆盖）

1. 行范围只到起始行；`止` 不参与任何视觉或选区行为（D1）。
2. `起-止:列` 不支持（后缀形态互斥）。
3. `止` 越界不报错、只按起始行落点（与 `:行号` 越界钳制同族）。
4. 带空白的写法只认前半段行号（沿用既有「空白即候选边界」）。
5. prompt 纪律的遵从度仍按抽样观察，不进机器判据（与既有「路径引用纪律」同一条边界）。
