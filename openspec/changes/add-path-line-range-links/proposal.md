## Why

Alex 2026-10-23 的需求原话（逐字）：

> 「支持 harness 输出里的 {path}:{line-start}-{line-end} 可点击（现在已经支持
> {path}:{line}:{column}）」

**现状与实测**（起草时对 `src/harness-path-link.ts` 的真实行为跑了一组输入，判据取该模块导出的
`findPathCandidates`；索引里只有 `notes/plan.md`）：

| 输入 | 今天的结果 |
|---|---|
| `notes/plan.md:12:3` | 可点范围 = 整段 `notes/plan.md:12:3`，落点行 12（列 3 只解析、不参与落点） |
| `见notes/plan.md:120-140的内容` | 可点范围 = 仅 `notes/plan.md`，**没有任何行落点**；`:120-140` 留在正文里 |
| `notes/plan.md:12-` | 仅路径可点（后缀不成立） |
| `notes/plan.md:40-12` | 仅路径可点 |
| `notes/plan.md:12 - 40` | 可点到 `notes/plan.md:12`（空白即候选边界），` - 40` 是普通文本 |
| `notes/plan.md:9-12-15` | 仅路径可点 |

根因是后缀解析器的两条既有约束（`src/harness-path-link.ts` 的 `LINE_SUFFIX` 与它后面的
「后缀之后不得紧跟 ASCII 路径延续」守卫）：正则只认 `:N` / `:N:M`，且 `-` 被算作「路径还在继续」，
于是 `:120-140` 既匹配不上、又被守卫拒绝——**整段后缀被丢回正文**。用户看到的是一个能点但只跳到
文件、不跳到行的路径：点击行为与文字承诺不一致。

**为什么值得做**：agent 引用文档时最自然的写法就是「第 120–140 行这段」——那正是它在读工具结果时
看到的读数形态（`vault_read` 的 `offset` / `limit`、diff 头、`grep` 的命中上下文）。用户读到
`plan.md:120-140` 时想的就是「跳到那段去看看」，而今天这一按只把文件打开在第一屏。这条不是新能力，
是**让已有能力覆盖它最常见的书写形态**。

## What Changes

逐条对应 `specs/harness/spec.md` 增量里的 requirement：

1. **行范围后缀被识别**（harness，MODIFIED：输出中的 vault 路径可点击）。在既有的 `:行号` /
   `:行号:列号` 之外，`:起-止` 也成为后缀形态；可点范围包含整个后缀、展示文本逐字不变（与
   `:行号:列号` 的既有口径一致——链接化不改写正文）。
2. **落点 = 起始行**（同上）。点击打开文件并把第 `起` 行滚入视口居中（与 `:行号` 同一条落点算式与
   CL-2 让位窗口）；行范围**只解析、v1 不选中也不高亮**——点击是「去看这段」，不是「把这段选起来准备
   改写」（选中会把随后的一次键入变成对正文的覆盖，这是数据风险，不是审美取舍）。
3. **畸形形态不吞半截**（同上）。`12-`、`-9`、`9-12-15`、`止 < 起` 一律使整个后缀不成立（可点范围止于
   路径本身）；`12 - 40` 这类带空白的写法沿用既有口径（空白即边界，只认 `:12`）。
4. **提示词补一句**（harness，MODIFIED：路径引用纪律；属起草倾向 D3）。纪律段增加「引用一段连续行时
   带 `:起-止`、两端的行号取自实际读到的位置」——否则新形态只在模型偶然写出时才出现，识别能力等于
   白做。

## 起草期取值（已裁决之外，请评审时一并裁）

| # | 取值 | 倾向与理由 | 若你选另一侧 |
|---|---|---|---|
| D1 | 行范围点击**只落到起始行**（不选中、不高亮） | 选中会留下「一次键入覆盖整段」的风险；高亮要新增一套视觉语言与清除时机；与 `:行号:列号` 里「列号只解析、不参与落点」的既有取舍同一口径 | 选中 N–M 行：需要决定是否进入编辑态、键入是否覆盖；高亮：需要定色值与消退时机（新增视觉 token） |
| D2 | 形态严格：仅紧贴的 `起-止`；三段、缺段、`止 < 起` 全部不认 | 一处的失败模式必须是「整段不成立」，不能只吞一半（半吞会让可点范围与文字承诺错位） | 宽松解析（如容忍 `12 - 40`）：需要另一套边界规则，且与「空白即候选边界」的既有口径冲突 |
| D3 | 提示词纪律段补一句 `:起-止` | 不写进纪律段，模型几乎不会写出这个形态（既有扫描证据：带行号后缀的路径占总候选 0/12） | 若你要保持提示词不动，则只做识别、不做引导——新形态的出现率取决于模型自觉 |
| D4 | 工具卡片 Read 的 `offset` + `limit` **不**合成行范围 | 卡片的落点今天只有 `offset` 一个读数；把 `limit` 也读成「行范围」是给卡片路径引入第二种落点语义，收益不明确 | 若要，卡片点击可变成「落到 offset 并选中 limit 行」——与 D1 的另一侧绑定，需一起裁 |

## Non-goals

- **不做行范围高亮 / 选中**（D1）。
- **不做 `起-止:列` 之类的组合后缀**：三种形态各自独立，不叠加。
- **不复制行范围文本**：点击是导航动作，不把那段内容放进剪贴板（`block.copy` 已有独立能力）。
- **不改 `:行号` / `:行号:列号` 的既有行为**：解析、落点、越界钳制逐条不变。
- **不改目录引用的行号后缀口径**（目录候选的可点范围仍不含任何行号后缀）。
- **不改工具卡片路径的落点语义**（D4：Read 仍只落 `offset`）。
- **不新增后端命令 / 不改工具参数 schema**：全部在前端纯函数与既有跳转编排里完成。

  整块替换（按 living spec 全文抄录后就地改），第二条只改一句纪律 + 一处场景期望。

  - 后端：`src-tauri/src/harness/prompts/path-reference.md` 的纪律段一句话（D3）；`context.rs` 的固定段

  - 单测：`tests/unit/harness-path-link.test.ts` 扩展（畸形形态与「不吞半截」是重点）。
- **关联约束**：
  - 阅读位置合同 CL-2：行范围跳转与 `:行号` 跳转走**同一个**让位窗口实现，不新增窗口语义。
  - ADR 0002 §6：识别仍在渲染路径上（同步、零 IPC），新增的只是正则分叉。
  - 无视觉改动（链接元素形态不变），因此不触发视觉基线更新。

## 观测闸三问

- **怎么知道用户用了它**：点击是显式动作；dogfood 可感知；无埋点。
- **怎么知道它有效**：回复里出现 `path:120-140` 时整段可点、点一下落到第 120 行；不再出现「能点但
  只跳到文件」的半截形态。
- **出问题怎么发现**：纯函数单测（三种形态 × 畸形 × 中文紧邻 × 列号组合）、真机 / 视觉场景（点击落点
  与展示文本）、prompt 遵从度如实登记为抽样观察（不进机器断言）。
