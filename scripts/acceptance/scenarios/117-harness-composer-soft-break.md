# 117-harness-composer-soft-break —— 一次 ⇧Enter 即换行（M419 缺陷，HC1）

## 本场景在验什么

Alex 原话（2026-10-10）：「Harness composer 里按两次 SHIFT + Enter 才会换行」。

根因（M419 定位，实测见 [docs/specs/harness-composer.md](../../../docs/specs/harness-composer.md)
「实测依据」节）：修前段末换行落成**尾随 `\n`**，而 CSS 里尾随换行**不产生行盒**
（`white-space: pre-wrap` 下 `"ab\n"` 与 `"ab"` 同高）——第一次 ⇧Enter 零可见变化、光标停在一个
没被渲染出来的行上；再按一次才把上一次的尾随换行挤成内部换行。修复把段末断行落成**新的空段落块**
（`min-height: 1em`，一行真实落地），光标落到新行。

真机可观测回路（mock provider，不发消息、零外部 API）：

1. `HNL-BRK-AA` → 一次 ⇧Enter → `HNL-BRK-CD`。
2. **像素层**：第二行行位（窗口点 y≈723）上有字形。修前 `CD` 落在第一行（同行拼接），
   y≈723 是空白 ⇒ 该条红——这是本缺陷在真机上唯一有区分度的判据（AX 值里的换行只在修复后
   才出现，且真机 AX 对空行的暴露不可依赖）。
3. **AX 层**：composer 文本里两串之间有换行，且同行拼接的签名字符串不在场。
4. 反面对照：第一行行位照旧有字形（防「两处都空」的空转读数）。

**M462 追加段（`⌃A → ⌃E → ⇧Enter` 起）**——同一场景的第二个缺陷形态，合同条款 = 同文件
**HC1 第 3 条**（段末断行的**落点**）。Alex 原话（2026-10-12）：「光标放在最后一行的行末，
按 ⇧Enter 不是新起一行，而是在当前这一行**前面**加了一个换行，光标留在文字行行首」。

根因（WebKit 探针定位，读数见 §实测依据的 M462 节）：`{block: 块数, offset: 0}`
（「末尾之后」）是**末段末缘的归一等价表示**，行级命令把光标停在这一档时它被**写回 DOM 的
块级容器边界**；旧实现把这个越界位钳到末块、`offset` 仍取 0 ⇒ 当成「末段段首」，`\n` 落到
末段文本第 0 位。修复把「末尾之后」按**末块之后**处理（新空段落块追加在末尾）。

真机可观测回路（接着上面的两行往下做）：

5. `⌃A`（到末行行首）→ `⌃E`（到末行行末 = 归一表示，缺陷形态在这一档可达）→ 一次 ⇧Enter →
   键入 `HNL-BRK-EE`。
6. **像素层**：第二行行位（y≈702）**仍有字形**（`hnl-brk-cd` 没被挤下去）。缺陷形态下那一带
   是空白——空行被插到了它**前面**、整行文字下移一行 ⇒ 该条红。
7. **AX 层**：`hnl-brk-cd` 与 `hnl-brk-ee` 之间有换行（新空段落块落在末行之后）；缺陷签名串
   `hnl-brk-eehnl-brk-cd`（探针串接在 `cd` 行首）不在场。
8. 反面对照：第三行行位（y≈723）有字形——防「换行把字挤没了」的空转读数。

## 断言口径

- **行位像素判据的坐标从布局读数来**（1200×800 窗口、⌘⇧A 默认分栏下 composer 内容左缘 x≈789、
  行高 ≈21pt、行位中心见下（两行态 702 / 723；三行态 681 / 702 / 723））：**不用整页基线**——本场景判的是「哪一行有字」，不是「画面与上一版
  比没变」。坐标是**实测值**，口径与来历（M462 校正）：
  - 窗口尺寸由 `resizeWindow`（1200×800）**显式钉住**：M437 起产品按工作区 90% 现算启动尺寸
    （套件 `--config` 只钉位置），2026-10-12 实测本机跑到 1152×864 ⇒ 旧坐标整片落空（四个采样点
    全读到亮度跨度 0/9）。钉住之后几何才可复算。
  - **composer 的输入区是「底部锚定、向上生长」**：加一行 ⇒ 内容整体上移一个行高（实测：两行态
    首行 y≈702、次行 y≈723；三行态 681 / 702 / 723）。所以同一条 y 在不同行数下装的是不同的行
    ——本场景的两段断言各自绑定自己的行数（第一段两行态、第二段三行态），标签里写清了哪一行。
  - 采样 x 取 **780**（实测文本字形横跨 x≈734..802，取中段落点）；旧值 905 落在文本右侧的空白上
    （10 字串只到 ≈802），M462 一并改准——当时的 x 与现在的 pane 布局已经对不上了。
- **`contrast` 而非 `same`**：判「这一带真有字形」用亮度跨度（`pixel.contrast`），
  与场景 68 同一口径；两个字形的实际落点不逐像素可预测，`same` 会把噪声当差异。
- **AX 换行断言是第二把锁**，不是唯一判据：真机 AX 对多段落 contenteditable 的文本拼接方式
  依赖 WKWebView 的文本提取（块之间是否插换行），实测**会插**（本条因此可判；换行是主判据的
  补强，不是唯一依据）。
- **区分度实测（反向验证，2026-10-10）**：把 `insertSoftBreakAtCaret` 临时改回缺陷形态（段末
  追加尾随 `\n`）后重跑本场景——像素条读到第二行行位**亮度跨度 0**（修后 186）、AX 两条变红
  （文本是同行拼接的 `hnl-brk-aahnl-brk-cd`），第一行对照条照旧绿。断言对缺陷有区分度。

**M462 追加段的两条口径**：

- **为什么用 `⌃A` → `⌃E` 而不是点鼠标**：缺陷态要求光标落在「末尾之后」这一档，而**鼠标点进末行
  行末交出的 DOM 选区是原始末缘**（WebKit 探针逐档实测：点在字后、点在本行右侧、点在本行下方
  空白带，三种都落 `#text@len`），那一档本来就落在「段末」分支上、复现不出缺陷。行级命令才是把
  光标停到该表示的路径（⌃E 从行内到行末会把等价值写回 DOM）。这一段同时是 HC4 与 HC1 的**接口
  回归**：导航写回的光标位必须能被编辑动词读懂。
- **AX 在这一段是主判据、像素是判「行位没被挤动」的那条**：`contrast` 判的是「这一带有字形」，
  而三行态**第三行（y≈723）**在缺陷形态（`ee` 与 `cd` 挤在同一行）与修后（`ee` 自成一行）下
  **各自都有字形**——它只防「字被挤没」的空转；真正有区分度的是**第二行（y≈702）**那条（修后
  `cd` 在、缺陷是空行），而它只覆盖「`cd` 被挤下去」这一半，另一半（`cd` 与 `ee` 是否同一行）
  只有 AX 的分层串能判：`/hnl-brk-cd[\r\n]+hnl-brk-ee/` 命中 + `hnl-brk-eehnl-brk-cd` 不在场。
  两条一起才是完整判据，缺一不可。
